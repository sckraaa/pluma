# 0039. Модерация: очередь жалоб, ограничения, панель только в tailnet

- Статус: proposed (2026-11-09).
- Задача: 025. Обоснование и источники — бриф `docs/tasks/025-moderation-and-premium-panel.md` («Что известно», «Решение по панели», «Результат»).

## Контекст
Жалобы никуда не шли: `messages.report` отвечал `ERR_ENTERPRISE_IS_BLOCKED`, остальные — поддельным успехом (`fake_rpc_result.go`). Ограничений аккаунтов не было. Premium выдавался только `pluma-admin`.

Панель модерации Telegram не опубликована. Видно только API и реакции клиентов — проектируем по ним.

Источники, прочитанные для этого решения:
- `core.telegram.org/method/messages.report`, `/api/errors`, `/api/errors.json` (`PEER_FLOOD` — 400, «spamreported»; `USER_DEACTIVATED_BAN` — 401, описание «banned by antispam»), `/method/messages.sendMessage` (`USER_BANNED_IN_CHANNEL`), `/method/auth.sendCode` (`PHONE_NUMBER_BANNED`), `/api/config` (значения Premium).
- Android (DrKLO/Telegram): `ReportBottomSheet.java` (идёт по дереву `option`; ответ `MESSAGE_ID_REQUIRED` просит выбрать сообщения; поле комментария — 1024), `AlertsCreator.java:510-519` (`PEER_FLOOD` → «MoreInfo» и @spambot), `:6676` (старое меню причин), `LoginActivity.java:3228`.
- tdesktop: `api/api_report.cpp`, `apiwrap.cpp:525-541`, `intro/intro_phone.cpp:282`. iOS: `PendingMessageManager.swift:90-94`, `Authorization.swift:237`.
- Tailscale Serve: `tailscale.com/kb/1312/serve` — заголовки личности снимаются, если их прислал клиент; Serve добавляет их только для трафика tailnet; бэкенду советуют слушать только localhost.
- WebAuthn: `www.w3.org/TR/webauthn-3` (ceremonies §7, ES256 — COSE -7).

Дерево причин у Telegram серверное, его нельзя прочитать, не отправив настоящую жалобу. Его устройство в Pluma — решение проекта, а не копия. Что именно делают ограничения с `PEER_FLOOD` в личных чатах Telegram, снаружи видно частично: «spamreported» плюс сообщение @SpamBot.

## Решение
1. **Хранилище — таблицы проекта.** `moderation_reports` (жалоба со снимком JSON на момент жалобы), `moderation_restrictions` (один ряд на пользователя), `admin_users`, `admin_passkeys`, `admin_sessions`, `admin_challenges`, `admin_audit` (только добавление: пользователь БД панели имеет на неё только `SELECT, INSERT`). Схема — `teamgramd/deploy/sql/migrate-20261109-moderation.sql`.
2. **Приём жалоб — новый модуль bff `reports`** (`mtproto.RPCReports`, маршрут в трёх `session.yaml`). Подмены `fake_rpc_result.go` для этих методов убраны. Снимок делается при подаче жалобы (сообщения — из ящика самого жалующегося, значит он их видел; пользователи без телефона; медиа — как ссылка на файл). Открытая жалоба того же человека на то же объединяется (ключ `dedup_key`); после решения та же жалоба — новая. Лимит: 60 жалоб в час на пользователя (`FLOOD_WAIT`).
3. **Дерево причин — один уровень.** Причины как в типе `ReportReason` и старом меню Android; следующий шаг — `reportResultAddComment` с отдельным `option` (`spam:c`), комментарий к «другое» обязателен. `messages.report` без id — жалоба на весь чат (Android так шлёт, ответа `MESSAGE_ID_REQUIRED` мы не даём). Несуществующие сообщения — `MESSAGE_ID_INVALID`. Тексты — на языке сессии, ru/en, как служебные сообщения 777000 (задача 019).
4. **Ограничения.** Два вида. *Ограничен*: в личке писать можно только тем, у кого отправитель в контактах (`PEER_FLOOD`, 400), в группах и каналах нельзя (`USER_BANNED_IN_CHANNEL`), чаты с собой и с 777000 открыты (обжалование; 777000 — поддержка, ADR 0026). *Заблокирован*: сессии завершаются, `auth.sendCode`/`auth.signIn` → `PHONE_NUMBER_BANNED`. Истечение проверяется при чтении, без фоновой работы.
5. **Панель — отдельный сервис `app/ops/admin`.** Слушает только loopback (проверяется при старте), наружу — `tailscale serve`. Контейнер с сетью хоста (`docker-compose.admin.yaml`): иначе соединение с прокси шло бы с адреса моста, и проверка loopback ничего бы не значила. Личность — заголовок `Tailscale-User-Login`, которому верят только на соединениях с loopback; поверх — ключ доступа (WebAuthn, ES256, проверка своя по §7: только ES256, без attestation, поэтому без зависимости `go-webauthn`).
6. **Опасные действия подтверждаются ключом заново.** Запрос несёт `payload` строкой и `assertion`, challenge которого выдан на `sha256(path + payload)`: подпись не подходит ни к другому отчёту, ни к другому решению.
7. **Роли.** Владелец — всё; модератор — очередь и решения; наблюдатель — чтение (`admin_users`, правит владелец). Первый владелец — `pluma-admin panel owner <login>`.
8. **Журнал только на добавление**: каждое решение, вход, правка людей и просмотр снимка или файла (сначала запись, потом ответ). Копия строки (без подробностей) уходит в лог сервиса и из него в Loki.
9. **Минимум данных.** Модератор видит снимок и файлы этих сообщений, а не чаты. Телефон — только у владельца на странице Premium, для поиска аккаунта.
10. **Решения — транзакция плюс шаги.** В одной транзакции закрывается жалоба, ставится ограничение и пишется журнал. Остальное (удаление сообщения — `msg.deleteMessages` или `channel.deleteMessages` от создателя канала; 777000; завершение сессий — `authsession.resetAuthorization` и пуши `sync`) идёт шагами `effects_stage`, каждый шаг отмечается сразу после выполнения. Воркер панели подхватывает незавершённые после сбоя и перезапуска (захват на 2 минуты); после 10 неудач — кнопка «Повторить» в панели. Повтор шага после падения между шагом и отметкой возможен, это дубль одного сообщения 777000 в худшем случае.
11. **Запасной доступ — `pluma-admin moderation restrict|ban|lift|reports`** по SSH, тем же `pkg/moderation`.
12. **Premium в панели** — через `user.updatePremium` (владелец, подтверждение ключом). Включены лимиты Premium как у Telegram там, где их проверяет сервер (био 140, GIF 400, каналы 1000, публичные 20, подпись 4096, файл 4 ГБ — ADR 0016 здесь расширен; покупка остаётся выключенной). Функции, которых на сервере нет, не включаются.

## Последствия
- Модерация не зависит от внешних сервисов: Tailscale только доставляет трафик, TLS заканчивается на сервере, Cloudflare Access отвергнут как раз из-за этого.
- Заблокированному нужен вход с разблокировкой: `pluma-admin moderation lift`.
- `stories.report` не сделан (историй в Pluma нет).
- Секретные чаты не обслуживаются, `messages.reportEncryptedSpam` — `ERR_ENTERPRISE_IS_BLOCKED`.
- Тексты ограничений в чате 777000 написаны нами: текстов Telegram снаружи не видно. Настоящее дерево и формулировки ограничений не сверены: помечено в брифе.
- Хост с панелью должен иметь Tailscale (ставит владелец); `docs/ops/admin-panel.md`.
