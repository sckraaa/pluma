# 0008. Закрепление версий клиентов по layer

- Статус: accepted
- Дата: 2026-10-21

## Контекст
Сервер реализует layer 228 (`github.com/teamgram/proto v0.228.0`). Свежие клиенты ушли на 229–232; пропатченные форки teamgram ещё старее (177–223). Аудитория закрытая, клиенты собираем сами — мы контролируем, какие версии у пользователей.

## Решение
- Базовые версии клиентов — последние на layer 228: iOS `release-12.9.2`, Android 12.9.1 (`aac1efcb83`), tdesktop v7.0.x; для Web K/A коммит на 228 найти в задаче 006. Источник: `docs/audit/04-clients-and-builds.md`.
- Патчи клиентов поддерживаются как набор изолированных изменений поверх тега upstream, а не как долгоживущий форк с мерджами.
- Сервер и клиенты переходят на новый layer вместе, одной задачей; сборка проверяет совпадение layer (fail fast).

## Последствия
Пользователи не получают новинки Telegram мгновенно — осознанно. Обновление layer зависит от публикации нового `teamgram/proto` upstream; если upstream остановится, понадобится своя кодогенерация TL (риск записан в STATUS).
