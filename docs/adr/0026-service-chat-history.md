# 0026. Сообщения служебного аккаунта 777000 — история аккаунта

- Статус: accepted (2026-11-01)
- Заменяет: пункт 4 ADR 0022
- Задача: 022

## Контекст
- **У Telegram** чат «Telegram» (777000) — обычный чат с историей на сервере. Веб-сессия, открытая 2026-10-30, видит сообщения с 2024-05-16: коды входа, «New login», «Two-Step Verification settings changed», «Incomplete login attempt». У каждого обычный id сообщения (`docs/audit/07-telegram-parity.md`, «Служебный чат 777000»).
- **У Pluma** до этой записи «Новый вход» шёл как `updateServiceNotification` только сессиям в сети (ADR 0022, п. 4). Клиент создавал из него локальное сообщение. Новое устройство этой истории не видело, а в Pluma Web чата 777000 не было вовсе. Код входа уже был настоящим сообщением (`msg.pushUserMessage`, задача 019).

## Решение
- **Сообщения служебного аккаунта — настоящие сообщения от 777000 в истории пользователя.** Их доставляет `msg.pushUserMessage` с ненулевым `push_type`: сообщение кладётся только в ящик пользователя, у служебного аккаунта копии нет. Сессии получают `updateNewMessage` с `pts`, пропустившие — через `getDifference`, новое устройство — в `messages.getHistory`. Отправку делает пакет `app/bff/authorization/servicemsg`.
- **Что отправляется сейчас:**
  - код входа (как было);
  - «Новый вход» — вместо `updateServiceNotification`;
  - «Two-Step Verification settings changed» — при установке, смене и снятии облачного пароля из `account.updatePasswordSettings`. Указываются устройство и место сессии, которая это сделала, язык — её `lang_code`.
- **Баннер неподтверждённого входа** (`updateNewAuthorization`, ADR 0022, пп. 1–3) не меняется: его получают все сессии, кроме новой.
- **«Новый вход» теперь видит и новая сессия.** Это история аккаунта, общая для всех его устройств. Баннера о себе новая сессия по-прежнему не получает.
- **Тексты** — `servicetext`, слово в слово по образцам Telegram. Если русского текста Telegram нет («Two-Step Verification settings changed»), приходит английский, как Telegram прислал английский клиенту на чешском.

## Последствия
- `updateServiceNotification` для «Нового входа» больше не отправляется. Клиенты не создают локальных дублей: сообщение приходит один раз, с `pts`.
- Разбор ADR 0022 о дублях из `getDifference` к этим сообщениям не относится: у обычного сообщения есть id, и клиенты его не повторяют.
- **Не сделано** (задача 022, «Результат»):
  - «Incomplete login attempt» — нужен надёжный момент отправки после входа, брошенного на пароле: запись `pkg/twofa` истекает в Redis молча;
  - сообщения о Premium — с панелью модерации (задача 025).
