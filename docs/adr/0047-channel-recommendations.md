# 0047. Похожие каналы: подбор по общим читателям, без весов и без истории просмотров

- Статус: proposed (2026-11-11)
- Задача: 081.

## Контекст
- `channels.getChannelRecommendations` вызывают все четыре клиента. С каналом — «похожие каналы» под каналом после вступления и во вкладке профиля (Android `MessagesController.getChannelRecommendations`, MessagesController.java:23882-23930; iOS `_internal_requestRecommendedChannels`, ChannelRecommendation.swift:55-140; tdesktop `ChatParticipants::loadSimilarPeers`, api_chat_participants.cpp:860-890, только для `asBroadcast()`). Без канала — каналы для аккаунта во вкладке «Каналы» поиска (Android SearchViewPager.java:716; iOS ChatListSearchListPaneNode.swift:4245; tdesktop `loadRecommendations`, api_chat_participants.cpp:923-938, передаёт `inputChannelEmpty` без флага).
- Ответ — `messages.Chats`. `messages.chatsSlice` с `count` больше списка клиенты читают как «ещё N каналов с Premium»: Android `more = count - chats.size()` и показывает его только без Premium (ChannelRecommendationsCell.java:148, SharedMediaLayout.java:9956), iOS хранит `count` в кэше. Сколько каналов отдаёт Telegram и по какому правилу подбирает, в документации нет (не проверено).
- Pluma — до 100 пользователей. Статистики просмотров, тем и языков у сервера нет, и строить её ради этого метода незачем; подбор должен быть объяснимым: «почему мне это показали».
- ADR 0041: всем доступно всё, что даёт Premium, лимиты премиальные.

## Решение
1. **Кандидат** — публичный (есть редактируемое имя) вещательный канал, не удалённый и не заблокированный владельцем (ADR 0042), в котором у аккаунта нет строки участника вообще: не состоит, не выходил, не исключён. Супергруппы и частные каналы не предлагаются.
2. **Люди, о которых подбор**:
   - с каналом — его читатели;
   - без канала — все участники каналов и супергрупп, где состоит аккаунт.
   Сам аккаунт, боты и удалённые аккаунты не считаются.
3. **Порядок**: число этих людей в кандидате (пересечение) по убыванию, затем размер канала (`participants_count`), затем `id` (меньший, то есть более старый канал, — раньше). Одни и те же данные дают один и тот же список.
4. **С каналом** предлагаются только кандидаты с пересечением не меньше одного: канал без общих читателей не «похож». **Без канала** после кандидатов с пересечением идут остальные публичные каналы по размеру — новый пользователь без каналов видит, какие каналы есть на сервере.
5. **Лимит** — 100, премиальный лимит (`recommended_channels_limit_default` и `_premium` в `app_config.json` равны 100; это и запасное значение tdesktop и Web K: data_premium_limits.cpp:30, limitDefaults.ts:36). Ответ всегда `messages.chats`: скрытых «для Premium» каналов нет, `count` клиентам не нужен.
6. Каждый канал отдаётся так, как его видит аккаунт: `channel` с `left`, `access_hash` и `participants_count` (iOS берёт из него число подписчиков, ChannelRecommendation.swift:116-125).
7. Чтобы спросить о канале, аккаунт должен иметь право его читать: чужой частный канал — `CHANNEL_PRIVATE`, неверный `access_hash` — `CHANNEL_INVALID`.

## Последствия
- Подбор — один запрос к `channel_participants`, `channels`, `username` и `users` на вызов (затем чтение найденных каналов); при сотне пользователей и сотнях каналов это миллисекунды, кэш не нужен. Клиенты кэшируют ответ сами (iOS — час для аккаунта).
- Подбор не учитывает темы, язык и активность каналов. Если на сервере станет много каналов и простое пересечение начнёт давать шум, правило меняется новым ADR, а не тихо в коде.
- Владельцу канала нельзя выключить показ своего канала в рекомендациях: в Telegram такой настройки тоже нет (не проверено); частный канал не показывается никогда.
