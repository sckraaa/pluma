# 0003. Базовый уровень безопасности MTProto

- Статус: accepted (детали уточняются по итогам аудита `docs/audit/02-transport-and-security.md`)
- Дата: 2026-10-21

## Контекст
Транспортное шифрование задано клиентами (MTProto 2.0) — выбирать его не нам. Наша зона: корректность реализации, хранение ключей, PFS, 2FA, push, логи.

## Решение
- Строгое следование MTProto security guidelines: проверки DH-параметров, msg_id/seqno, временного окна, защиты от повторов.
- PFS: поддержка временных ключей (`auth.bindTempAuthKey`). Сейчас метод — заглушка (см. api-coverage).
- Приватный RSA-ключ сервера не лежит в конфиге в открытом виде: KMS/HSM или как минимум зашифрованный файл с ключом из secret-хранилища. Ротация описана.
- auth_key хранятся зашифрованными at rest.
- 2FA строго по SRP (`account.getPassword` и т. д.).
- Push только зашифрованные (ключ на устройство через `account.registerDevice` secret): Apple и Google не видят содержимое.
- Секретные чаты: сервер только пересылает; ничего не логирует и не нарушает порядок.
- Секреты не в репозитории; дефолтные пароли инфраструктуры запрещены.

## Последствия
Дополнительная работа в authsession и конфигурации; взамен — отсутствие переделок безопасности потом.
