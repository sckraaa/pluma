# 0002. Сравнительное тестирование с настоящим Telegram

- Статус: accepted
- Дата: 2026-10-21

## Контекст
«Один в один» нельзя проверить на глаз. Мобильные клиенты молча ломаются на неточностях в апдейтах (`pts`/`qts`/`seq`, `getDifference`), file reference и ошибках RPC.

## Решение
- Набор сценариев на MTProto-клиенте (TDLib или библиотека уровня MTProto) прогоняется против настоящего Telegram (тестовые аккаунты) и против нашего сервера.
- Сравниваются структура ответов, коды ошибок, порядок и состав апдейтов — с нормализацией изменчивых полей (id, даты, хэши).
- Эталонные записи с настоящего Telegram хранятся в репозитории как фикстуры, чтобы тесты нашего сервера шли без доступа к Telegram.
- Каждый реализованный метод получает сценарий. Матрица покрытия (`tools/apicoverage`) показывает и наличие обработчика, и наличие теста.

## Последствия
- Регрессии ловятся тестами, а не памятью разработчика.
- Нужны тестовые аккаунты Telegram и аккуратное соблюдение лимитов API, чтобы не получить бан.

## Рассмотренные альтернативы
- Только ручная проверка в клиентах — не масштабируется и не ловит гонки.
