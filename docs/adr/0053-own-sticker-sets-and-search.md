# 0053. Свои наборы стикеров и эмодзи, поиск стикеров

- Статус: proposed (2026-11-12)
- Задача: 084 (ветка `task/084-own-stickers`).
- Связано: ADR 0028 (каталог из Telegram), 0029 (наборы по запросу и наборы аккаунта), 0020 (обновления с seq), 0041 (Premium для всех).

## Контекст

### Схема
Слои 228 (vendored `third_party/teamgram-proto`) и 233 (`reference-src-new/tdesktop/Telegram/SourceFiles/mtproto/scheme/api.tl`, `// LAYER 233`) совпадают по всем методам задачи: `stickers.createStickerSet#9021ab67`, `addStickerToSet#8653febe`, `removeStickerFromSet#f7760f51`, `changeStickerPosition#ffb6d4ca`, `changeSticker#f5537ebc`, `replaceSticker#4696459a`, `renameStickerSet#124b1c00`, `deleteStickerSet#87704394`, `setStickerSetThumb#a76a5392`, `checkShortName#284b3639`, `suggestShortName#4dafc503`, `messages.getMyStickers#d0b5e1fc`, `getAttachedStickers#cc5b67cc`, `searchStickers#29b1c66a`, `searchStickerSets#35705b8a`, `searchEmojiStickerSets#92b4494c`, `searchCustomEmoji#2c11c0d7`, `readFeaturedStickers#5b118126`. Служба `RPCStickers` уже зарегистрирована в bff и маршрутизирована (задача 024); методы отвечали `ERR_ENTERPRISE_IS_BLOCKED`.

### Документация
- core.telegram.org/stickers: статичный стикер — PNG или WEBP, одна сторона ровно 512, другая не больше; анимированный — TGS, холст 512x512, до 3 секунд, 60 кадров в секунду, до 64 КБ; видео — WEBM (VP9), одна сторона 512, до 3 секунд, до 256 КБ, без звука; статичный и видео-эмодзи — ровно 100x100. Лимит размера статичного файла и число стикеров в наборе на странице не названы.
- core.telegram.org/method/stickers.createStickerSet: название 1–64 символа; короткое имя 1–64, латинские буквы, цифры и подчёркивания, начинается с буквы, без двух подчёркиваний подряд; ошибки `PACK_SHORT_NAME_INVALID`, `PACK_SHORT_NAME_OCCUPIED`, `PACK_TITLE_INVALID`, `PACK_TYPE_INVALID`, `STICKERS_EMPTY`, `STICKER_EMOJI_INVALID`, `STICKER_FILE_INVALID`, `STICKER_GIF_DIMENSIONS`, `STICKER_PNG_DIMENSIONS`, `STICKER_PNG_NOPNG`, `STICKER_TGS_NOTGS`, `STICKER_VIDEO_BIG`, `STICKER_VIDEO_NOWEBM`, `STICKER_THUMB_PNG_NOPNG`, `STICKER_THUMB_TGS_NOTGS`, `USER_ID_INVALID`.
- core.telegram.org/method/stickers.addStickerToSet: `STICKERPACK_STICKERS_TOO_MUCH`, `STICKERSET_INVALID`. changeSticker: `STICKER_INVALID`; ключевые слова через запятую, не для масок (constructor/inputStickerSetItem). setStickerSetThumb: `thumb` только для обычных наборов, `thumb_document_id` только для наборов эмодзи, 0 — первый эмодзи.

### Клиенты (`~/pluma-work/reference-src-new`)
- **Загрузка файла.** Все клиенты сначала делают `messages.uploadMedia` с `inputMediaUploadedDocument` и `documentAttributeSticker` без набора, затем передают полученный документ: Android `StickerMakerView.java:1422-1447` (`image/webp` или `video/webm`), iOS `ImportStickers.swift:36-108`, tdesktop `api_stickers_creator.cpp:505-560`. В набор добавляют и уже существующий стикер чужого набора: tdesktop `api_stickers_creator.cpp:240-258`, Android `StickersDialogs.java:198-204`, iOS `ImportStickers.swift:198-200` (`CloudDocumentMediaResource`).
- **Пустое короткое имя.** Android (`StickerMakerView.java:1507`) и iOS-редактор (`MediaEditorScreen.swift:8195`) создают набор из одного стикера с `short_name = ""`.
- **После создания.** Android сам ставит набор (`toggleStickerSet(…, 2, …)`, `StickerMakerView.java:1513`); iOS-редактор только открывает его (`MediaEditorScreen.swift:8274`).
- **Признак «мой набор».** `stickerSet.creator`: Android `StickersAlert.java:2365`, tdesktop `StickersSetFlag::AmCreator` (`api_stickers_creator.cpp:144`), причём tdesktop ищет свои наборы среди установленных.
- **Пределы.** Android `StickersAlert.STICKERS_MAX_COUNT = 120` (`StickersAlert.java:117`); tdesktop `kStickersInOwnedSetMax = 120`, `kEmojiInOwnedSetMax = 200` (`api_stickers_creator.h:33-34`). «Уже в наборе» tdesktop определяет по неизменившемуся `count` (`api_stickers_creator.cpp:207-214`).
- **Удаление последнего стикера.** Android ждёт в ответ набор и сам снимает его у себя (`StickersAlert.java:247-256`).
- **Проверка имени.** iOS: `SHORT_NAME_OCCUPIED` — занято, любая другая ошибка — неверно (`ImportStickers.swift:707-712`); Android любую ошибку считает «занято» (`StickersAlert.java:1845-1853`).
- **Свои наборы.** Android листает `messages.getMyStickers` по 100, смещение — id последнего (`ContentPreviewViewer.java:2273-2308`); iOS читает только `stickerSetCovered` и `stickerSetFullCovered` (`ImportStickers.swift:561-600`).
- **Обложка набора.** Тип `photoSize`: `a` — TGS, `v` — WEBM, иначе картинка (Android `ImageLocation.java:303-306`); без обложки клиенты берут `thumb_document_id` или первый стикер.
- **Поиск стикеров.** Android и iOS сами находят эмодзи по словам и передают их в `emoticon` вместе с `q` (`MediaDataController.java:10283-10299`, `SearchStickers.swift:309`); tdesktop и Web шлют только `q` и языки (`stickers_list_widget.cpp:672-684`, `appStickersManager.ts` `searchStickersOnServer`) — слова в эмодзи переводит сервер. Страницы по 50–128, `next_offset`.
- **Поиск эмодзи.** `messages.searchCustomEmoji` отдаёт id, документы клиент берёт через `messages.getCustomEmojiDocuments` (iOS `SearchStickers.swift:1646-1665`).
- **Прочитанные трендовые.** Один метод для стикеров и эмодзи: по id набора (Android `MediaDataController.java:2501-2510`, tdesktop `apiwrap.cpp:3476`) и без id — «все» (Android `MediaDataController.java:2472-2487`, одинаковый пустой запрос для обоих видов); на `updateReadFeaturedStickers` / `updateReadFeaturedEmojiStickers` Android помечает прочитанным весь вид (`MessagesController.java:20468-20471`).

Не проверено по источникам (и код на это не опирается): устанавливает ли Telegram созданный набор автору сам; куда Telegram ставит добавленный стикер (в начало или в конец); удаляет ли Telegram набор, оставшийся без стикеров; меняет ли id документа при добавлении в набор.

## Решение

1. **Где живёт набор.** В той же таблице `catalog_sticker_sets`, что и наборы каталога: `source = 'user'`, `owner_id` — автор, `thumb_document_id` — документ своей обложки. Все существующие пути (по id, по имени, наборы аккаунта, наборы групп, списки недавних) работают без изменений. Импорт каталога и набор «по запросу» никогда не заменяют набор пользователя с тем же именем (`keepUserSet` в `Replace` и `PutSet`): ссылка `pluma.chat/addstickers/<имя>` остаётся за автором. Имя набора Telegram, которого у нас ещё нет, пользователь занять может; тогда одноимённый набор Telegram у нас не появится.
2. **Стикер — свой документ.** Сервер читает файл переданного документа из dfs, проверяет его по байтам (`pkg/catalog/stickerfile`) и сохраняет копией через `dfs.importDocument` + `media.importDocument` с атрибутами набора (`documentAttributeSticker` или `documentAttributeCustomEmoji` со ссылкой на набор, размер, имя файла, для видео — `documentAttributeVideo`). Исходный документ не трогаем: он может быть стикером другого набора или лежать в сообщениях. Таблица `user_sticker_set_documents` связывает стикер с набором и с исходным документом: методы, которым передают только стикер, находят набор; один и тот же документ дважды в набор не попадает. Удалённый из набора стикер остаётся документом (`removed = 1`): старые сообщения его показывают, кастомный эмодзи по-прежнему отдаётся по id.
3. **Проверка файла.** WEBP (размер из заголовка VP8/VP8L/VP8X), TGS (gzip + JSON: холст 512, 60 к/с, до 3 с, до 64 КБ), WEBM (EBML: `DocType webm`, дорожка `V_VP9`, размер кадра, длительность, до 256 КБ). PNG не принимаем: официальные клиенты шлют WEBP, а перекодировать нечем без cgo; ответ `STICKER_FILE_INVALID`. Для статичного файла свой предел 1 МБ (в документации его нет). Превью (`thumbs`) у таких стикеров нет, как и у обычных стикеров, отправленных файлом.
4. **Изменение набора.** Одна транзакция со строкой набора под `FOR UPDATE` (`usersets.Store.Update`): читаем `messages.stickerSet`, меняем, пересчитываем `count` и `hash` (CRC32 содержимого, никогда не 0), пишем вместе со связями. Менять может только `owner_id`; чужому — `STICKERSET_INVALID` / `STICKER_INVALID`. Пределы: 120 стикеров или масок, 200 эмодзи.
5. **Кто узнаёт.** Автору набор ставится сразу (`updateNewStickerSet` на все его устройства). После любого изменения каждому аккаунту, у которого набор установлен или в архиве, уходит `updateStickerSets` нужного вида: клиент перечитывает список, видит новый `hash` набора и загружает набор. Удаление набора снимает его у всех с тем же обновлением. Набор уже изменён к моменту рассылки: сбой рассылки пишется в лог, клиент узнает по хэшу при следующей загрузке.
6. **Флаг `creator`** ставится при чтении (`decodeSet`), в хранимом наборе его нет.
7. **Короткое имя.** Пустое — делаем из названия (латиница и цифры, русские буквы транслитом, остальное — подчёркивание), при занятости добавляем цифры; для названия без букв — `set_<цифры>`. То же отдаёт `stickers.suggestShortName`.
8. **Обложка набора.** Эмодзи-набор: `thumb_document_id` из своих эмодзи. Обычный набор: файл по правилам стикера или эмодзи, хранится отдельным документом, `stickerSet.thumbs = [photoSize s|a|v]`, `thumb_version` растёт; `upload.getFile` с `inputStickerSetThumb` обслуживает плагин `usersets.ThumbFiles` (раньше плагина не было, запрос отвечал `ERR_ENTERPRISE_IS_BLOCKED`). У наборов каталога обложек по-прежнему нет (ADR 0028).
9. **Поиск.** Индекс в памяти процесса bff (`pkg/catalog/search`), построенный из хранимых наборов: названия и короткие имена, эмодзи и ключевые слова каждого стикера. Перед поиском, не чаще раза в 3 секунды, читаются хэши всех наборов и перечитываются только изменившиеся. Отдельных таблиц индекса нет — расходиться нечему; после перезапуска индекс строится заново (в фоне при старте). Для каталога в несколько тысяч наборов это единицы мегабайт; внешнего сервиса нет.
   - Наборы: каждое слово запроса — начало слова названия или короткого имени; сначала наборы аккаунта, потом трендовые, потом остальные; до 50. Эмодзи-наборы целиком (`stickerSetFullCovered`), обычные с первыми пятью стикерами (`stickerSetMultiCovered`).
   - Стикеры: по эмодзи из `emoticon` и из текста, по эмодзи, найденным по словам запроса в `messages.getEmojiKeywords` каталога для языков `lang_code`, и по ключевым словам стикеров; порядок стабильный, страницы через `offset`/`next_offset`.
   - Служебные наборы (те, что клиенты просят по виду: анимированные эмодзи, кубики) в поиск не входят.
10. **Трендовые прочитаны.** Таблица `user_featured_sticker_reads`; запрос без id отмечает все трендовые наборы обоих видов (по запросу вид не отличить); непрочитанные в `getFeaturedStickers` / `getFeaturedEmojiStickers` — трендовые наборы без отметки, и они входят в хэш ответа. Раньше `unread` был всегда пуст.
11. **Стикеры на фото.** Таблица `media_attached_stickers` по id фото или документа. Запись — при `messages.uploadMedia`, `sendMedia`, `sendMultiMedia` с `stickers`; там же ставится `photo.has_stickers` или `documentAttributeHasStickers`, а при повторной отправке по id метка восстанавливается. `messages.getAttachedStickers` отдаёт наборы этих стикеров.
12. **Боты.** Методы изменения наборов ботам пока отвечают `BOT_METHOD_INVALID`: у Telegram бот создаёт набор для пользователя с именем `…_by_<бот>`, этого пути нет.

## Последствия
- Миграция `migrate-20261114-own-sticker-sets.sql` (колонки в `catalog_sticker_sets`, три таблицы), повторно запускаемая. Код читает новые колонки, поэтому миграция идёт до запуска bff (как обычно, сервис `migrate`).
- Копия файла на каждый стикер: до 1 МБ, обычно десятки килобайт.
- `alt` в хранимом документе не меняется при `stickers.changeSticker`; меняются набор (packs) и копия документа в наборе. Клиенты читают эмодзи стикера набора из packs.
- У всех аккаунтов после обновления появятся непрочитанные трендовые наборы (значок на вкладке), пока их не откроют.
