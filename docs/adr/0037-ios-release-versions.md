# 0037. Выпуски iOS: версия повторяется, сборку различает номер; конфликт версии — 422, а не 409

- Статус: accepted (2026-11-06).
- Задача: 054 (продолжение), найдено при выпуске iOS-сборки 36 с ссылками pluma.chat (задача 026).
- Заменяет в ADR 0035 правило «повтор номера сборки или версии — `409`» (решение 1) и уточняет, что iOS-приложению показывается как версия (решение 4).

## Контекст
- У iOS версия выпуска — версия Telegram (`UPSTREAM_VERSION`, `12.9.2`), она одна у всех сборок Pluma с этого апстрима. Номер сборки — `BUILD_NUMBER`, номер запуска CI (`ci/release-upload.sh` pluma-ios). `help.getAppUpdate` сравнивает у iOS только номер сборки (`IOSInstalled`, ADR 0035 решение 4).
- Сервис `releases` отказывал выпуску, если у платформы уже есть такая версия: `409`. Первая iOS-сборка (33) записалась, следующая (36, 2026-11-06) получила `409`.
- Все три скрипта CI (`ci/release-upload.sh` iOS, `ci/publish.sh` Android и Desktop) считают `409` повтором той же сборки при перезапуске задачи и завершаются успешно. Поэтому отказ прошёл молча. IPA 36 лежит на странице установки (`iosinstall`), а приложениям предлагается и сайт показывает 33.
- Уникальность версии нужна только выпускам с файлами: их каталог — `files/<платформа>/<версия>`, он не меняется. У iOS файлов нет, IPA раздаёт `iosinstall`.
- Экран обновления iOS показывает версию как «Pluma %@» (`Update.AppVersion`, `UpdateInfoController.swift:87` на `6ad963e5`). С версией `12.9.2` при установленной `12.9.2` предложение выглядит как та же версия.

## Решение
1. **Повтор сборки — `409`.** Это прежний ответ, скрипты CI принимают его за повтор.
2. **Версия, которая уже есть у другой сборки, — `422`, и только у выпуска с файлами** (Android, Desktop). На `422` скрипты CI падают: ответ попадает в ветку «прочее», которая завершается с ошибкой.
3. **Выпуск без файлов (iOS) может повторять версию.** Каждая сборка — свой выпуск, текущий — с наибольшим номером, как у остальных платформ.
4. **`help.appUpdate` для iOS** отдаёт версию с номером сборки, `12.9.2 (36)`, в той же форме, в какой приложение само пишет `app_version`. Экран показывает «Pluma 12.9.2 (36)».

## Последствия
- Сборку 36 приложения не увидят: она отклонена, а записать выпуск без CI нельзя (у `pluma-admin release` нет добавления, токен загрузки — только в CI). Следующая iOS-сборка запишется.
- Скрипты клиентов не меняются: новый код ответа ловит их существующая ветка ошибок.
- Выпуск Android или Desktop с версией, которая уже есть у другой сборки, по-прежнему не публикуется, но теперь CI падает, а не проходит молча.
