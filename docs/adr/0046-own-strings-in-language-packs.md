# 0046. Свои строки Pluma в языковых пакетах сервера

- Статус: accepted (2026-11-10)
- Дополняет: ADR 0025 (пункт «Последствия»: «наши собственные тексты этим механизмом не добавляются»).
- Задача: 076.

## Контекст
- iOS, tdesktop и Web K встраивают только английский, остальные языки берут с сервера (ADR 0025). Тексты патчей Pluma, которых нет у Telegram, на другом языке без сервера не покажутся: русский пользователь увидит английский.
- Первый такой случай — экраны кода входа через Telegram (задача 076): «Проверьте Telegram», «Код не дошёл до Telegram» и путь в настройках Telegram.
- Импорт превращает в надгробия ключи, которых нет в снимке Telegram, поэтому строки, вписанные в базу отдельно, следующий импорт удалил бы.

## Решение
1. **Свои строки лежат в коде**: `pkg/langpack/own.json`, `{пакет: {ключ: {язык: текст}}}`, у каждого ключа обязателен английский. Ключи — те, что вписывают патчи клиентов (iOS `Pluma.*`, tdesktop `lng_pluma_*`, Web K `Pluma.*`).
2. **Импорт добавляет их к снимку** своего пакета на импортируемом языке, как обычные строки: версия растёт только при изменении, повторный импорт ничего не меняет.
3. **Без замены**: «Telegram» в своих строках — настоящий Telegram; `Rebrand` их не трогает, в отчёт об остатках имени они не входят.
4. **Язык без своего текста** получает английский (или текст базового языка, `pt` для `pt-br`); такие ключи перечисляются в `ImportResult.OwnMissing`, `pluma-admin langpack import` их печатает.
5. **Ключ, который есть и у Telegram, останавливает импорт**: своё имя не должно перекрыть чужое.

## Последствия
- После выката новой версии со своими строками нужен `pluma-admin langpack import` (без `fetch`: исходные тексты Telegram хранятся) — `docs/ops/langpacks.md`. Клиенты получают разницу при следующем `help.getConfig`.
- Android встраивает свои строки во все свои языки сам (патч), сервер для него их не добавляет.
- Удалять ключи из `own.json` нельзя без замены: Web K не получает надгробий (ADR 0025, п. 4).

## Дополнение (2026-11-11): строки Telegram с другим текстом
- Задача: 080 (`docs/tasks/080-service-account-strings.md`). Владелец: у аккаунта поддержки вместо «support» пишется «service account» на всех языках.
- Замена имени (`Rebrand`) этого не умеет: меняется смысл, а не слово «Telegram». Патч клиента меняет только встроенный английский; скачанный пакет вернул бы текст Telegram.
- **`pkg/langpack/override.json`** той же формы, что `own.json`: ключи Telegram, текст которых задаёт Pluma. При импорте текст ключа берётся из него на языке импорта; исходный текст Telegram остаётся в `upstream_*`. Ключа нет в снимке — он добавляется, как своя строка. Язык без перевода получает английский и перечисляется в `ImportResult.OwnMissing`.
- Пункт 5 остаётся в силе для `own.json`. Ключ не может быть в обоих файлах: загрузка останавливается.
- Удаление ключа из `override.json` возвращает текст Telegram при следующем импорте.

## Дополнение (2026-11-19): все клиенты, все языки, проверка ключей патчей
- Задача: 114 (`docs/tasks/114-langpack-coverage.md`).
- **Android тоже получает свои строки с сервера.** Пункт «Последствий» про Android заменён: в `own.json` с задачи 076 уже были ключи Android, а ключ ошибки шифрования групповых звонков (задача 094) патч встроил только в 10 папок `values-*` — в остальных 23 языках пакета он был английским. Переводы 10 встроенных языков в `own.json` взяты из патча дословно, чтобы сервер не перекрывал их другим текстом.
- **Полнота по языкам.** Каждый ключ `own.json` и `override.json` имеет свой текст во всех 42 языках пяти пакетов Telegram (`pkg/langpack/languages.json`, по `langpack.getLanguages` на 2026-11-18): к 37 языкам задач 076/080 добавлены af, az, et, lv, sq (их знает только tdesktop). Тест требует все языки списка и пустой `OwnMissing`. Тексты сервера вне пакетов (письма, подписи статистики) остаются на 37 языках: у af, az, et, lv, sq там английский.
- **Ключи патчей.** `pkg/langpack/patchkeys.json` — `{пакет: [ключи, которые добавляет патч клиента]}`; тест требует, чтобы свои строки пакета совпадали с этим списком. Список правится вместе с патчем клиента (правило — в `clients/patches/README.md`); сверка собранного клиента с сервером — `pluma-admin langpack coverage`.
- **Ссылки по пакетам.** Замена ссылок (`linkRules`, `rebrand.go`) — таблица «пакет → ключ → правило» по тем же правкам, что делает патч клиента: Android (вход по QR, `GroupDescription3`), iOS (вход по QR, ключи `STRINGS_LINKS`), Web K (`PublicLinksLimitSubtitle`, `GroupDescription3`; у `ChatList.Main.EmptyPlaceholder.SubtitleNoContacts` ссылки на telegram.org снимаются с сохранением слов, у `ChatAutomation.HeroDescription` убирается пустая ссылка «Подробнее»). tdesktop ссылок в строках не меняет. Это ссылки, а не смысл, поэтому правило, а не `override.json`: переводы Telegram сохраняются на всех языках.
