# 0046. Свои строки Pluma в языковых пакетах сервера

- Статус: accepted (2026-11-10)
- Дополняет: ADR 0025 (пункт «Последствия»: «наши собственные тексты этим механизмом не добавляются»).
- Задача: 076.

## Контекст
- iOS, tdesktop и Web K встраивают только английский, остальные языки берут с сервера (ADR 0025). Тексты патчей Pluma, которых нет у Telegram, на другом языке без сервера не покажутся: русский пользователь увидит английский.
- Первый такой случай — экраны кода входа через Telegram (задача 076): «Проверьте Telegram», «Код не дошёл до Telegram» и путь в настройках Telegram.
- Импорт превращает в надгробия ключи, которых нет в снимке Telegram, поэтому строки, вписанные в базу отдельно, следующий импорт удалил бы.

## Решение
1. **Свои строки лежат в коде**: `pkg/langpack/own.json`, `{пакет: {ключ: {язык: текст}}}`, у каждого ключа обязателен английский. Ключи — те, что вписывают патчи клиентов (iOS `Pluma.*`, tdesktop `lng_pluma_*`, Web K `Pluma.*`).
2. **Импорт добавляет их к снимку** своего пакета на импортируемом языке, как обычные строки: версия растёт только при изменении, повторный импорт ничего не меняет.
3. **Без замены**: «Telegram» в своих строках — настоящий Telegram; `Rebrand` их не трогает, в отчёт об остатках имени они не входят.
4. **Язык без своего текста** получает английский (или текст базового языка, `pt` для `pt-br`); такие ключи перечисляются в `ImportResult.OwnMissing`, `pluma-admin langpack import` их печатает.
5. **Ключ, который есть и у Telegram, останавливает импорт**: своё имя не должно перекрыть чужое.

## Последствия
- После выката новой версии со своими строками нужен `pluma-admin langpack import` (без `fetch`: исходные тексты Telegram хранятся) — `docs/ops/langpacks.md`. Клиенты получают разницу при следующем `help.getConfig`.
- Android встраивает свои строки во все свои языки сам (патч), сервер для него их не добавляет.
- Удалять ключи из `own.json` нельзя без замены: Web K не получает надгробий (ADR 0025, п. 4).
