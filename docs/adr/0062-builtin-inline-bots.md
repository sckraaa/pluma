# 0062. Встроенные инлайн-боты @gif, @pic, @places: реестр в сервере, медиа только с сервера, прокси веб-файлов

- Статус: accepted (2026-11-16). Владелец подтвердил поставщиков (`@gif` — популярное внутри Pluma, `@pic` — SearXNG, KLIPY — только с их письменным согласием) и отказ от мест: `@places`, Photon и всё о местах в тексте ниже не делаются (задача 099). Остальные пункты «Решения владельца» ждут его слова.
- Задача: 099 (ветка `task/099-inline-search-bots`). Меняются `messages.getInlineBotResults`, `messages.sendInlineBotResult`, `contacts.resolveUsername`, `upload.getWebFile` (сейчас `ErrEnterpriseIsBlocked`), `help.getConfig` (`gif_search_username`, `img_search_username`, `venue_search_username`, `webfile_dc_id`), `help.getAppConfig` (`stories_venue_search_username`, `gif_search_emojies`).
- Связано: ADR 0043 (боты MTProto, `pkg/botstore`, `pluma-admin bot`), задача 070 (инлайн-режим, открытый вопрос о `webDocumentNoProxy`), ADR 0027 (превью ссылок: безопасная загрузка с публичного интернета, `pkg/webpage`), ADR 0057 и 0061 (открытое содержимое не покидает дом, исходящий трафик через VPS), ADR 0041 (всё открыто всем), ADR 0046 (свои строки на 37 языках), задача 100 (карты: `inputWebFileGeoPointLocation` на общей основе `upload.getWebFile` из этого ADR).

Удаления файлов в dfs нет нигде.

### Поставщики (прочитано 2026-11-15)
- **KLIPY** (docs.klipy.com/integration-requirements.md, /attribution.md, /getting-started.md, /gifs-api/gifs-search-api.md, /gifs-api/gifs-format-sizes.md). Стандартные условия: медиа грузить прямо с URL ответа, не хранить, не зеркалировать, не держать копий; **запросы к API и медиа — только с устройства пользователя, не через серверы, прокси и CDN партнёра** без письменного разрешения; не переупорядочивать и не смешивать выдачу с другими источниками. Серверные запросы, прокси и кэш — только по предварительному письменному согласию (developers@klipy.com), и одобренный кэш обязан следовать их спецификации ревалидации, удаления и инвалидации. Атрибуция: плейсхолдер поиска «Search KLIPY» — обязательно, водяной знак и «Powered by KLIPY» — по желанию. Тестовый ключ — 100 запросов в час, боевой — «unlimited» по запросу в панели партнёра. Цены в документации нет. `customer_id` необязателен. `per_page` 8–50. Медианный размер mp4: `sm` ≈ 85 КБ, `hd` ≈ 295 КБ.
- **GIPHY** (developers.giphy.com/docs/api, /best-practices): кэш и копии медиа, прокси запросов и медиа запрещены без одобрения; боевой доступ по договорённости. **Tenor** закрыт 2026-06-30 (отчёт исследования, источники там).
- **SearXNG** (docs.searxng.org/dev/search_api.html, /dev/result_types/main/image.html): `/search?q=&categories=images&pageno=&safesearch=&language=&format=json`; формат `json` должен быть включён в `settings.yml` (`search.formats`), иначе 403; у результата картинки `img_src`, `thumbnail_src`, `resolution`, `img_format`.
- **Photon** (github.com/komoot/photon README и docs/api-v1.md; download1.graphhopper.com/public): `/api?q=&lat=&lon=&limit=&lang=&layer=&bbox=`, `/reverse?lat=&lon=&radius=`; планета — около 95 ГБ диска, рекомендовано 64 ГБ RAM, Java 21+; еженедельные дампы. Сжатые дампы БД 1.0 (2026-11-10): планета 63,2 ГБ, Европа (с Россией, Беларусью, Молдовой, Украиной, Грузией) 32,5 ГБ, Северная Америка 15,6 ГБ, Южная Америка 7,3 ГБ; для Центральной Азии, Армении, Азербайджана есть только JSON-дампы (Центральная Азия — 191,9 МБ).

## Решение

### 1. Реестр встроенных ботов в сервере
- Пакет `pkg/inlinebots`: три записи — `gif` (id 1000101, вид `gif`), `pic` (1000102, `photo`), `places` (1000103, `venue`, `bot_inline_geo`). Ни токена, ни процесса бота: на `messages.getInlineBotResults` к ним отвечает сам bff `bots` через поставщика (раздел 3).
- Учётные записи заводит идемпотентный `teamgramd/deploy/sql/z_pluma-inline-bots.sql` (как антиспам): строка `users` (`is_bot = 1`), имя в `username`, строка `bots` с `bot_inline_placeholder`, `bot_nochats = 1`, `bot_inline_geo` у `places`, пустой `token`. Путь `pluma-admin bot create` и его правило имён не меняются; `pluma-admin bot token|set` отказывает id из реестра.
- `contacts.resolveUsername` больше не смотрит таблицу апстрима `GetBotIdByName`: имя ищется только в `username`. Это заодно чинит имена `music`, `youtube`, `sticker` и подобные у людей и каналов.
- При старте bff `bots` сверяет реестр с базой (имя → id, `is_bot`, плейсхолдер); расхождение — ошибка в логе и метрика, бот не обслуживается (отвечает `BOT_INLINE_DISABLED`), остальное работает.

### 2. Конфигурация клиентов
- `help.getConfig`: `gif_search_username = gif`, `img_search_username = pic`, `venue_search_username = places` — всегда все три; `webfile_dc_id = 1`.
- `help.getAppConfig`: `stories_venue_search_username = places`; `gif_search_emojies` — пустой список, пока у `@gif` нет поиска по тексту (раздел 4.1): без него категории-эмодзи в панели были бы пустыми; с поиском — список Android по умолчанию (`MessagesController.java:1948-1957`).

### 3. Ответы — только медиа с сервера
- `@gif` отвечает `botInlineMediaResult` с документом-анимацией (`video/mp4`, `documentAttributeAnimated`, `documentAttributeVideo`), `@pic` — `botInlineMediaResult` с фото, `@places` — `botInlineResult` типа `venue` с `botInlineMessageMediaVenue` (`provider = "osm"`, `venue_id` = OSM-тип и id, `venue_type = ""`), без миниатюры.
- Причина — клиенты: Web K берёт из панели только документы; Android при URL-результатах поиска картинок сам качает чужой адрес по HTTP. С файлами из dfs ни одно устройство не обращается к сторонним хостам, `sendInlineBotResult` и `outOfResult` работают без изменений, сохранённые GIF работают.
- Файлы импортируются при запросе: сервер качает медиа через общий безопасный загрузчик (`pkg/webfetch`, вынесен из `pkg/webpage`), фото пережимается в JPEG ≤ 1280 px, GIF — mp4 одной выбранной версии ≤ 2 МБ. Таблица `inline_media` помнит, что уже импортировано (поставщик + ключ источника → фото/документ), так что повтор и популярное не качаются снова. Дневной бюджет байтов импорта, сверх него отдаётся только уже импортированное.
- `hide_via` соблюдается только для ботов реестра (по документации — «encountered in the config»); для сторонних ботов подпись остаётся всегда, как сейчас.

### 4. Поставщики
#### 4.1. GIF
- **KLIPY по стандартным условиям не подходит**: условия требуют запросов и загрузки медиа с устройства и запрещают серверные запросы, прокси, хранение и смешивание выдачи — это прямо противоречит правилу «устройства не ходят к третьим лицам» и модели Telegram, где выбранный GIF становится документом в истории чата.
- **Подходит только с письменным согласием KLIPY** на серверную интеграцию: поиск и популярное с сервера Pluma без `customer_id`, хранение импортированных GIF в Pluma (отправленный GIF остаётся в истории чата навсегда), их ревалидация и удаление из кэша по спецификации KLIPY, порядок выдачи без изменений, без смешивания. Обязательная атрибуция «Search KLIPY» как плейсхолдер — тоже вопрос к KLIPY: плейсхолдер у нас без слов (раздел 6). Запрос пишет владелец; адаптер KLIPY строится только по полученной спецификации.
- GIPHY запрещает то же самое и платный — не берётся. Альтернативы поиска GIF по тексту с правом хранения не найдено.
- **Без KLIPY** `@gif` отвечает только на пустой запрос: популярное внутри Pluma — GIF, которые сохранили не меньше трёх разных людей (`user_saved_gifs`), и GIF, отправленные через `@gif`, по числу отправок за 30 дней. Запрос с текстом — пустой список. С KLIPY локальный список не подмешивается (условие KLIPY).

#### 4.2. Картинки — свой SearXNG дома
- Отдельный контейнер `searxng` (закреплённая версия) в сети сервисов, без опубликованного порта; `json` включён, `safesearch = 1`, движки картинок — выбор при настройке. bff зовёт его по внутреннему адресу. Ссылки картинок из ответа качаются только через безопасный загрузчик.
- Текст запроса уходит поисковикам (через SearXNG, с адреса VPS по ADR 0061) — как адреса ссылок при превью (ADR 0027). Ни пользователь, ни его IP поисковикам не видны. Сообщения и файлы дом не покидают.

#### 4.3. Места — свой Photon дома
- Контейнер `photon` (Java 21, закреплённая версия, своя сборка) с данными на отдельном томе, без доступа в интернет во время работы. Запрос с `geo_point` — места рядом (`/api` со смещением к точке, пустой текст — `/reverse`), без точки — поиск по тексту. Язык — `lang` из сессии.
- Ничего не уходит наружу: ни текст, ни координаты.
- Данные: регионы владельца (Европа с Россией, СНГ, Северная и Южная Америка) по размеру близки к планете (сжатые дампы 55,4 ГБ из 63,2 ГБ планеты), а объединение нескольких JSON-дампов в одну базу не проверено. Владелец выбрал регионы (2026-11-15); если импорт нескольких дампов в одну базу на CachyOS не проходит, берётся дамп БД планеты (~95 ГБ по README).
- Атрибуция ODbL — в описании бота на языке человека.

### 5. `upload.getWebFile`: общая основа и прокси подписанных адресов
- Пакет `pkg/webfile`: разбор `upload.getWebFile` по виду места, общие для всех видов правила `offset`/`limit` (`offset < 0` — `OFFSET_INVALID`, `limit` вне 1…1 МиБ — `LIMIT_INVALID`, как у `upload.getFile`; за концом файла — пустые `bytes`; вид без источника — `LOCATION_INVALID`), ответ `upload.webFile{size, mime_type, file_type, mtime, bytes}` (тип файла по MIME), кэш на диске bff с пределом размера и одной загрузкой на ключ одновременно — для источников, которые не держат копию сами (карта 100 держит свою в Redis).
- `inputWebFileLocation`: `access_hash` = первые 8 байт HMAC-SHA256 под ключом `WEBFILE_HMAC_KEY` с меткой `pluma-webfile-v1` от адреса. Сервер отдаёт только адреса, которые подписал сам. Чужой хэш — `LOCATION_INVALID`; адрес не публичный, не http(s), ответ не того типа, больше предела или недоступен — `WEBFILE_NOT_AVAILABLE` (имя ошибки уже есть в обработчике; документация его не называет — выбор сервера).
- URL-миниатюры и контент сторонних инлайн-ботов отдаются как подписанный `webDocument` вместо `webDocumentNoProxy`: хост бота видит адрес VPS, а не пользователя. Это закрывает открытый вопрос задачи 070.
- Сессия пускает `upload.getWebFile` в обход очереди ключа, как запросы к ботам: загрузка с чужого хоста может идти секунды.
- Задача 100 регистрирует источник `inputWebFileGeoPointLocation` (свой рендер и кэш), не меняя общую часть. Основу строит только задача 099 (часть B, вместе с `webfile_dc_id: 1` и `DontLogContentForMethod`); 100 сливается после неё.

### 6. Тексты
- Описания ботов (`bot_info.description`, а с ним и атрибуция) — ключи `pkg/langpack/inlinebots.json` на всех 37 языках `own.json`; `botstore.BotInfo` для ботов реестра берёт их по языку сессии.
- Имена ботов и `bot_inline_placeholder` хранятся в объекте `User`, а он у Pluma не зависит от того, кто смотрит. Поэтому имена — собственные названия без перевода (`GIF`, `Pic`, `Places`), а плейсхолдер — символ без слов (`🔍`). Перевод имени и плейсхолдера на язык зрителя требует отдельной работы во всех местах, где сервер отдаёт пользователей.
- Задача 111 (владелец, 2026-11-17): имена стали `GIF Search` и `Image Search` (`z_pluma-inline-names.sql`), у ботов есть фото (`pluma-admin inline-bots photos`). Правило то же: собственные названия без перевода.

## Последствия
- Вкладка GIF и `@gif`, `@pic`, `@places` в поле ввода работают во всех четырёх клиентах без патчей. Поиск картинок в галерее Android работает. Ни одно устройство не обращается к сторонним хостам за медиа этих ботов и сторонних инлайн-ботов.
- Поиск GIF по тексту появится только после письменного согласия KLIPY. До этого `@gif` — популярное внутри Pluma.
- Импортированные файлы не удаляются: в dfs нет удаления, а безопасная сборка мусора требует учёта ссылок во всех путях отправки (Web K отправляет выбранный GIF как `inputMediaDocument`, минуя `sendInlineBotResult`). Рост ограничен повторным использованием и дневным бюджетом; размер виден в метриках. Сборка мусора — отдельная задача, если рост станет заметен.
- Новые контейнеры дома: `searxng` (сотни МБ RAM, не измерено) и `photon` (~95 ГБ диска для планеты, 4–8 ГБ кучи — не измерено, измерить на CachyOS до выката). На время обновления дампа Photon нужен второй том того же размера или простой поиска мест.
- Решения владельца: (1) писать ли в KLIPY и что принимать из их условий; (2) планета или регионы для Photon (диск); (3) SearXNG ходит к поисковикам с адреса VPS — их блокировки и CAPTCHA возможны, платного запасного поставщика не ставим без его слова; (4) трёхпользовательский порог для популярного из сохранённых GIF; (5) имена и плейсхолдер без перевода.

## Что не делается
- Патчи клиентов: выбор мест в пикере iOS и Android остаётся за ОС, поиск картинок в iOS, tdesktop и Web K не появляется.
- `inputMediaAreaVenue` в историях (остаётся `QUERY_ID_INVALID`, ADR 0054): в 13.2 его не шлёт ни iOS (места выключены флагом), ни Android (бот мест не используется).
- URL-контент сторонних ботов с `inputBotInlineMessageMediaAuto` по-прежнему отклоняется (`SEND_MESSAGE_MEDIA_INVALID`, задача 070): сервер не импортирует их файлы.
- Сборка мусора импортированных файлов, перевод имён и плейсхолдеров на язык зрителя, `inputWebFileAudioAlbumThumbLocation`, `@vid`, `@wiki`, `@music` и другие боты Telegram.
- GIPHY, Tenor, платный запасной поиск картинок.
