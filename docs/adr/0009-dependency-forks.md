# 0009. Свои копии teamgram/proto и teamgram/marmota

- Статус: accepted
- Дата: 2026-10-21 (уточнено при старте задачи 001: копии в репозитории, а не отдельные форки)

## Контекст
Часть исправлений безопасности (декодер TL, gzip, ошибки расшифровки в `mtproto/crypto`) и доставки (Kafka-консьюмер в `marmota/pkg/mq`) находится не в этом репозитории, а в зависимостях `github.com/teamgram/proto` и `github.com/teamgram/marmota`.

## Решение
- Копии модулей лежат в репозитории: `third_party/teamgram-proto`, `third_party/teamgram-marmota` (когда понадобится), подключены через `replace` в `go.mod`.
- Первый коммит копии — нетронутый upstream указанной версии (`v0.228.0`). Каждое наше изменение — отдельный коммит с префиксом `third_party(proto):` / `third_party(marmota):`, чтобы при обновлении layer переносить их на новую версию upstream (`git log -- third_party/teamgram-proto` даёт полный список патчей).
- Где возможно, исправление делается в основном коде (обёртка), а не в копии — меньше конфликтов при обновлениях.

## Последствия
- Один репозиторий, без внешних форков и дополнительных доступов; сборка воспроизводима.
- Репозиторий тяжелее (~30 МБ сгенерированного кода).
- Обновление layer = заменить содержимое копии новой версией upstream одним коммитом и заново применить наши коммиты-патчи.

## Рассмотренные альтернативы
- Отдельные форки на GitHub владельца — лишние репозитории и доступы; при единственном владельце выигрыша нет.
