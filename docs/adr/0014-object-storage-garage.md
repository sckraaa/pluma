# 0014. Объектное хранилище: Garage вместо MinIO

- Статус: accepted
- Дата: 2026-10-23

## Контекст
С 2026 года MinIO не публикует образы; в compose стояли сборки `pgsty/minio` и `pgsty/mc` из исходников сторонним человеком — риск цепочки поставок, а сама MinIO community edition в режиме поддержки. `dfs` делает только базовые вызовы S3 через `minio-go`: `PutObject`, `GetObject` (с диапазоном), многочастную загрузку (`NewMultipartUpload`, `PutObjectPart`, `CompleteMultipartUpload`); политик, версий, presigned URL нет. Нагрузка — до 100 пользователей, один сервер.

## Решение
- **Garage** (Deuxfleurs, AGPL-3.0, официальный образ `dxflrs/garage`, закреплён по digest): один узел, одна копия, метаданные в SQLite с автоснимком раз в час (`metadata_auto_snapshot_interval`) — согласованная копия для бэкапа без остановки.
- Конфиг — `teamgramd/deploy/garage/garage.toml`; секреты из окружения: `GARAGE_RPC_SECRET`, `GARAGE_ADMIN_TOKEN`. Ключ S3 для dfs — `S3_ACCESS_KEY_ID` (`GK` + 24 hex) и `S3_SECRET_ACCESS_KEY` (64 hex).
- **Подготовка хранилища** — одноразовый сервис `storage-init` (`pluma-admin storage init`, пакет `pkg/garage`, Admin API v2): роль узла в раскладке, импорт ключа dfs, бакеты из конфига dfs и права ключа на них. Каждый шаг идемпотентен; dfs стартует только после успеха.
- `dfs` указывает регион `garage` (без лишнего `GetBucketLocation`).
- Бэкап (ADR 0013): блоки данных (неизменяемые файлы) и последний снимок метаданных; живая база метаданных не копируется.

## Последствия
- Нет сторонних сборок в цепочке поставок; один процесс, около 50 МБ памяти.
- Существующей установки с данными в MinIO нет (сервер ещё не развёрнут), переноса данных не требуется. Если понадобится: `rclone sync` из MinIO в Garage по S3.
- Проверка — интеграционный тест `pkg/garage` (подготовка дважды, затем вызовы dfs: запись, чтение с диапазоном, многочастная загрузка) и e2e-стек на Garage.

## Рассмотренные альтернативы
- Оставить `pgsty/minio` — сторонняя сборка без гарантий; MinIO CE в режиме поддержки.
- Chainguard MinIO — бесплатно только тег `latest`, без закрепления версий.
- SeaweedFS (Apache-2.0) — больше компонентов (master, volume, filer), метаданные filer в LevelDB без штатного снимка для согласованного бэкапа.
- RustFS — молодой проект.
