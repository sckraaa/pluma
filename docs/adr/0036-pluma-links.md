# 0036. Ссылки pluma.chat: один хост ссылок, сервис `links` за Caddy, клиенты считают pluma.chat своим

- Статус: accepted (2026-11-06; решение владельца — бриф 026: «pluma.chat вместо t.me… в браузере функционал один в один с t.me, в стиле сайта»).
- Задача: 026.

## Контекст
- Сервер строил приглашения и ссылки бустов с хоста `t.me`: `pkg/env2.TDotMe = "t.me"`, флаг нигде не переопределялся. Из-за этого QR-код и ссылка приглашения на Android показывали `t.me/+…` (`biz/chat/internal/dao/chat_invite.go:24`). `me_url_prefix` в `help.getConfig` уже был `https://pluma.chat/`.
- core.telegram.org/api/links: клиент считает своими ссылки `t.me`, `telegram.me`, `telegram.dog` «и домен из `me_url_prefix`». На деле официальные клиенты так не делают: Android и Desktop строят из `me_url_prefix` только исходящие ссылки, iOS и Web K его не читают вовсе. Распознавание везде идёт по зашитому списку хостов (Android `LaunchActivity.java:1969`, `Browser.java:727`; iOS `UrlHandling.swift:11-14`, `OpenUrl.swift:233`; tdesktop `local_url_handlers.cpp:1936`, `click_handler_types.cpp:81`; tweb `matchTelegramUrlHost.ts:3`; пины клиентов — `upstream.env`).
- t.me в браузере (снято 05.11.2026 curl'ом с разными User-Agent):
  - **Карточка.** Почти у каждой ссылки один шаблон: фото или значок, название, строка «N subscribers»/«N members», описание, одна кнопка на `tg://…` и строка «If you have Telegram, you can … right away». Скрипт сам открывает приложение: на iOS через скрытый iframe с запасным переходом через 2 с, у остальных через 100 мс. Android получает `tg:path` без `//`.
  - **Без 404.** Неизвестное имя получает 200 и общую страницу «contact @name»; неверный хеш приглашения выглядит так же, как верный.
  - **Мусорные пути** уходят 302 на telegram.org.
  - **Лента канала.** `t.me/s/<канал>` — веб-лента публичного канала; для остальных имён она отвечает 302 на `/<name>`.

## Решение
1. **Один хост ссылок.** `env2.TDotMe = "pluma.chat"`. Тест `pkg/conf` (`TestLinkHost`) держит его равным хосту `me_url_prefix`. Приглашения и бусты строятся на нём. Разбор приглашения (`chat.GetInviteHashByLink`) принимает и pluma.chat, и t.me/telegram.me/telegram.dog в формах `/+` и `/joinchat/`: у клиентов остались выданные раньше ссылки t.me. В базе хранится только хеш, миграции нет.
2. **`channels.exportMessageLink`** отвечает по core.telegram.org/api/links#message-links: `<имя>/<id>`, `c/<канал>/<id>`, с `thread` — `<тред>/<id>`, медиа альбома без `grouped` — `?single`. Поле `html` пустое: виджета встраивания нет.
3. **Сервис `links`** (`app/interface/links`, сервис основного compose). Caddy отдаёт файлы и страницы сайта как раньше, а всё остальное на доменах сайта проксирует в `links:9096`.
   - Сервис разбирает путь по таблице `t.me` и строит страницу на сервере. Без серверного рендера не будет og-тегов, а по ним строят превью ссылок мессенджеры и сети.
   - Оформление — бумага, чернила, шалфей и Geologica сайта, ru/en по `Accept-Language`, светлая и тёмная тема по системе.
   - Кнопки: «Открыть в Pluma» (`plm://…`, на Android `plm:…`) и «Открыть в браузере» (`web.pluma.chat/#?tgaddr=plm://…`, разбор `tgaddr` в Web K). Скрипт открытия — отдельный файл: CSP сайта запрещает встроенные скрипты.
   - Неизвестное имя — 200 с общей страницей (как t.me), мусор — 302 на главную сайта. Пути функций, которых в Pluma нет (`giftcode`, `invoice`, `$…`, `call`, `m/`, `nft`, `auction`, `addstyle`, `newbot`), тоже уходят на главную.
   - Лента `/s/<канал>` есть только у публичного канала: последние 20 постов, текст с разметкой (смещения UTF-16 по API), фото, просмотры, даты, «Показать ранние посты». Для остальных имён — 302 на `/<name>`. Поиска по ленте пока нет.
4. **Приватность.** Страница показывает то, что видно любому, кто не вошёл в Pluma. «О себе» и главное фото пользователя видны только при правиле «все» (`EvaluatePrivacy` для зрителя без аккаунта, ADR 0031), иначе фото — публичное (ADR 0033). История канала читается с `self_id = 0`: сервис каналов отдаёт её только публичному каналу. Фото выдаются по имени (`/_l/avatar/<имя>`, `/_l/post/<канал>/<id>/photo`), а не по id: чужие фото нельзя перебрать. Сервис не пишет в лог ни ссылки, ни имена, ни хеши.
5. **Имена-пути.** Первые сегменты путей сайта и ссылок (`android`, `iphone`, `windows`, `linux`, `assets`, `collect`, а также `joinchat`, `addstickers`, `proxy`, `share`, `login`, `boost` и т. п.) не могут быть username: `user.ReservedUsername` отвечает `USERNAME_INVALID`, иначе такое имя никогда бы не открылось.
6. **Клиенты** (патчи A-099…A-105, I-…, D-…, W-…; реестры `clients/patches/*.md`):
   - pluma.chat — внутренний хост, как t.me, точное совпадение (не `*.pluma.chat`: `web.pluma.chat` — настоящий сайт). Ссылки t.me тоже остаются внутренними, как в апстриме.
   - Исходящие ссылки, которые клиент строит сам (профиль, сообщение, набор стикеров, QR, прокси, телефон, истории), — на pluma.chat. Ссылки на функции, которые есть только у Telegram (подарки, Premium, Stars, BotFather), не трогаем.
   - Android: перехват `https://pluma.chat` с `autoVerify`. Сайт отдаёт `/.well-known/assetlinks.json` с отпечатком сертификата подписи релиза (он публичен, читается из APK).
   - iOS: универсальные ссылки (`applinks:pluma.chat`) отложены, они требуют возможности Associated Domains у App ID и новых профилей в аккаунте Apple. Внутри приложения pluma.chat распознаётся.

## Последствия
- Ссылки, выданные раньше (t.me/+…), продолжают работать в приложениях Pluma: t.me остался внутренним хостом.
- Ссылка `t.me/<имя>` внутри Pluma открывает объект Pluma с тем же именем, а не Telegram (так было и раньше).
- Имя, которое кто-то занял до этого решения и которое теперь зарезервировано, у владельца остаётся (сервер его не отнимает), но его ссылка pluma.chat ведёт на главную сайта или на его страницу. Проверка перед выкаткой — запрос из `docs/ops/deployment.md` («Ссылки pluma.chat»); совпадения решает владелец.
- Если на сайте появится новая страница, её путь нужно исключить из `@links` в Caddyfile, иначе он уйдёт в `links`; если её имя может быть username — добавить его в `ReservedUsername`.
- Превью ссылок pluma.chat внутри Pluma (`pkg/webpage`) строятся по og-тегам этих страниц, как для любого сайта. Особых типов `telegram_channel`/`telegram_user`, как у ссылок t.me в Telegram, нет.
