# 0004. Архитектура звонков

- Статус: proposed — окончательно принимается на этапе звонков (этап 3 ROADMAP с 2026-10-30) после прототипа и замеров качества
- Дата: 2026-10-21 (пересмотрено по `docs/audit/04-clients-and-builds.md` и `docs/audit/06-call-quality.md`)

## Контекст
Владелец хочет качество звонков уровня Discord (между странами, на плохих сетях, экран и вебкамера), но без дорогого парка серверов по миру. Исследование показало:
- качество Discord держится в первую очередь на медиа-стеке (адаптация к каналу, повторы потерь, слои качества), а не на количестве точек присутствия: на звонок один SFU, и для смешанной географии важнее место звонка и связность дата-центра;
- в tgcalls лимиты зашиты консервативно (Opus 32 кбит/с, видео 1:1 1000–1200 кбит/с, общий потолок групп 1052 кбит/с, слои 60/110/900);
- `tgcalls/tools/go_sfu` совместим с родными клиентами, но это тестовый SFU: NACK игнорируется, опора на REMB (клиенты его не шлют), всё аудио пересылается всем, только UDP4;
- в РФ с 2025 года режутся соединения к зарубежным дата-центрам и Cloudflare; на мобильных сетях появляются белые списки.

## Решение (предлагаемое)
- **Без флота:** один медиа-узел (go_sfu, доведённый до продакшна, + coturn) в хорошо связанном дата-центре ЕС рядом с основным сервером. Дополнительные узлы — только по замерам (RTT > 120–150 мс) и в виде дешёвых L4-форвардеров.
- **Универсальность (география пользователей неизвестна):** региональные узлы подключаются конфигурацией, без изменений кода. Реестр узлов (coturn, форвардеры к SFU) с регионами; при каждом звонке сервер выбирает узлы для конкретного клиента по стране его IP (сервис `geoip` уже есть) и отдаёт их в `phoneConnectionWebrtc` / ответе на `phone.joinGroupCall`. Для стран с блокировками зарубежных дата-центров (сейчас РФ) правило «только узлы внутри страны + TCP/TLS 443» включается записью в конфиге. Метрики качества по странам показывают, где пора добавлять узел.
- **1:1:** P2P разрешён; `phoneConnectionWebrtc` со STUN/TURN: свой coturn основной, Cloudflare TURN (1 ТБ/мес бесплатно) — для пользователей вне РФ; имена хостов сервер резолвит в IP перед выдачей.
- **SFU до продакшна:** ответы на NACK из RTX-кэша, оценка канала до каждого получателя по transport-cc и выбор слоя simulcast, лимит PLI, пересылка только активных говорящих, IPv6, UDPMux на одном порту, ICE-TCP на 443 (проверить тестом на iOS/Android/tdesktop), метрики.
- **Один патч tgcalls** (общий C++ для iOS/Android/desktop): лимиты битрейта и параметры Opus — из параметров от сервера; TURN через TCP/TLS.
- iOS: CallKit + PushKit (VoIP push) с самого начала.
- Порядок: TURN + P2P → SFU (NACK, transport-cc, ICE-TCP) → патч tgcalls → замеры → форвардеры. AV1/SVC откладываем (групповой движок умеет VP8, VP9, H.264).

## Последствия
- Стоимость: ≈ $0–15/мес сверх основного VPS при обычной нагрузке (трафик укладывается во включённый у хостера).
- Клиенты остаются родными; расхождение с Telegram — только в лимитах качества (в нашу пользу).
- SFU — отдельный подпроект; критерии качества (потери, задержка, MOS, разрешение экрана) фиксируются до начала работ.

## Рассмотренные альтернативы
- LiveKit в клиентах — переписывание медиа-слоя пяти клиентов.
- Глобальный парк медиа-серверов — дорого, а основной выигрыш даёт медиа-стек.
- Cloudflare Realtime SFU — несовместим с протоколом групповых звонков tgcalls (HTTP-API своей модели).
