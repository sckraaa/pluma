# 0042. Панель — пульт владельца: без ролей, блокировка каналов, открытая регистрация

- Статус: proposed (2026-11-09).
- Задача: 072. Дополняет ADR 0040 (сеть и вход не меняются). Обоснование и источники — бриф `docs/tasks/072-admin-panel.md`.

## Контекст
Панель 025 была инструментом модерации с тремя ролями. Владелец решил (2026-11-09): в панели работает только он, панель — пульт для всего Pluma. Заново потребовалось то, чего в сервисах нет: блокировка канала и группы, переключатель регистрации, рассылка от 777000, операции над выпусками и зависшими событиями.

Источники:
- `core.telegram.org/constructor/channel` (`restricted`, `restriction_reason`), `/constructor/restrictionReason` (платформа `all`: клиент не показывает канал). Клиенты: Android `MessagesController.getRestrictionReason` и `checkCanOpenChat` (показывает текст и не открывает чат), `ChatObject.isNotInChat` (группа `deactivated` — вне чата), tdesktop `Data::UnavailableReason::Extract` (`platform == "all"`), iOS `PeerUtils.restrictionText`, Web K `isPeerRestricted`.
- `chat#` слоя 228 не имеет полей ограничения, поэтому обычная группа не может быть `restricted`.

## Решение
1. **Ролей нет.** `admin_users` — список логинов tailnet, которым открыта панель (столбец `role` убран, миграция `migrate-20261109-panel-roles.sql`). Первый вход по-прежнему `pluma-admin panel owner`, название команды оставлено.
2. **Блокировка канала и супергруппы — RPC `channel.setBlocked`**, столбец `channels.blocked`. `channelperm.Can` отвечает `CHANNEL_PRIVATE` на любое действие, включая создателя; чтение (`viewerOf`) закрыто, кроме `getChannelDifference` (иначе клиенты, получив `CHANNEL_PRIVATE`, убрали бы канал из диалогов, Android `checkChannelError`; новых сообщений в заблокированном канале нет). В объекте канала — `restricted` с `restriction_reason` платформы `all`. Текст один на всех: язык читателя при сборке объекта неизвестен, поэтому в нём два языка сервера (`channel_view.go`).
3. **Блокировка обычной группы — RPC `chat.setBlocked`**, столбец `chats.blocked` вместе с `deactivated`: клиенты считают группу недоступной, участники сохраняются, снятие блокировки возвращает её. Удаление заблокированной группы идёт поверх: `chat.deleteChat` отличает блокировку от удаления по `blocked`.
4. **Регистрация «открыта / по списку»** — таблица `registration_settings`, одна строка. `phoneallowlist.DAO.Contains` читает её вместе со списком на каждый запрос логина, поэтому переключатель действует на следующем `auth.sendCode` и `auth.signUp`. Строки нет — по списку. Пока нет доставки кодов (задача 073), открытая регистрация означает, что код видит только владелец: на карточке пользователя или в разделе «Регистрация».
5. **Опасные действия только через RPC сервисов и с ключом доступа.** Панель пишет только свои таблицы и журнал. Исключения, как у `pluma-admin`, через пакеты с той же логикой: `phone_allowlist` (`pkg/phoneallowlist`), `user_passwords` при удалении аккаунта (`pkg/twofa.Forget`), коды входа в Redis (`pkg/logincode`), `mq_outbox` (`pkg/outbox`, в транзакциях ящика).
6. **Выпуски — через сервис `releases`**: новые маршруты `/internal/releases` за отдельным токеном, не проксируются Caddy, порт опубликован только на loopback хоста.
7. **Рассылка** — задача в `admin_broadcasts`: воркер панели, по одному получателю, курсор и аренда 5 минут; после падения продолжает, максимум один дубль.
8. **Удаление только после блокировки**: сервер проверяет ограничение (аккаунт) или `blocked` (канал), плюс ввод id заново и ключ доступа.

## Последствия
- Панель зависит от Prometheus только для разделов «Обзор» и «Система», остальное работает без него.
- Заблокированный создатель канала не может ни писать, ни читать его.
- Доставка кода при открытой регистрации — задача 073.
