# 0038. Права в каналах: одна функция прав, ограниченный остаётся участником, исключённый — своё состояние, ошибки по типу медиа

- Статус: accepted (2026-11-07).
- Задача: 042. Исследование и решения — бриф `docs/tasks/042-channel-rights.md` («Исследование», «Решения»).
- Заменяет в ADR 0034 строку `USER_BANNED_IN_CHANNEL` п. 8 (ошибки) и уточняет п. 9 (права). Остальное в ADR 0034 не меняется.

## Контекст
- `channels.editAdmin`, `channels.editBanned`, `channels.editCreator` и канальные ветки `messages.editChatDefaultBannedRights` и `messages.editChatCreator` отвечали `ERR_ENTERPRISE_IS_BLOCKED`. Права проверялись в каждом обработчике по-своему, личные ограничения участника и их `until_date` не учитывались нигде.
- Состояние `state = 2` значило «забанен» и выкидывало участника из рассылки и отправки (`state = 0` в истории, разнице, отправке), хотя ограниченный участник в Telegram остаётся в группе.
- `USER_BANNED_IN_CHANNEL` все четыре клиента показывают как общий антиспам-запрет (Android `AlertsCreator.java:513-514`, tdesktop `apiwrap.cpp:530-541`, iOS `PendingMessageManager.swift:94`), а не как запрет в этой группе.

## Решение
1. **Одна функция прав** `pkg/channelperm.Can(channel, participant, action, now)` — для отправки (по типу медиа), правки, удаления чужих сообщений, приглашений, смены данных, бана и назначения админов. Создатель может всё; админ — что дают `admin_rights` (в трансляции отправка — только с `post_messages`, закрепление — также с `edit_messages`); подписчик трансляции только читает; участник супергруппы — что не запрещают общие ограничения канала и его личное ограничение, пока не наступил `until_date` (0 и Int32.max — навсегда).
2. **Ограниченный остаётся участником** (`state = 0` с `banned_rights` и `until_date`). `state = 2` — только исключённый (`view_messages`), он вне канала до своего `until_date`. Истечение проверяется при чтении, без задачи по расписанию. Счётчики `kicked_count` и `banned_count` считаются запросом при чтении канала: хранимый счётчик держал бы истёкшие запреты.
3. **Ошибки отправки:** запрет писать — `CHAT_WRITE_FORBIDDEN`; запрет типа медиа и общий `send_media` — ошибка этого типа (`CHAT_SEND_PHOTOS_FORBIDDEN` и т. д.: у Android есть текст для каждого типа и нет для `CHAT_SEND_MEDIA_FORBIDDEN`, `AlertsCreator.java:448-519`); медиа без своего флага (место, контакт) — `CHAT_SEND_MEDIA_FORBIDDEN`. `USER_BANNED_IN_CHANNEL` не используется. Превью ссылки участника без `embed_links` убирается, сообщение не отклоняется.
4. **Проверка — под блокировкой канала** (после `channelbox.Open`) в транзакции ящика того, кто действует: изменение прав либо предшествует проверке, либо ждёт её.
5. **Кто кого меняет** (core.telegram.org/api/rights): админ с `add_admins` выдаёт не больше своих прав (`RIGHT_FORBIDDEN`) и меняет только назначенных им админов; создатель — любых; создателя не меняет никто (`USER_CREATOR`, в `editBanned` — `USER_ADMIN_INVALID`). Сам создатель меняет у себя только анонимность и звание. Повышение снимает ограничение; ограничение или исключение админа снимает его права.
6. **Исключённый** выходит из счёта участников; в супергруппе — служебное сообщение `messageActionChatDeleteUser`; его ящик удаляет диалог и получает `updateChannel` с `channelForbidden` событием `inbox.channelKickedToInbox` (как удаление канала, задача 055). Исключить можно и того, кто не в канале. Снятие исключения (`banned_rights` 0) делает его «вышедшим»: он может вступить снова.
7. **Передача владения** — одна логика для `channels.editCreator` (Android) и `messages.editChatCreator` (iOS, tdesktop): сначала пароль 2FA (клиенты проверяют им наличие пароля пустым `inputCheckPasswordEmpty`, iOS — даже с `inputPeerEmpty`, `ChannelOwnershipTransfer.swift:36-41`; Android `ChatRightsEditActivity.java:1116-1148`), затем права. Бывший создатель становится админом со всеми правами, назначенным новым.
8. Остальные участники узнают об изменении по `updateChannel` (загружают канал заново, ADR 0034, п. 3). `updateChannelParticipant` не рассылается: из клиентов его разбирает только Web K, и он строит его сам после `editAdmin`/`editBanned` (`appChatsManager.ts:865-892, 996-1010`).

## Последствия
- Все обработчики записи в канал читают права одной функцией; новое действие добавляется в `channelperm`, а не в обработчик.
- Счётчик админов включает создателя (как и раньше, с создания канала).
- Не сделано и не проверено: `PASSWORD_TOO_FRESH_X` и `SESSION_TOO_FRESH_X` (пароль и сессия моложе суток) — у сервиса 2FA нет дат смены пароля; лимит числа админов (`ADMINS_TOO_MUCH`) не задан; служебное сообщение при исключении и ответы Telegram в этих случаях не сверены с настоящим Telegram (пробой Web K).
