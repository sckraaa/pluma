# 0001. Официальные клиенты Telegram — спецификация и приёмочный тест

- Статус: accepted
- Дата: 2026-10-21

## Контекст
Цель — поведение «один в один» с Telegram. Свои клиенты писать не нужно: официальные клиенты открыты (GPL) и подключаются к своему серверу патчем адресов DC, RSA-ключа и api_id/api_hash. Прошлая попытка проекта провалилась на мобильных клиентах: долгие и хрупкие сборки, строгая обработка апдейтов, push.

## Решение
- Используем форки официальных клиентов: Telegram-iOS, Telegram-Android, Telegram Desktop, Telegram Web (K/A). Патчи минимальные и изолированные, чтобы регулярно подтягивать upstream.
- Мобильные клиенты — приёмочный критерий с первого дня. Фича готова, только когда работает в iOS, Android и Web.
- Воспроизводимый конвейер сборки клиентов строится до серверных фич.

## Последствия
- Сервер обязан следовать за layer клиентов (примерно ежемесячно). Обновление layer — рутинная задача с кодогенерацией, а не переделка.
- Обязательства GPL при распространении форков клиентов.
- Бренд «Telegram» использовать нельзя; bundle ID / application ID фиксируются один раз.

## Рассмотренные альтернативы
- Собственные клиенты — годы работы, хуже результат.
- Клиенты на TDLib (Telegram X и др.) — только часть платформ; TDLib всё равно используется в тестах (ADR 0002).
