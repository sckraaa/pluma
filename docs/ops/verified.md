# Отметка верификации

Отметку верификации (галочку рядом с именем, флаг `user.verified`) ставит и снимает администратор командой `pluma-admin user verify`. Из клиентов её не поставить: `account.updateVerified` (верификация от имени бота-верификатора) не поддержан.

## Развёртывание
Миграций и новых переменных нет: столбец `users.verified` есть в схеме с самого начала. Служебный аккаунт «Pluma» (777000) отмечен уже при создании базы (`z_init.sql`).

## Команда
Команда обращается к сервису biz, поэтому её запускают в контейнере `bff`, как `service-photo`:

```bash
docker compose -f docker-compose.yaml -f docker-compose.public-ip.yaml exec bff ./pluma-admin -f ../etc2/bff.yaml user verify @support on
```

- `user verify <@имя|id> on` — ставит отметку, `off` — снимает.
- Аккаунт задаётся именем пользователя (с `@` или без, регистр не важен; подходит любое из его имён) или числовым id. Удалённые аккаунты не находятся. Номер телефона команда не принимает и не печатает.
- Ответ называет аккаунт: `user 136817688 (@support, Pluma Support) is verified now; …`. Если отметка уже стоит (или уже снята), команда так и пишет и ничего не меняет.
- Неизвестный аккаунт — ошибка `no account <имя|id>`, код выхода 1.

## Что видят клиенты
biz меняет флаг и в той же транзакции отправляет `updateUser` всем устройствам аккаунта и тем, у кого аккаунт в контактах или есть личный диалог с ним (ADR 0020, ADR 0021). Вместе с обновлением приходит сам аккаунт с новым флагом, а кэш пользователей biz сбрасывается, поэтому `users.getUsers` и `users.getFullUser` сразу отвечают с отметкой.

- Android берёт пользователя из обновления (`MessagesController`, обработка `TL_updateUser`).
- Desktop по `updateUser` заново запрашивает полный профиль, если уже его загружал (`api_updates.cpp`, `case mtpc_updateUser`).
- Остальные увидят отметку при следующей загрузке аккаунта (открытие чата или профиля, перезапуск).

Цвет и вид галочки рисует клиент.
