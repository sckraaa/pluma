# Боты

Боты — обычные аккаунты MTProto (ADR 0043). Создаёт и настраивает их администратор через `pluma-admin`, клиенты и библиотеки (Telethon, TDLib, Pyrogram) входят токеном через `auth.importBotAuthorization`. Отдельного сервера Bot API нет. Платформа ботов (ADR 0068, задача 106): вход на сайты кнопкой и через `oauth.pluma.chat`, мини-приложения, меню вложений, игры, виджеты в сообщениях. Всё это настраивает только администратор: из клиента настроек нет, как нет таких методов в API Telegram.

## Развёртывание
- Миграции `migrate-20261109-bots-core.sql` и `migrate-20261121-bot-platform.sql` применяются службой миграций, повторный запуск безопасен.
- Порядок выката (секреты, DNS `oauth.pluma.chat`, пересоздание `web`, токены) — `deployment.md`, «Платформа ботов». Замена ключей — `security-setup.md`, §6.
- Переменные в `.env` (контейнеры `bff`, где работает и `pluma-admin`, и `links`):
  - `BOT_SECRET_ENCRYPTION_KEY` — `openssl rand -hex 32`. Ключ AES-256-GCM, под которым лежат ключи ботов, выведенные из их токенов (`bot_secret_keys`). Без него мини-приложения и вход через ботов выключены: приложения отвечают `BOT_WEBVIEW_DISABLED`, кнопка входа открывает адрес без входа. Потеря ключа: всем ботам — новый токен (`bot token`) или повторный вход токеном.
  - `WEBAPP_SIGNING_KEY` — `openssl rand -hex 32`, seed Ed25519 подписи `initData` мини-приложений (поле `signature`). Без него приложения не открываются. Открытый ключ печатает `bot webapp-key`.
- Сессия (задача 108) читает у `biz`, бот ли пользователь ключа (`BizServiceClient` в `session.yaml`, `teamgramd/etc` и `teamgramd/etc2`, внутри образа), и отмечает запросы ботов. Действий оператора не нужно, кроме выката нового образа `session`. Если `biz` недоступен, запрос с ключа отвечает `INTERNAL_SERVER_ERROR` (клиент повторяет), а не выполняется как запрос человека.
- **Шаг выката платформы.** Ключи бота выводятся из токена только при выдаче токена и при входе бота токеном. Бот, который уже работает с сохранённой сессией, может не войти заново, и тогда его приложения и кнопка входа не работают. Поэтому после выката каждому работающему боту выдаётся новый токен: `bot token <имя_bot>`, и токен передаётся тому, кто запускает бота. Список ботов — `bot list`; встроенным `@gif` и `@pic` токен не нужен. `bot token` сразу завершает сессии бота со старым токеном, поэтому бот перезапускают с новым сразу после выдачи. Бот без ключей отвечает на открытие приложения `BOT_WEBVIEW_DISABLED`, а его кнопка «Войти» открывает адрес без входа.

## Как запускать
```
docker compose exec bff ./pluma-admin -f ../etc2/bff.yaml bot <команда>
```
Картинки и значки команда читает из файловой системы контейнера; сначала скопируйте их туда:
```
docker compose cp ./shop.png bff:/tmp/shop.png
```
Команды `app`, `attach`, `game` загружают файлы через `dfs` и `media`, как клиент, и меняют флаги бота через `biz`, поэтому работают только в контейнере `bff`. Встроенных инлайн-ботов (`@gif`, `@pic`, ADR 0062) ни одна команда, кроме `list`, не трогает и не показывает: ответ `built-in bot, managed by the server`.

## Учётная запись бота
- `bot create <имя_bot> <название> [-owner <телефон>]` — создаёт бота и один раз печатает токен. Имя: 5–32 символа, латиница, цифры, `_`, начинается с буквы, заканчивается на `bot`. Владелец (`-owner`) сможет менять имя и описание бота из клиента.
- `bot token <имя_bot>` — выдаёт новый токен: старый перестаёт работать сразу, уже вошедшие сессии бота завершаются, ключи бота для приложений и входа записываются заново. Если команда сообщила, что сессии не завершены, запустите её ещё раз и используйте токен из последнего запуска.
- `bot list` — список ботов, без токенов.
- `bot set <имя_bot> [-privacy on|off] [-groups on|off] [-inline <подсказка>] [-inline-geo on|off] [-domain <домен>|off] [-main-app <адрес>|off] [-business on|off]`:
  - `-privacy off` — бот читает все сообщения групп (по умолчанию только команды, ответы ему и служебные сообщения; бот-админ видит всё);
  - `-groups off` — бота нельзя добавить в группы;
  - `-inline "Поиск..."` включает инлайн-режим, `-inline " "` (пробел) выключает;
  - `-domain shop.example.com` — сайт, на который бот входит кнопкой «Войти» (`keyboardButtonUrlAuth`). Адрес кнопки должен быть ровно на этом хосте, без поддоменов. Домен принадлежит одному боту; домены всех ботов попадают в `url_auth_domains` конфигурации приложения (ссылки на них клиенты открывают со входом). `off` отвязывает;
  - `-main-app https://…` — главное мини-приложение: кнопка «Открыть приложение» в профиле бота и ссылка `https://pluma.chat/<имя_bot>?startapp`. `off` убирает.
  - `-business on` — бизнес-режим (`user.bot_business`): бота можно подключить в «Настройки → Telegram Business → Чат-боты» (только такого бота клиенты предлагают). `off` выключает режим и отключает бота у всех аккаунтов, где он подключён; если команда сообщила, что бот ещё подключён у части аккаунтов, запустите её ещё раз.

Токен — секрет: в базе лежит только его хэш, показать его ещё раз нельзя. Передавайте его тому, кто запускает бота, надёжным каналом.

## Встроенные инлайн-боты `@gif` и `@pic`
- За `@gif` (id 1000101) и `@pic` (id 1000102) отвечает сам сервер (ADR 0062, `docs/ops/inline-bots.md`). Токена и процесса бота нет.
- Их учётные записи заводит `teamgramd/deploy/sql/z_pluma-inline-bots.sql`: имя, плейсхолдер `🔍`, без групп и без запроса геопозиции. При старте и потом раз в 10 минут bff сверяет их с реестром `pkg/inlinebots`.
- `pluma-admin bot` их не меняет:
  - `token`, `set`, `app`, `attach`, `game`, `login` отвечают `built-in bot, managed by the server`;
  - `bot list` их показывает.

  Расхождение с реестром исправляется в базе: недостающие строки — повторным запуском того же SQL-файла, изменённые руками — возвратом значений из него (`docs/ops/inline-bots.md`, «Если имя бота занято»), а не командами бота.
- Описания ботов клиенты получают на своём языке из `pkg/langpack/inlinebots.json` (37 языков). Имена `GIF Search` и `Image Search` (`z_pluma-inline-names.sql`) не переводятся. Фото ботам ставит `pluma-admin inline-bots photos` (`docs/ops/inline-bots.md`, «Имена и фото»).

## Прямые мини-приложения
Открываются ссылкой `https://pluma.chat/<имя_bot>/<короткое_имя>` (у Telegram — `t.me/<бот>/<приложение>`).
- `bot app list <имя_bot>` — главное приложение и прямые приложения со ссылками.
- `bot app add <имя_bot> <короткое_имя> -title <название> -url <https-адрес> -photo <jpg|png> [-description <текст>] [-animation <mp4>] [-write-access on|off]`.
- `bot app edit <имя_bot> <короткое_имя> [те же флаги]` — меняет только названные поля; `-animation off` убирает анимацию. Версия приложения растёт, клиенты перечитывают его.
- `bot app rm <имя_bot> <короткое_имя>` — убирает приложение; ссылка на него больше не открывается (`BOT_APP_INVALID`). Повторный `add` с тем же именем возвращает его с теми же id.

Короткое имя: 1–64 символа, латиница, цифры, `_`. Название — 1–64 символа, описание — до 512. Адрес — только `https://`, до 1024 символов. Картинка обязательна (у Telegram `botApp.photo` не опционально): JPEG или PNG до 10 МиБ. Анимация — MP4 до 10 МиБ, показывается вместо картинки. `-write-access on` — при первом запуске клиент спрашивает разрешение боту писать пользователю.

## Меню вложений
У Telegram меню вложений дают отдельным ботам; у нас его включает администратор. Пользователь добавляет бота ссылкой `https://pluma.chat/<имя_bot>?startattach` или из профиля бота.
- `bot attach show <имя_bot>` — запись меню бота.
- `bot attach set <имя_bot> [флаги]` — создаёт или меняет запись; при изменении меняется только названное. Для новой записи нужны `-name` и `-url`.
  - `-name <имя>` — подпись в меню: 1–64 символа, латиница, цифры, `_`;
  - `-url <https-адрес>` — приложение, которое открывает пункт меню;
  - `-attach-menu on|off` — пункт в меню скрепки (у новой записи — `on`); `-side-menu on|off` — пункт в боковом меню (у новой — `off`); хотя бы одно из двух;
  - `-peers all` или список из `same_bot,bot,pm,chat,broadcast` — в каких чатах предлагать (чат с этим ботом, с другими ботами, личные, группы, каналы); у новой записи — `all`;
  - `-write-access on|off` — при добавлении спросить разрешение боту писать пользователю; `-settings on|off` — у приложения есть кнопка настроек;
  - `-icon <значок>=<файл>` — значок, можно несколько раз; `-no-icon <значок>` убирает;
  - `-color <значок>:<цвет>=#rrggbb` — цвет значка (Android), `=off` убирает.
- `bot attach rm <имя_bot>` — убирает запись и бота из меню всех, кто его добавил.

Значки (имена — те, что читают клиенты). `*_static` — SVG, `*_animated` — TGS (Lottie, сжатый gzip), каждый файл до 64 КиБ:

| значок | кто рисует |
|---|---|
| `default_static` | все клиенты; обязателен для меню скрепки (Desktop берёт только его) |
| `placeholder_static` | Android и iOS — заставка, пока приложение загружается |
| `ios_static`, `ios_animated`, `ios_side_menu_static` | iOS |
| `macos_animated`, `macos_side_menu_static` | имена из кода iOS (общий код клиентов Apple) |
| `android_animated`, `android_active_animated`, `android_side_menu_static` | Android |

Цвета значка (Android): `light_icon`, `light_text`, `dark_icon`, `dark_text`.

Пользователи, уже добавившие бота, видят изменения записи, когда их клиент перечитывает меню: iOS и Web — при запуске, Android — при следующем запросе списка (`hash` списка меняется вместе с записью). Изменение записи администратором клиентам не рассылается (`updateAttachMenuBots` уходит только при добавлении и удалении бота самим пользователем); `bot attach rm` убирает бота у всех сразу на сервере, а клиенты увидят это при следующем чтении меню.

## Игры
Бот отправляет игру `messages.sendMedia(inputMediaGame(inputGameShortName))`; адрес игры бот даёт ответом на нажатие кнопки «Играть». Поделиться игрой — ссылка `https://pluma.chat/<имя_bot>?game=<короткое_имя>`.
- `bot game list <имя_bot>`.
- `bot game add <имя_bot> <короткое_имя> -title <название> -photo <jpg|png> [-description <текст>] [-animation <mp4>]`.
- `bot game edit <имя_bot> <короткое_имя> [те же флаги]` — `-animation off` убирает анимацию.
- `bot game rm <имя_bot> <короткое_имя>` — игру больше нельзя отправить; уже отправленные сообщения и таблица рекордов остаются, повторный `add` возвращает игру с теми же id.

Пределы — как у приложений: название 1–64, описание до 512, картинка обязательна.

Удаление аккаунта удаляет его строки платформы ботов: входы на сайты (`web_authorizations`), разрешения ботам писать (`bot_write_allowed`), запуски мини-приложений, установленные меню вложений и подготовленные для него сообщения (`bot_prepared`). Рекорды игр (`game_scores`) остаются: это строки таблицы рекордов чата, которую видят другие игроки, как и сообщения удалённого аккаунта в общих чатах.

## Вход на сайты (`oauth.pluma.chat`)
Сайт входит через Pluma по OpenID Connect, как через Telegram: `client_id` — id бота, `client_secret` — секрет, который печатается один раз.
- `bot login set <имя_bot> -redirect <https-адрес> [-redirect …] [-origin https://хост[:порт] …]` — создаёт клиента или заменяет его вместе с секретом (старый секрет перестаёт работать). Секрет печатается один раз, в базе — только его хэш; передайте его владельцу сайта надёжным каналом.
- `bot login edit <имя_bot> [-redirect …] [-origin …|off]` — меняет адреса, секрет прежний; названный список заменяется целиком, `-origin off` очищает.
- `bot login show <имя_bot>` — домен кнопки входа и адреса клиента (без секрета).
- `bot login rm <имя_bot>` — удаляет клиента: сайт больше не может входить.

`-redirect` — точный адрес возврата (`redirect_uri`), `https://`, без `#`; от 1 до 16 адресов. `-origin` — origin страниц сайта, которые запускают вход из приложения (`in_app_origin`), в нижнем регистре, без пути; до 16.

**Развёртывание провайдера.** Запись DNS `oauth.pluma.chat` (или имени из `PLUMA_OAUTH_DOMAIN`) указывает туда же, куда `pluma.chat`; Caddy получает для неё сертификат сам. Ключи ID-токенов — файл `OAUTH_SIGNING_KEY_FILE` (по умолчанию `./secrets/oauth_signing_key.pem`), который compose монтирует в `links` как secret: файл обязан существовать, иначе стек не поднимется. Создать ключ: `(umask 077 && openssl genpkey -algorithm RSA -pkeyopt rsa_keygen_bits:2048 -out secrets/oauth_signing_key.pem)`; пустой файл (`install -m 600 /dev/null secrets/oauth_signing_key.pem`) выключает провайдер. Сервису `links` нужен и `BOT_SECRET_ENCRYPTION_KEY` (старый формат входа проверяет ключи ботов).

**Замена ключа ID-токенов.** В файле может быть несколько блоков PEM: подписывает первый, в `/.well-known/jwks.json` публикуются все. Новый ключ дописать в файл вторым и перезапустить `links` — сайты успевают получить его из JWKS; через сутки поставить его первым (перезапуск), ещё через сутки удалить старый (перезапуск): токены, подписанные старым ключом, к тому времени уже проверены.

## Ключ подписи мини-приложений
`bot webapp-key` печатает открытый ключ Ed25519 (hex), которым сторонние сервисы проверяют поле `signature` в `initData` (у Telegram — свои опубликованные ключи; нашим подписям нужен наш). Проверка `hash` токеном бота работает без изменений. Ключ отдают разработчикам ботов вместе с этим документом.

**Замена `WEBAPP_SIGNING_KEY`:** новый seed в `.env`, перезапуск `bff`, новый открытый ключ (`bot webapp-key`) — разработчикам. Подписи уже открытых приложений перестают проверяться по новому ключу: приложения нужно открыть заново.

## Виджеты в сообщениях
Настройки администратора не нужны: виджет отправляет сам бот (`inputMediaWidget` в `messages.sendMedia` или инлайн-результатом `inputBotInlineMessageWidget`). Документации Telegram нет; поведение и пределы взяты из кода клиентов (Android `jni/twidget/widget-sandbox/docs/tgw-format.md`, tdesktop `tgw/`), ADR 0068 п. 8.
- Куда: личка бота с пользователем, базовые группы и супергруппы, где бот участник; в каналы — нет. Пользователь отправляет виджет только инлайн-результатом бота.
- Пределы: HTML до 32 КиБ, после сжатия до 4 КиБ; стороны до 4096; общее и чатовое состояние — до 1024 байт текста; запрос виджета — 1–64 байта, ответ бота — до 1024 байт.
- Общий виджет (`shared_widget`) живёт отдельно от сообщений: `messages.editWidgetData` меняет его состояние не чаще раза в секунду, клиенты опрашивают его с периодом 5–3600 с (по умолчанию 30).
- Запрос виджета к боту ждёт ответа до 15 с; от одного пользователя одному боту — не больше 5 запросов за 5 с. Запросы кошелька (TON) не обслуживаются: `WIDGET_QUERY_TYPE_UNSUPPORTED`.

## Для разработчиков ботов
Боты работают по MTProto (Telethon, Pyrogram, TDLib), HTTP Bot API нет. Методы и обновления — как у Telegram; отличия:
- **`initData`.** Проверка `hash` токеном бота — как в core.telegram.org/bots/webapps, без изменений. Поле `signature` подписано ключом Pluma, а не Telegram: открытый ключ даёт администратор (`bot webapp-key`).
- **Данные кнопки «Войти» и старого виджета входа** проверяются как у Telegram: `hash = hex(HMAC_SHA256(строка_проверки, SHA256(токен)))`.
- **Вход на сайт по OpenID Connect** — провайдер `https://oauth.pluma.chat` (`/.well-known/openid-configuration`); `client_id` — id бота, секрет выдаёт администратор (`bot login set`). Refresh-токенов и UserInfo нет.
- **Сроки и пределы сервера:**

| что | значение |
|---|---|
| запрос мини-приложения (`query_id`) | 180 с от последнего `prolongWebView`, затем `QUERY_ID_INVALID` |
| `start_param` | до 512 символов `[A-Za-z0-9_-]` |
| `theme_params` | JSON до 4096 байт |
| адрес приложения | только `https://`, до 1024 символов |
| `sendWebViewData` | до 4096 байт (`DATA_TOO_LONG`); только из приложения клавиатурной кнопки бота в личке с ним |
| подготовленное сообщение или кнопка | 24 ч, не больше 100 живых на пару бот — пользователь |
| запрос входа через `oauth.pluma.chat` | 5 мин; после 3 неверных эмодзи запрос сгорает |
| код авторизации OIDC / ID-токен | 60 с, одноразовый / 10 мин |
| счёт игры | целое ≥ 0; без `force` только больше прежнего (`BOT_SCORE_NOT_MODIFIED`) |

- **Не поддерживается** (ADR 0068, «Что не делается»): платежи и звёзды в приложениях, TON и кошелёк, подарки, боты-стражи вступления (`requestChatJoinWebView`), `bots.invokeWebViewCustomMethod`, статус-эмодзи от бота, медиа превью бота, создание ботов из клиента. Такие методы отвечают `ERR_ENTERPRISE_IS_BLOCKED`.
- **Без ключей бота** (бот не входил токеном после выката платформы) мини-приложения отвечают `BOT_WEBVIEW_DISABLED`, кнопка «Войти» открывает адрес без входа. Лечится повторным входом токеном или новым токеном.
