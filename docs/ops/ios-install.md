# Установка iOS-приложения с сайта (Ad Hoc)

Сервис `iosinstall` (задача 029) ставит Pluma на iPhone прямо с pluma.chat, без App Store и без Mac. Человек проходит путь на сайте:
1. скачивает профиль;
2. ставит его в «Настройках», и айфон сообщает свой UDID;
3. сервис регистрирует айфон у Apple, перевыпускает ad hoc-профили и переподписывает сборку;
4. на странице появляется кнопка «Установить».

Для запуска нужен «Режим разработчика» (iOS 16+, проверено на iOS 26). Пуши работают. Apple даёт команде 100 айфонов в год.

## Как устроено
- **Адреса** — на именах сайта (`PLUMA_SITE_DOMAINS`), Caddy передаёт `/ios/adhoc/*` в контейнер `iosinstall:9098`:
  - `GET /ios/adhoc/profile` — профиль `Profile Service` с одноразовым challenge на 30 минут;
  - `POST /ios/adhoc/enroll` — ответ айфона. Подпись проверяется по цепочке до Apple Root CA, сертификат устройства выдан Apple iPhone Device CA. Затем переход на страницу `PUBLIC_URL/iphone/install#t=<токен>`;
  - `GET /ios/adhoc/status?t=` — `waiting`, `ready` (со ссылкой `itms-services`) или `refused`;
  - `GET /ios/adhoc/manifest?t=`, `GET /ios/adhoc/app.ipa?t=` — манифест и IPA, только по токену устройства;
  - `GET /ios/adhoc/manifest?u=`, `GET /ios/adhoc/app.ipa?u=` — те же манифест и IPA по билету обновления из приложения (раздел «Обновление из приложения»);
  - `POST /ios/adhoc/upload` — CI выкладывает новую сборку (заголовок `Authorization: Bearer <токен загрузки>`);
  - `GET /internal/update` — только внутри сети контейнеров (Caddy его не проксирует): какую сборку сервис сейчас отдаёт по билетам; его спрашивает `bff`.
- **Подпись.** CI pluma-ios после ad hoc-сборки отправляет:
  - подписанный IPA;
  - версию;
  - список бандлов с их bundle ID и правами (entitlements).

  Сервис переподписывает эту сборку. Порядок:
  1. новые айфоны регистрируются у Apple (`POST /v1/devices`);
  2. ad hoc-профиль каждого бандла удаляется и создаётся заново со всеми включёнными устройствами команды, под тем же именем;
  3. `rcodesign` 0.29.0 подписывает IPA сертификатом Apple Distribution.

  Все айфоны получают один и тот же IPA. Переподпись идёт по одной; при ошибке повторяется с паузой от 1 до 30 минут.
- **Хранение.** `state.json` в томе `iosinstall_data`: айфоны (UDID, модель, версия iOS, id у Apple, токен), текущая сборка и подписанный IPA. UDID — персональные данные: в логи не пишутся, в общие базы не попадают.
- **Ограничения.** Профиль — 5 раз в сутки с одного адреса (`LIMIT_ADDRESS_DAY`). Новых айфонов — 10 в сутки (`LIMIT_DEVICES_DAY`). Только iPhone, iPad не обслуживается.
- **Секреты** доступны только этому контейнеру. Это ключ App Store Connect (Admin), сертификат Apple Distribution с ключом и паролем, токен загрузки. Они лежат файлами в `/opt/pluma/iosinstall` (владелец uid 65532, режим 0400). В общем `.env` только несекретные значения:
  - `PLUMA_IOSINSTALL_IMAGE`;
  - `PLUMA_IOSINSTALL_URL`;
  - `PLUMA_ASC_KEY_ID`;
  - `PLUMA_ASC_ISSUER`;
  - `PLUMA_SIGN_CERTIFICATE_ID`.

  Кто захватит сервер, получит ключ подписи и Admin-ключ команды Apple — риск принят владельцем (вариант «а», бриф 029).

## Обновление из приложения
Установленная с сайта сборка обновляется, не выходя из приложения (задача 085, дополнение к ADR 0035 от 2026-11-11): кнопка «Обновить» на экране обновления сразу запускает системную установку, сайт открывать не нужно. Клиент для этого не менялся: он открывает ссылку из `help.appUpdate` как есть.
- **Как работает.**
  1. `bff` на `help.getAppUpdate` спрашивает у `iosinstall` (`GET http://iosinstall:9098/internal/update`, ответ хранится 30 секунд), какую сборку тот отдаёт.
  2. Если это текущий выпуск, приложение получает ссылку `itms-services://?action=download-manifest&url=<манифест>?u=<билет>`. Иначе — страницу `<сайт>/iphone/install`, как раньше.
  3. iOS качает манифест и IPA по билету.
- **Билет** — подпись HMAC-SHA256 общим секретом `PLUMA_IOS_UPDATE_SECRET` над номером сборки, днём выпуска (UTC) и хешем ключа сессии. UDID и токенов устройств `bff` не знает, поэтому билет не привязан к айфону.
  - Одинаков для сессии и сборки в течение суток UTC: приложение показывает экран обновления заново при любом изменении ответа, и после «Пропустить» экран не возвращается до смены суток (03:00 по Москве).
  - Действует в день выпуска и на следующий, то есть от 24 до 48 часов.
  - Слабее токена устройства: кто получил чужой билет, может до двух суток скачать IPA. Поставить его всё равно можно только на зарегистрированный айфон. Владелец принял это 2026-11-11.
- **Когда билет не принимается** (ответ 404, как на неизвестный токен):
  - сборка ещё не переподписана (после загрузки из CI — около минуты);
  - билет от другой сборки, просрочен или подписан другим секретом;
  - сборка не текущий выпуск: выпуск отозван (`releases.md`) или записи о нём ещё нет. Текущий выпуск `iosinstall` читает у сервиса `releases` (`http://releases:9097/dl/releases.json`, ответ хранится 30 секунд). Пока тот не отвечает, пять минут действует его последний ответ; дольше — билеты не принимаются, а `GET /internal/update` отвечает 503;
  - секрет не задан.

  Во всех этих случаях `bff` ссылку из приложения не предлагает и отдаёт страницу сайта. Токены устройств со страницы работают как прежде и от сервиса `releases` не зависят.
- **Журнал.** На каждую выдачу манифеста по билету — строка `an update from the app for <адрес>, session <хеш>`. Сам билет в журнал не пишется. Один хеш сессии с многих адресов — признак утёкшего билета; сменить секрет — значит отозвать все выданные билеты.
- **Включить.**
  1. В `.env` сервера: `PLUMA_IOS_UPDATE_SECRET` (`openssl rand -hex 32`, не короче 32 символов). Нужны оба сервиса, `iosinstall` и `releases`.
  2. Пересоздать `bff` и `iosinstall` (`up -d --no-build bff iosinstall`), образ `iosinstall` — этого коммита или новее.
  3. Проверка: `docker compose … exec bff bash -c 'exec 3<>/dev/tcp/iosinstall/9098 && printf "GET /internal/update HTTP/1.0\r\n\r\n" >&3 && cat <&3'` — в ответе `{"build":<номер текущей сборки>,"manifest":"https://…/ios/adhoc/manifest"}`. `{"build":0}` — билеты сейчас не принимаются (причины выше); `503` — `iosinstall` не может узнать текущий выпуск у сервиса `releases`.
- **Выключить** — очистить `PLUMA_IOS_UPDATE_SECRET` и пересоздать `bff` и `iosinstall`. Приложение снова получает страницу сайта, выданные билеты перестают действовать. Так же поступить, если на iOS 26 установка из приложения зависает на «Ожидание…» (открытый риск, дополнение к ADR 0035): тогда основным способом остаётся сайт.
- **При включении и выключении** экран обновления один раз покажется снова тем, кто нажал «Пропустить»: ссылка в ответе изменилась. То же — в минуту между загрузкой сборки и концом её переподписи.

## Первое включение
1. **Секреты** кладёт владелец со своей машины. Скрипт ничего не печатает и не передаёт в командной строке:
   ```bash
   teamgramd/deploy/iosinstall/put-secrets.sh neo_old ~/pluma-secrets/desktop/AuthKey_4FQM72H54Q.p8 \
     ~/pluma-secrets/ios/pluma-distribution.p12 ~/pluma-secrets/ios/pluma-distribution.p12.password
   ```
   Он создаёт на сервере токен загрузки и записывает его секретом `IOSINSTALL_UPLOAD_TOKEN` окружения `release` в pluma-ios (нужен `gh` с правом на этот репозиторий).
2. **`.env` сервера:** `PLUMA_IOSINSTALL_IMAGE=ghcr.io/sckraaa/pluma-iosinstall:<коммит>`, `PLUMA_IOSINSTALL_URL=https://pluma.chat`, `PLUMA_ASC_KEY_ID`, `PLUMA_ASC_ISSUER`, `PLUMA_SIGN_CERTIFICATE_ID` (id сертификата Apple Distribution у Apple: `GET /v1/certificates?filter[certificateType]=DISTRIBUTION`).
3. **Запуск** — в команду сервисов добавляется `-f docker-compose.iosinstall.yaml` после `docker-compose.web.yaml`. Если в выкатке изменился Caddyfile (в нём маршрут `/ios/adhoc/*`), контейнер `web` пересоздаётся: `docker compose … up -d --no-build --force-recreate --no-deps web`. Файл смонтирован в контейнер по одному; `git checkout` заменяет его новым файлом, и `caddy reload` читает прежний. Пересоздание — несколько секунд простоя сайта и веб-клиента.
4. **Первая сборка** — запуск workflow pluma-ios с `ipa`. CI отправляет IPA сервису, через минуту `docker compose … logs iosinstall` пишет `build … uploaded` и `signed for N devices`.

## Проверка
- `curl -sI https://pluma.chat/ios/adhoc/profile` — `200`, `application/x-apple-aspen-config`.
- `docker compose … exec iosinstall /iosinstall healthcheck; echo $?` — `0`.
- На айфоне: страница pluma.chat/iphone/install → профиль → «Настройки» → «Профиль загружен» → «Установить» → Safari возвращается на страницу → «Установить Pluma».

## Отказ и откат
- Apple отказала в регистрации айфона (неверный UDID, исчерпан лимит в 100) — у айфона статус `refused`, причина в `state.json` (поле `failure`), в логе только код HTTP.
- Ошибка подписи или API — в логе `signing failed, again in …`. Айфоны ждут, прежний IPA продолжает раздаваться.
- Выключить — убрать `-f docker-compose.iosinstall.yaml` из команды и `docker compose … rm -sf iosinstall`. Маршрут Caddy тогда отвечает 502, остальной сайт не затронут.
