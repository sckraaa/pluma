# 05.11.2026: сервер Pluma пропал из сети

Сервер `ubuntu-8gb-nbg1-1` (Hetzner CX33, 159.69.215.232, Floating IP 195.201.252.126). Общий: на нём туннель НАВИгатора (sshd, nginx на `127.0.0.1:8081/8082`).

## Итог

Память здесь ни при чём. Сервер перестал отвечать, потому что 05.11 в 18:48:34 UTC ядро сняло с `eth0` основной адрес вместе с маршрутом по умолчанию: истекла аренда DHCP. Её некому было продлить: в 06:20 systemd-networkd после перезапуска не смог прочитать свой файл настроек и отпустил `eth0`. Файл стал нечитаемым 29.10, когда при настройке Floating IP на работающем сервере запустили `netplan generate` под `umask 077`. Это ошибка Pluma.

## Почему не память

Описание «dfs 7 ГБ, OOM каждые 40–50 секунд» совпадает с тремя записями ядра от **02.11** 20:31 (anon-rss 6,8–6,97 ГБ, total-vm 12–14 ГБ). Записей OOM за 05.11 нет ни в `kern.log`, ни в журнале. По sysstat за 05.11 занято около 3,6 ГБ из 7,6 весь день, включая минуты до перезагрузки.

## Что сделано

- Причина рекомендации в runbook убрана: `docs/ops/deployment.md` теперь проверяет netplan только во временном каталоге (`--root-dir`) и объясняет, чем опасен `netplan generate` на работающем сервере.
- Память (задача 056, `docs/ops/memory.md`): у каждого контейнера свой лимит без подкачки, Go-сервисы держат кучу в 80% от него, на общем сервере все контейнеры Pluma в `pluma.slice` с потолком 4,5 ГБ, sshd и nginx с `OOMScoreAdjust=-900`.
- dfs, рост 02.11: части неизвестного размера по 16 МБ вместо 528 МБ (`393af58d6`), импорт каталога не больше 8 документов разом (`ac2e68b2c`). Другие пути, где один запрос может занять гигабайты, найдены разбором кода и вынесены в отдельную задачу.

## Что осталось

- Проверка, которая заметила бы такое за 12 часов до отказа. networkd без `eth0` и пустой список DNS видны сразу (`networkctl status eth0` не `configured`). Такая проверка в деплое или алерт не сделаны.
- Пинги `hc-ping.com` не проходили с 06:20 (`docs/ops/monitoring.md`, сторожевой сигнал). Пришло ли владельцу оповещение — не проверено.
- SSH сервера принимает вход root по паролю (`PasswordAuthentication yes` из cloud-init), идёт постоянный перебор паролей. Решение за владельцем: туннель НАВИгатора входит по ключу.
