# Перенос группы из Telegram

`pluma-admin import-chat` переносит группу из Telegram в Pluma (задача 083, ADR 0051): выгрузка Telegram Desktop становится новой закрытой супергруппой. Сообщения — от уже существующих аккаунтов Pluma тех же людей, с исходными датами. После переноса у всех участников история прочитана, голосовые и кружки прослушаны.

Что переносится и что нет — в `docs/tasks/083-telegram-group-import.md`. Коротко о потерях: в выгрузке нет сведений, кто что прочитал, поэтому прочитано у всех; реакции переносятся только те, у которых выгрузка называет автора; альбомы приходят отдельными сообщениями; закреп, админы, темы форума и превью ссылок не переносятся.

## Развёртывание
Миграция `migrate-20261114-channel-imports.sql` (таблицы `channel_imports`, `channel_import_messages`, `channel_import_media`, столбец `channels.imported_max_id`) применяется службой миграций; повторный запуск безопасен. Новых переменных нет. Команда работает после обновления образа сервисов: ей нужны новые RPC сервиса `biz`.

## 1. Выгрузить группу
В официальном Telegram Desktop: группа → «⋮» → **Export chat history**.
- Отметить всё: Photos, Videos, Voice messages, Video messages, Stickers, GIFs, Files.
- **Size limit** — до конца вправо (4000 МБ). По умолчанию там 8 МБ и только фото: с такими настройками видео и файлы в выгрузку не попадут.
- Формат — **Machine-readable JSON**. Даты не ограничивать.
- Выгружает участник, который видит всю историю. Telegram может попросить подтвердить выгрузку с другого устройства и подождать сутки.

Получится папка `ChatExport_<дата>` с `result.json` и подпапками файлов.

## 2. Положить папку на сервер
```
rsync -a --partial ChatExport_<дата>/ <сервер>:/srv/pluma-import/<имя>/
```
Имена файлов и папок не менять.

## 3. Команды
Команда запускается разовым контейнером сервиса `bff` с папкой выгрузки внутри (ниже `DC` — `docker compose` с файлами стенда, как в `docs/ops/deployment.md`):
```
DC run --rm --no-deps -v /srv/pluma-import/<имя>:/import bff ./pluma-admin -f=../etc2/bff.yaml import-chat <подкоманда> -dir /import ...
```

| Подкоманда | Что делает |
|---|---|
| `accounts` | Список аккаунтов Pluma: id и имя. |
| `map -dir /import` | Пишет `/import/mapping.json`: все, кто встречается в выгрузке, и кандидат из Pluma, если имя совпало ровно с одним аккаунтом. Повторный запуск сохраняет уже заполненное. |
| `plan -dir /import [-missing-media=skip]` | Что будет перенесено. Ничего не пишет. Код выхода не 0, пока перенос невозможен. |
| `run -dir /import -storage-dir <каталог> \| -free-bytes <байт> [-missing-media=skip] [-title <название>] [-batch 200] [-pause 20ms]` | Переносит. Повторный запуск продолжает с места остановки. |
| `status -dir /import` или `status <id>` | Состояние переноса и счётчики. |
| `abort <id>` | Отменяет незавершённый перенос и удаляет недоделанную группу. |

Файл соответствий по умолчанию — `mapping.json` в папке выгрузки; другой путь — `-mapping`. `map` пишет в папку выгрузки, поэтому для него папка монтируется на запись; для `plan` и `run` достаточно `:ro`.

## 4. Файл соответствий
```json
{
  "export_chat_id": 1234567890,
  "creator": 136817690,
  "exporter": 136817690,
  "authors": {
    "user111222333": {"names": ["Иван Петров"], "messages": 15234, "pluma": 136817690, "pluma_name": "Иван Петров", "suggested": true, "confirmed": false},
    "user444555666": {"names": ["Маша"], "messages": 8120, "pluma": null, "confirmed": false}
  },
  "service_names": {"Олег Сидоров": null},
  "extra_members": []
}
```
- `creator` — аккаунт Pluma, который станет создателем группы. Обязателен.
- `exporter` — аккаунт Pluma того, кто делал выгрузку. В выгрузке опросов есть только его собственный голос; с этим полем голос переносится. `0` — опросы без голосов.
- `authors` — каждой строке поставить `pluma` (id из `accounts`) и `"confirmed": true`. Автор обычных сообщений без подтверждённого аккаунта — ошибка: `plan` перечислит таких, `run` не начнёт. Строки, у которых `messages` равно 0 (человек только ставил реакции или упоминается в служебных сообщениях), заполнять не обязательно: его реакции и служебные сообщения просто не перенесутся.
- `"skip": true` вместо `pluma` — явно не переносить сообщения автора (например, бота).
- `service_names` — имена из служебных сообщений («добавил(а) Олега»), у которых в выгрузке нет id и которые не совпали ни с одним автором. Можно вписать id аккаунта Pluma; `null` — такое служебное сообщение не переносится.
- `extra_members` — аккаунты, которых нужно добавить в группу, хотя в выгрузке их нет.

Участниками станут создатель, все аккаунты из `authors`, `service_names` и `extra_members`.

После начала переноса менять аккаунт уже учтённого автора нельзя (`IMPORT_MAPPING_CHANGED`); добавлять новых можно.

## 5. План
`plan` печатает: число сообщений по видам; что не переносится и почему; число и размер файлов; файлы, которых нет в выгрузке; ответы без исходного сообщения; реакции — «по счётчикам», «с названным автором» и «будет перенесено»; число участников; число сообщений с датой правки (все они будут с отметкой «изменено», в том числе те, где Telegram её скрывал: выгрузка их не различает); авторов без аккаунта; таблицу «Authors» — каждый автор выгрузки и аккаунт Pluma, от имени которого пойдут его сообщения, с **настоящим именем этого аккаунта из базы**, и строку `NOTE`, если один аккаунт Pluma дан нескольким авторам. Таблицу нужно прочитать глазами перед `run`: после переноса авторство не исправить. Текст сообщений не печатается.

`pluma_name` в `mapping.json` — подсказка: `map` при каждом запуске переписывает его именем аккаунта, чей id стоит в `pluma`, так что после правки id руками повторный `map` покажет, кто это.

Причины «не переносится»:
- `author_skipped` — автор помечен `skip`;
- `service_not_imported` — служебное без соответствия в перенесённой группе (звонки, подарки, темы, переход из обычной группы в супергруппу);
- `service_unresolved` — служебное, чей автор или названный участник не сведён к аккаунту Pluma;
- `service_photo_missing` — смена фото группы, а файла фото в выгрузке нет;
- `media_not_imported` — игра, счёт, розыгрыш, платное медиа без текста;
- `media_missing` — файла нет, текста нет (только с `-missing-media=skip`);
- `unsupported` — запись, которую сама выгрузка не смогла описать;
- `invalid` — опрос или список дел, который Pluma не принимает;
- `empty` — пустое сообщение.

**Файлов нет в выгрузке.** Без `-missing-media=skip` это ошибка: лучше выгрузить заново с нужными настройками. С флагом сообщение с подписью переносится текстом, без подписи пропускается.

## 6. Перенос
```
DC run --rm --no-deps -v /srv/pluma-import/<имя>:/import:ro bff ./pluma-admin -f=../etc2/bff.yaml \
  import-chat run -dir /import -storage-dir /import
```
- **Место.** Перед загрузкой файлов команда сравнивает свободное место с нужным: размер файлов × 2,2 плюс 5 ГиБ. Файл занимает место дважды: `dfs` держит части загрузки около трёх часов после того, как файл уже в хранилище. `-storage-dir` — любой каталог на диске хранилища, видимый в контейнере (если выгрузка лежит на том же диске, что данные Docker, подойдёт сама папка выгрузки). Если такого каталога нет — `-free-bytes` с числом из `df -B1 --output=avail <диск хранилища>`. Без одного из двух флагов перенос с файлами не начнётся. Если места не хватит уже в пути, `dfs` откажет в приёме части, команда остановится; продолжить можно позже той же командой.
- **Пока идёт перенос**, группы ни у кого нет: уведомлений и событий клиентам нет.
- **Оборвалось** (сеть, перезапуск сервисов, выключение) — запустить ту же команду ещё раз. Она продолжит с первой незаписанной записи; уже загруженные файлы не загружаются повторно. Сбой между загрузкой файла и записью о нём оставляет в хранилище один лишний объект на сбой.
- **В конце** создатель становится участником, остальные добавляются обычным приглашением. Каждый получает группу в списке чатов и одно уведомление «добавил(а) вас»; непрочитанного нет. Настройки приватности «кто может добавлять меня в группы» при этом не проверяются.
- Нагрузка: одна транзакция на `-batch` записей (до 200), между ними `-pause`. Отправка сообщений в остальные чаты во время переноса работает как обычно.
- **Файл, который сервер не принял** (например, повреждённая картинка): команда останавливается и называет номер записи. Убрать этот файл из папки выгрузки и запустить с `-missing-media=skip` — сообщение перенесётся текстом или будет пропущено.
- Папку выгрузки после проверки в клиентах можно удалить.

## 7. Отмена
`abort <id>` работает только до завершения. Группа помечается удалённой; тот же чат можно переносить заново. Уже загруженные файлы остаются в хранилище и в таблице `channel_import_media`: повторный перенос того же чата их не загружает снова. Автоматической очистки файлов отменённого переноса нет.

Завершённый перенос не отменяется: группу удаляет её создатель в клиенте, как любую.

## 8. После переноса руками
Назначить админов, поставить фото группы, закрепить нужные сообщения — этого в выгрузке нет.

## Что в логах
Команда и сервисы пишут только номера, id, виды и счётчики. Текст сообщений, подписи, телефоны контактов в вывод и логи не попадают. Имена людей из выгрузки печатают только `map` и `plan` — на экран оператора и в файл соответствий.
