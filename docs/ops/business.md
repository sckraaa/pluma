# Telegram Business

Решение — ADR 0067, задача 105. Все функции Telegram Business открыты каждому пользователю (ADR 0041): часы работы, местоположение, своё вступление, ссылки на чат, быстрые ответы, приветствие и «нет на месте», подключённый бот. Отдельного сервиса нет:

| Что | Где |
|---|---|
| Методы `account.updateBusiness*`, `*BusinessChatLink*`, `*ConnectedBot*`, `messages.*QuickReply*` | bff, модуль `app/bff/business` (маршруты `RPCBusiness*` → `bff.bff` в `session.yaml`) |
| Поля `business_*` в профиле, панель бота над чатом | bff `users.getFullUser`, `messages.getPeerSettings` |
| Быстрые ответы | сервис msg, таблицы `quick_reply_*` |
| Решение «отправить автоответ» | inbox сервиса msg, в транзакции ящика владельца |
| Отправка автоответов | воркер `msg` (раз в секунду, `business_autoreply_worker.go`) |
| Обновления подключённому боту | inbox сервиса msg → очередь qts бота (`pkg/qtsqueue`) |
| Действия бота от имени владельца | сессия (`invokeWithBusinessConnection`) → bff, проверка `pkg/business` `Act` |
| Страница `https://pluma.chat/m/<slug>` | сервис `links` («Открыть в Pluma», `plm://message?slug=…`) |
| Бизнес-режим бота | `pluma-admin bot set <бот> -business on|off` (`docs/ops/bots.md`) |
| Алерт | группа `business`, `teamgramd/deploy/prometheus/server/rules/business.yml` |

Redis для Business не нужен: всё состояние в MySQL, после перезапуска любой службы работа продолжается с записанного.

## Что нужно при выкатке

1. **Сервер и клиенты вместе.** Строку «Telegram Business» в настройках показывают патчи клиентов задачи 105 (часть 9). Сервер без патчей ничего не ломает; патчи без сервера открыли бы экраны, которые отвечают ошибкой.
2. **Миграции** применяет сервис `migrate`, действий нет: `migrate-20261119-business.sql` (семь таблиц `business_*`), `migrate-20261119-quick-replies.sql` (`quick_reply_shortcuts`, `quick_reply_messages`), `migrate-20261119-qts-updates.sql` (`qts_updates`). После выката `pluma-admin migrate status` пишет `0 pending`.
3. **Часовые пояса.** Экран часов работы берёт список поясов из каталога (`help.getTimezonesList`, `docs/ops/catalog.md`). Перед выкаткой проверить, что запись есть, иначе выбор пояса в клиентах пуст:
   ```bash
   docker exec mysql sh -c 'MYSQL_PWD="$MYSQL_ROOT_PASSWORD" mysql -uroot teamgram -e "SELECT method, imported_at FROM catalog_answers WHERE method = \"help.getTimezonesList\""'
   ```
   Пустой ответ — импортировать каталог заново. Сами пояса сервер знает без системной базы образа (`time/tzdata` в бинарниках bff, msg и links, около 450 КБ).
4. **Конфиг приложения.** Пределы — ключи `quick_replies_limit`, `quick_reply_messages_limit`, `business_chat_links_limit`, `intro_title_length_limit`, `intro_description_length_limit` в `teamgramd/bin/app_config.json` (`docs/ops/app-config.md`, раздел «Telegram Business»). Клиенты заберут их сами.

Новых переменных окружения, сайдкаров и томов нет.

## Что хранится

| Таблица | Что | Сколько |
|---|---|---|
| `business_profiles` | часы, местоположение (адрес и точка), вступление | строка на пользователя |
| `business_auto_reply_settings` | приветствие и «нет на месте»: ярлык, получатели, расписание, `enabled_at` | до двух строк на пользователя |
| `business_auto_replies` | очередь автоответов к отправке | пусто, кроме секунд между сообщением и ответом |
| `business_auto_reply_log` | когда автоответ последний раз ушёл собеседнику (частота «нет на месте») | строка на пару владелец–собеседник |
| `business_chat_links` | ссылки на чат: slug, текст, сущности, заголовок, просмотры | до 100 на пользователя |
| `business_bot_connections` | подключённый бот: `connection_id`, права, получатели | строка на пользователя |
| `business_bot_paused_peers` | чаты, где бот на паузе | строка на чат |
| `quick_reply_shortcuts`, `quick_reply_messages` | ярлыки и их сообщения (JSON, как отложенные) | до 100 × 20 на пользователя |
| `qts_updates` | обновления бизнес-чатов для авторизаций ботов до подтверждения | см. ниже |

Диск: единицы МБ на весь сервер. Фото и видео быстрых ответов лежат в общем хранилище файлов, как вложения сообщений; удаление ярлыка файлов не удаляет.

## Автоответы

- Решение принимается, когда входящее личное сообщение ложится в ящик владельца; строка очереди уникальна по сообщению, повтор события её не удваивает. Воркер берёт строку арендой на 2 минуты и отправляет сообщения ярлыка от имени владельца обычной отправкой с пометкой `offline`. Несколько экземпляров msg не отправят одно и то же дважды; после перезапуска воркер продолжает с неотправленных строк.
- Не отправляется (`skipped`): настройка выключена, собеседник заблокировал владельца, приватность или ярлык не дают отправить.
- Временная ошибка — повтор после аренды; после 10 попыток строка удаляется (`failed`, в логе `given up after 10 attempts`).
- Правила, которых Telegram не публикует и которые выбраны в задаче 105 («Решения к подтверждению», п. 2–4): «новый» чат — начатый после первого включения автоответа; «нет на месте» уходит собеседнику не чаще раза в 24 часа и только если владелец написал ему после прошлого автоответа; «вне часов работы» без заданных часов не отправляется; ботам, служебным аккаунтам и в «Избранное» автоответы не уходят.
- «Только не в сети» смотрит на статус, который видят собеседники (`account.updateStatus`, ADR 0030): владелец не в сети больше 10 минут.

### Выключить автоответы пользователю

Обычно пользователь выключает их сам в клиенте. Если нужно с сервера (например, автоответы мешают собеседникам):

```bash
docker exec mysql sh -c 'MYSQL_PWD="$MYSQL_ROOT_PASSWORD" mysql -uroot teamgram -e "SELECT id FROM users WHERE phone = \"79991234567\""'
docker exec mysql sh -c 'MYSQL_PWD="$MYSQL_ROOT_PASSWORD" mysql -uroot teamgram -e "DELETE FROM business_auto_reply_settings WHERE user_id = <id>; DELETE FROM business_auto_replies WHERE user_id = <id>"'
```

Отправка прекращается сразу: воркер пропускает строку, если настройки уже нет. Клиенты пользователя увидят выключенные автоответы, когда перечитают свой профиль (вход на экран Business или перезапуск); обновления на устройства при правке базы не уходят. Одно приветствие — `AND kind = 1`, «нет на месте» — `AND kind = 2`.

## Подключённые боты

- Подключить можно только бота в бизнес-режиме: `pluma-admin bot set <бот> -business on`. `-business off` отключает бота у всех аккаунтов и сообщает ему об этом (`updateBotBusinessConnect` с `disabled`); если команда сказала, что бот ещё подключён у части аккаунтов, запустить её ещё раз.
- Обновления бизнес-чатов бот получает с `qts`, как в Telegram; бот вне сети догоняет их `updates.getDifference`. Неподтверждённые строки `qts_updates` живут 7 суток (`pkg/qtsqueue`, `Retention`): их, а также очередь вышедших авторизаций, удаляет периодическая чистка bff (та же, что у секретных чатов, `app/bff/secretchats/internal/core/sweeper.go`), так что забытый вход бота очередь не копит.
- Бот действует от имени владельца только методами из списка ADR 0067 (§ 6) и по выданным правам; права подарков, звёзд и историй сохраняются, но ничего не открывают.

## Ссылки на чат

Ссылка — `https://pluma.chat/m/<slug>` (хост — `TDotMe`, ADR 0036). Просмотр считается, когда ссылку открывает в клиенте не владелец; страница сайта просмотров не считает. Удалённая ссылка и ссылка удалённого аккаунта отвечают `CHATLINK_SLUG_EXPIRED`.

## Метрики и алерт

| Метрика | Служба | Что |
|---|---|---|
| `business_autoreply_total{kind, result}` | msg | автоответы: `kind` = `greeting`/`away`, `result` = `sent`/`skipped`/`failed` |
| `business_bot_updates_total{kind}` | msg (inbox) | обновления, поставленные в очередь подключённым ботам, по конструктору |
| `business_chatlink_resolve_total{result}` | bff | открытия ссылок на чат: `ok`, `empty`, `expired`, `error` |

| Алерт | Что значит | Что делать |
|---|---|---|
| `BusinessAutoReplyFailing` | больше 10 % автоответов за 15 минут брошены после 10 попыток: собеседники не получили приветствие или «нет на месте» | `docker compose logs --tail 200 msg` — строки `automatic reply N of user U, attempt K: <ошибка>`. Обычно MySQL или Kafka недоступны или перегружены: `docker compose ps`, `docker compose logs mysql kafka`. Брошенные автоответы не повторяются; после устранения причины новые уходят сами |

Тест `pkg/business` `TestAlertRules` держит выражения алерта на метриках и значениях меток, которые публикует код.

## Логи

В логи попадают только id пользователей, ярлыков, строк очереди и коды ошибок. Тексты сообщений, адреса, slug ссылок и `connection_id` в лог не пишутся (`tools/logaudit` ловит переменные и поля с именами `address`, `slug`, `connectionId`, `businessConnectionId`).

## Проверка после выката

1. `pluma-admin migrate status` — `0 pending`; в Prometheus → Alerts группа `business` с правилом `BusinessAutoReplyFailing` в состоянии «inactive», ошибок разбора правил нет.
2. В клиенте: Настройки → Telegram Business открывается без покупки и без переключателя рекламы; список часовых поясов на экране часов не пуст.
3. `https://pluma.chat/m/<slug>` своей ссылки в браузере — страница «Открыть в Pluma».
