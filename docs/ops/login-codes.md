# Коды входа через аккаунт Telegram

Необязательный сервис `codes` (задача 073, ADR 0044): настоящий аккаунт Telegram пишет код человеку на его номер. Без сервиса всё как раньше: код в приложении Pluma или у администратора.

## Что нужно от владельца
- Отдельный номер, не личный, с аккаунтом, заранее зарегистрированным в официальном приложении, и включённой двухэтапной аутентификацией. Telegram может завершать сессии сторонних клиентов без объяснений, особенно у свежих аккаунтов (задача 007).
- Приложение на my.telegram.org: `TELEGRAM_API_ID` и `TELEGRAM_API_HASH` в `.env` (те же, что у бота каталога).

## Развёртывание
1. Образ: CI собирает `pluma-codes` (`.github/workflows/images.yml`); сборка TDLib долгая и требует нескольких гигабайт памяти (на сервере собирать не нужно). В `.env`: `PLUMA_CODES_IMAGE=ghcr.io/sckraaa/pluma-codes:<коммит>`.
2. В `.env`, значения — `openssl rand -hex 32`:

   ```
   LOGIN_CODES_SENDER_TOKEN=<токен внутреннего API>
   LOGIN_CODES_DB_KEY=<ключ базы TDLib>
   ```

   Адрес пока оставить пустым: `LOGIN_CODES_SENDER_URL=`.
3. Применить миграцию: `teamgramd/deploy/sql/migrate-20261109-login-codes.sql` (сервис migrate применяет сам).
4. Первый вход (ниже).
5. Запустить: `docker compose -f docker-compose.yaml ... -f docker-compose.codes.yaml up -d codes`.
6. Убедиться, что `session` — `ready` (раздел «Состояние»), затем в `.env`: `LOGIN_CODES_SENDER_URL=http://codes:9378`, и перезапустить `bff`.

## Первый вход и повторный вход
Сервис должен быть остановлен: TDLib держит блокировку базы.

```bash
docker compose -f docker-compose.yaml ... -f docker-compose.codes.yaml stop codes
docker compose -f docker-compose.yaml ... -f docker-compose.codes.yaml run --rm -it --no-deps codes login
```

В терминале появится QR-код. В Telegram на телефоне аккаунта: «Настройки» → «Устройства» → «Подключить устройство», отсканировать. Код обновляется сам, сканировать последний. Затем команда спросит пароль двухэтапной аутентификации, без эха. После `Готово` снова `up -d codes`. Пароль и сессия нигде, кроме тома `codes_data`, не хранятся.

## Что видит человек (задача 076)
- Код ушёл в другую сессию Pluma (в том числе в сессию старой установки приложения): родной экран «код в Pluma на другом устройстве». «Не пришёл код?» на нём сразу отправляет код в Telegram (задача 080, ADR 0044) — дальше как ниже.
- Код ушёл в Telegram: экран «Проверьте Telegram» с кнопкой «Открыть Telegram» — чат с аккаунтом рассылки. **У аккаунта должно быть имя пользователя** (username, задаётся в настройках Telegram): без него кнопки нет. Сервис узнаёт имя при входе (`account` в `/v1/state`); после смены имени перезапустить `codes`.
- Код не дошёл (Telegram не нашёл человека или «Не пришёл код?»): экран «Код не дошёл до Telegram» с путём «Настройки → Конфиденциальность → Номер телефона → Кто может найти меня по номеру? → Все», кнопкой в эти настройки, «Отправить ещё раз» через 30 секунд и строкой про администратора. Код администратора и код из Telegram действуют оба.
- «Отправить ещё раз» снова пробует Telegram, не больше 4 доставок на один запрос; лимиты аккаунта (3 в час на номер) остаются.

## Состояние
```bash
set -a; . ./.env; set +a      # значения не выводить
curl -s -H "Authorization: Bearer $LOGIN_CODES_SENDER_TOKEN" http://127.0.0.1:9378/v1/state
```

Панель читает то же самое: она работает в сети хоста, порт `127.0.0.1:9378`.

| Поле | Значение |
|---|---|
| `session` | `ready`; `no_session` — входа нет, повторить вход; `starting`; `broken` — база не открывается (неверный `LOGIN_CODES_DB_KEY`) |
| `sendable` | можно ли сейчас отправлять |
| `limited_until` | до какого времени (unix) Telegram ограничил аккаунт |
| `queue_length`, `sent_last_hour`, `sent_last_day`, `contacts_to_remove` | очередь и счётчики |
| `account` | имя пользователя аккаунта рассылки; пусто — имени нет, у экрана кода нет кнопки «Открыть Telegram» |

## Алерты
- **`LoginCodesSessionGone`.** Telegram завершил сессию или входа ещё не было. Коды идут только через `pluma-admin login-code`, сервис работает. Посмотреть, заблокирован ли аккаунт в самом приложении Telegram, и повторить вход.
- **`LoginCodesAccountLimited`.** Ожидание от Telegram или ограничение (`PEER_FLOOD`, после него сервис молчит сутки). Ждать; если повторяется, снизить нагрузку или сменить аккаунт (новый вход на другой номер).
- **`LoginCodesSenderUnreachable`.** `docker compose ps codes`, логи сервиса. bff тем временем работает через администратора.
- **`LoginCodesContactsNotRemoved`.** Контакты не удаляются. Сервис повторяет раз в минуту.

## Что где хранится
- Том `codes_data`: база TDLib с сессией, зашифрована `LOGIN_CODES_DB_KEY`, и `sender-state.json` (лимиты, ожидание, контакты к удалению; номера только как HMAC).
- Коды — только в памяти на время очереди, при перезапуске теряются; человек запрашивает новый.
- Том не в бэкапах намеренно: это секрет. После потери — новый вход по QR.
- Логи не содержат номеров, кодов и текстов; собственный лог TDLib выключен.

## Лимиты
Заданы в `app/ops/codes/internal/sender` (`DefaultLimits`): пауза между отправками 5–10 с, на номер 3 в час и 8 в сутки, на аккаунт 30 в час и 120 в сутки, очередь 32, код ждёт в очереди не дольше 3 минут. Дополнительно у bff: не больше 20 кодов через аккаунт в час с одного адреса (`TelegramCodePerIP`).

## Память
Лимит контейнера 256 МБ — оценка: в документации TDLib числа нет, а без входа измерить нельзя. Базы сообщений и файлов выключены. После первого входа и нескольких отправок проверить `docker stats codes` и при необходимости поправить `docker-compose.codes.yaml` и `docs/ops/memory.md`.

## Что не проверено
Настоящая отправка: она невозможна до входа по QR. Всё остальное проверено модульными тестами с подставным TDLib.
