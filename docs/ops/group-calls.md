# Групповые звонки

Звонки в группах и каналах (задача 093, ADR 0059). Сигнализация — модуль `app/bff/groupcalls` внутри bff, медиа — отдельная служба `sfu` (`app/service/sfu`) со своим образом. SFU можно поставить на другую машину: bff находит его только по адресу из конфигурации (ADR 0057 §4).

Этап 1 к пользователям не выходит без этапа 2 (сквозное шифрование, ADR 0060): включать на боевом сервере только для проверки.

## Как устроено

- bff управляет SFU по gRPC с взаимным TLS (порт 20500): открыть и закрыть комнату, подключить и отключить участника, выключить ему звук, список удерживаемых SSRC, поток событий.
- Имя из `GROUPCALLS_SFU_ENDPOINT` bff разрешает заново при каждом подключении: SFU, пересозданный с другим адресом (новый контейнер, смена DNS при переносе), доступен сразу, без перезапуска bff.
- Клиенты подключаются к SFU напрямую: ICE, DTLS, SRTP, канал данных. Адрес и порты SFU клиент получает в ответе на `phone.joinGroupCall`.
- Состояние звонков — в MySQL (`group_calls`, `group_call_participants`, `group_call_viewer_prefs`, `group_call_subscriptions`; миграция `migrate-20261117-group-calls.sql`). Медиа нигде не хранятся.
- Перезапуск bff незаметен. Перезапуск SFU теряет комнаты: клиенты по `phone.checkGroupCall` видят, что их SSRC нет, и входят заново сами, комната открывается снова.
- Сборщик в bff раз в 5 с сверяет участников с SFU. Кого SFU не держит дольше 30 с (`GroupCalls.AbsentTimeout`), тот выходит из звонка. Пустая комната закрывается через то же время; сам звонок остаётся, пока его не завершат.
- «Войти от имени канала» не предлагается (ADR 0060): `phone.getGroupCallJoinAs` отдаёт только самого пользователя. Запись и RTMP не обслуживаются никогда.

## Порты

| Порт | Кто | Куда открыт |
|---|---|---|
| UDP `SFU_UDP_PORT` (20600) | клиенты, звук и видео | наружу |
| TCP `SFU_TCP_PORT` (20601) | клиенты, ICE-TCP — единственный путь, где UDP закрыт: TURN у групповых звонков стоковых клиентов нет | наружу |
| TCP 20500 | bff, управление | только сеть сервисов (`sfu:20500`); при SFU на другой машине — только адрес bff |
| TCP 20501 | Prometheus, `/metrics` | только сеть сервисов |

Порт 443 занят Caddy. ICE-TCP на 443 возможен только со вторым адресом сервера.

## Включить на сервере

1. **Сертификаты управления.** Один раз, на сервере:

   ```
   sudo teamgramd/deploy/sfu/control-certs.sh /opt/pluma/sfu /opt/pluma/groupcalls
   ```

   Скрипт выпускает два удостоверяющих центра — узлов и bff, чтобы сертификат одной стороны не сошёл за другую, — сертификат SFU с именем `sfu` и сертификат bff. Ключи центров не сохраняются: новый сертификат — новый запуск, и обе стороны получают новые файлы. Файлы SFU принадлежат uid 65532 (nonroot образа), режим 0400.
2. **`.env`:** `SFU_PUBLIC_IPV4` — адрес, на который придут клиенты (собственный адрес Pluma, если он есть: `PLUMA_PUBLIC_IPV4`). При нужде — `SFU_UDP_PORT`, `SFU_TCP_PORT`, `SFU_MEMORY`, `SFU_CPUS`.
3. **Межсетевой экран хостера:** открыть UDP `SFU_UDP_PORT` и TCP `SFU_TCP_PORT`. Docker публикует порты в обход ufw, но не в обход экрана хостера.
4. **Запуск:** к команде сервисов добавить `-f docker-compose.sfu.yaml`, поднять `sfu` и перезапустить `bff`:

   ```
   docker compose -f docker-compose.yaml ... -f docker-compose.sfu.yaml up -d sfu bff
   ```

   Наложение само задаёт bff `GROUPCALLS_SFU_ENDPOINT=sfu:20500` и монтирует его сертификат. Без наложения и без `GROUPCALLS_SFU_ENDPOINT` групповые звонки выключены: `phone.createGroupCall` и `phone.joinGroupCall` отвечают `GROUPCALLS_NOT_CONFIGURED`.
5. **Проверка:** `docker compose logs sfu` — строка о прослушивании портов. В Prometheus цель `ops.sfu` поднята. Звонок в тестовой группе с двух клиентов.

Образ SFU собирается из `teamgramd/deploy/sfu/Dockerfile` на месте (`pluma-sfu:local`) или задаётся `PLUMA_SFU_IMAGE`. CI образ SFU пока не собирает.

## Перенос SFU на другую машину

1. На новой машине — образ SFU и `teamgramd/deploy/sfu/sfu.yaml` с её публичным адресом. `Control.ListenOn` — адрес, который видит bff, лучше внутренний или VPN.
2. Сертификаты выпустить заново с именем или адресом новой машины: `control-certs.sh SFU_DIR BFF_DIR <имя или IP>`. Каталог SFU — на новую машину, каталог bff — на сервер ядра.
3. На сервере ядра: `GROUPCALLS_SFU_ENDPOINT=<адрес>:20500` в `.env`, наложение `docker-compose.sfu.yaml` не нужно. Сертификат bff смонтировать в `/run/secrets/groupcalls` (как в наложении) и перезапустить bff.
4. В Prometheus добавить цель `<адрес>:20501`.
5. Идущие звонки переедут сами: их комнаты на старом узле, и при первом же повторном входе клиента bff открывает комнату заново (условное обновление `sfu_node`). Имя узла (`Name: main`) менять нельзя, пока идут звонки. Несколько узлов перечисляются в `GroupCalls.Nodes` в порядке предпочтения: новая комната — на первом отвечающем.

Порты, роль ICE и `Plaintext` узла — в `teamgramd/deploy/sfu/sfu.yaml` (Docker) или `app/service/sfu/etc/sfu.yaml` (без Docker).

## Лимиты

| Что | Где | Сейчас |
|---|---|---|
| Участников в звонке | `Limits.MaxParticipants` SFU; `groupcalls.MaxParticipants` | 100 |
| Камер одновременно | `Limits.MaxVideos` SFU, `GroupCalls.VideoLimit` bff, appConfig `groupcall_video_participants_max` — одно и то же число в трёх местах | 30 |
| Говорящих одновременно | `Limits.LastN` | 5 |
| Отдача узла | `Limits.UplinkMbps` (0 — без лимита); при нехватке SFU понижает слои видео, а не отказывает во входе | 0 |
| Память и CPU контейнера | `SFU_MEMORY`, `SFU_CPUS` | 512m, 2 |

Сколько выдерживает узел под нагрузкой, не замерялось.

## Неполадки

| Признак | Что смотреть |
|---|---|
| Звонок создаётся, но клиент «соединяется» и не входит | `sfu_connect_failures_total` по `reason`. `no_check` — до SFU ничего не дошло: `SFU_PUBLIC_IPV4`, опубликованные порты, экран хостера |
| `GroupCallsSFUDown` | `docker compose ps sfu`, `docker compose logs --tail 100 sfu`: контейнер не запущен или перезапускается по кругу |
| `GroupCallsSFUUnreachable`, в логе bff `groupcalls: ... SFU node` | `docker compose ps sfu`; сертификаты (истёк срок, не тот центр); `GROUPCALLS_SFU_ENDPOINT` |
| Участник «висит» в списке после ухода | через 30 с его выведет сборщик; если нет — лог bff, строки `groupcalls:` |
| Исключённый из группы или канала остаётся в звонке | сборщик выводит его за один проход (5 с), `groupcalls_leaves_total{reason="access"}` |
| Выключенного администратором слышно | сборщик сверяет выключение на SFU со словом участника и повторяет `SetMuted`: `groupcalls_mute_repairs_total`; если растёт — лог bff, `mute of` |
| Видео мутное у всех | `sfu_uplink_bps` против `sfu_uplink_limit_bps`, `sfu_receiver_loss_ratio` |
| Только через TCP | `sfu_ice_pairs_total{network="tcp4"}`; у клиента закрыт UDP |

В журналы не пишутся ни учётные данные ICE, ни отпечатки DTLS, ни JSON входа (`tools/logaudit`).
