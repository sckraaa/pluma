# Групповые звонки

Звонки в группах и каналах (задача 093, ADR 0059), каждый — со сквозным шифрованием (задача 094, ADR 0060). Сигнализация — модуль `app/bff/groupcalls` внутри bff, медиа — отдельная служба `sfu` (`app/service/sfu`) со своим образом. SFU пересылает только шифр, поэтому его можно поставить на любую машину, в том числе на VPS вне доверенной зоны: bff находит его только по адресу из конфигурации (ADR 0057 §4, ADR 0060 §3).

Этап 1 к пользователям не выходит без этапа 2 (сквозное шифрование, ADR 0060): включать на боевом сервере только для проверки.

## Как устроено

- bff управляет SFU по gRPC с взаимным TLS (порт 20500): открыть и закрыть комнату, подключить и отключить участника, выключить ему звук, список удерживаемых SSRC, поток событий.
- Имя из `GROUPCALLS_SFU_ENDPOINT` bff разрешает заново при каждом подключении: SFU, пересозданный с другим адресом (новый контейнер, смена DNS при переносе), доступен сразу, без перезапуска bff.
- Клиенты подключаются к SFU напрямую или через трубу перед ним (раздел «Звонки из России»): ICE, DTLS, SRTP, канал данных. Адрес и порты SFU клиент получает в ответе на `phone.joinGroupCall`; какие — выбирает bff по стране клиента (`GROUPCALLS_ROUTES`).
- Состояние звонков — в MySQL (`group_calls`, `group_call_participants`, `group_call_viewer_prefs`, `group_call_subscriptions`; миграция `migrate-20261117-group-calls.sql`). Медиа нигде не хранятся.
- Перезапуск bff незаметен. Перезапуск SFU теряет комнаты: клиенты по `phone.checkGroupCall` видят, что их SSRC нет, и входят заново сами, комната открывается снова.
- Сборщик в bff раз в 5 с сверяет участников с SFU. Кого SFU не держит дольше 30 с (`GroupCalls.AbsentTimeout`), тот выходит из звонка. Пустая комната закрывается через то же время; сам звонок остаётся, пока его не завершат.
- «Войти от имени канала» не предлагается (ADR 0060): `phone.getGroupCallJoinAs` отдаёт только самого пользователя. Запись и RTMP не обслуживаются никогда.
- **Сквозное шифрование** (ADR 0060). Клиенты ведут цепочку блоков tde2e; сервер проверяет и упорядочивает блоки (`pkg/tde2e`), ключей не знает. Вход без ключа и блока — `GROUPCALL_FORBIDDEN`: клиент без патча в звонок не попадает. Цепочка — в `group_call_chain_blocks`, состояние — в строке `group_calls` (`chain_height`, `chain_hash`, `broadcast_count`), чей какой ключ — `group_call_chain_keys` (миграция `migrate-20261118-group-call-chain.sql`). Блоки звонка удаляются через `GroupCalls.ChainKeep` (по умолчанию 1 ч) после его завершения.
- **Диагностика шифрования** (ADR 0060 §5). SFU читает в звуковых кадрах открытые хэши эпох и принимает отчёты клиентов `PlumaE2EStatus` по каналу данных (строгая схема, до 16 КиБ, не чаще раза в секунду; отброшенные — `sfu_e2e_reports_total` по причине). bff сводит это с опросом цепочки и пишет по участнику в `group_call_e2e_diag`; метрики по звонку — `groupcalls_e2e_participants{call, alarm}`, без пользователей.

## Порты

| Порт | Кто | Куда открыт |
|---|---|---|
| UDP `SFU_UDP_PORT` (20600) | клиенты, звук и видео | наружу |
| TCP `SFU_TCP_PORT` (20601) | клиенты, ICE-TCP — единственный путь, где UDP закрыт: TURN у групповых звонков стоковых клиентов нет | наружу |
| TCP 20500 | bff, управление | только сеть сервисов (`sfu:20500`); при SFU на другой машине — только адрес bff |
| TCP 20501 | Prometheus, `/metrics` | только сеть сервисов |

Порт 443 занят Caddy. ICE-TCP на 443 возможен только со вторым адресом сервера.

## Включить на сервере

1. **Сертификаты управления.** Один раз, на сервере:

   ```
   sudo teamgramd/deploy/sfu/control-certs.sh /opt/pluma/sfu /opt/pluma/groupcalls
   ```

   Скрипт выпускает два удостоверяющих центра — узлов и bff, чтобы сертификат одной стороны не сошёл за другую, — сертификат SFU с именем `sfu` и сертификат bff. Ключи центров не сохраняются: новый сертификат — новый запуск, и обе стороны получают новые файлы. Файлы SFU принадлежат uid 65532 (nonroot образа), режим 0400.
2. **`.env`:** `SFU_PUBLIC_IPV4` — адрес, на который придут клиенты (собственный адрес Pluma, если он есть: `PLUMA_PUBLIC_IPV4`). При нужде — `SFU_UDP_PORT`, `SFU_TCP_PORT`, `SFU_MEMORY`, `SFU_CPUS`.
3. **Межсетевой экран хостера:** открыть UDP `SFU_UDP_PORT` и TCP `SFU_TCP_PORT`. Docker публикует порты в обход ufw, но не в обход экрана хостера.
4. **Запуск:** к команде сервисов добавить `-f docker-compose.sfu.yaml`, поднять `sfu` и перезапустить `bff`:

   ```
   docker compose -f docker-compose.yaml ... -f docker-compose.sfu.yaml up -d sfu bff
   ```

   Наложение само задаёт bff `GROUPCALLS_SFU_ENDPOINT=sfu:20500` и монтирует его сертификат. Без наложения и без `GROUPCALLS_SFU_ENDPOINT` групповые звонки выключены: `phone.createGroupCall` и `phone.joinGroupCall` отвечают `GROUPCALLS_NOT_CONFIGURED`.
5. **Проверка:** `docker compose logs sfu` — строка о прослушивании портов. В Prometheus цель `ops.sfu` поднята. Звонок в тестовой группе с двух клиентов.

Образ SFU собирает CI (`.github/workflows/images.yml`, `pluma-sfu`), как и остальные образы сервера (`docs/ops/deployment.md`: сервер ничего не собирает). В `.env` — образ того коммита, что работает:

```
PLUMA_SFU_IMAGE=ghcr.io/sckraaa/pluma-sfu:<коммит>
```

Без `PLUMA_SFU_IMAGE` наложение собирает образ на месте из `teamgramd/deploy/sfu/Dockerfile` (`pluma-sfu:local`) — так на стенде, не на сервере.

## Звонки из России: труба на узле amf (задача 116, ADR 0074)

Адрес SFU на Hetzner из России заблокирован, а TURN групповые звонки клиентов не используют (`GroupNetworkManager.cpp:398`, `groupCallConnectionInstance.ts:160`). Поэтому клиенту из России в ответе входа даются адрес и порты узла amf, а nginx Pluma на узле передаёт UDP и ICE-TCP как есть на адрес SFU. Сигнализация идёт, как и раньше, тем путём, которым клиент ходит к серверу (прямо, край `ru`, край Gcore).

```
клиент в России ──UDP 20600 / TCP 20601──► amf 194.87.226.185 (nginx stream Pluma) ──► SFU 195.201.252.126:20600/20601
прочие клиенты  ──UDP 20600 / TCP 20601──────────────────────────────────────────────► SFU 195.201.252.126:20600/20601
```

| Переменная | Где | Что | На проде |
|---|---|---|---|
| `PLUMA_RU_SFU_ADDR` | `/etc/pluma-ru/env` узла | публичный IPv4 SFU, апстрим трубы; пусто — трубы нет | `195.201.252.126` |
| `SFU_RELAYS` | `/opt/pluma-edge/.env` края (где работает SFU) | трубы перед узлом: `<имя>=<IPv4>:<UDP>/<TCP>` через запятую; имя `direct` занято собственными адресами | `ru=194.87.226.185:20600/20601` |
| `GROUPCALLS_ROUTES` | `.env` дома (bff) | наборы адресов по стране: `<страны или *>:<наборы>;…`, ровно одна запись `*`; пусто — всем `direct` | `RU,BY:ru;*:direct` |

- Страну bff узнаёт по адресу клиента (`authsession.getIpCountry`, кэш на час), при каждом входе и показе экрана. Неизвестная страна и ошибка поиска — запись `*`.
- Клиентам из России и Беларуси — только кандидаты узла, остальным — только прямые: SFU сам выдвигает пару и не отличает прямую от трубы по приоритету.
- Если bff просит набор, которого SFU не знает, SFU его пропускает (если не осталось ничего — отдаёт `direct`), считает `sfu_route_unknown_total` и пишет в журнал `a join names the route`; алерт `GroupCallsRouteUnknown`.
- Узел видит адреса клиентов, время и объём, как TURN `@ru`; содержимое — DTLS-SRTP с кадрами сквозного шифрования внутри.

**Включение — строго в этом порядке:**
1. **Замер пути** (один раз; бриф 116, часть 1): с amf до 195.201.252.126 — длинный поток UDP и TCP (`iperf3` на краю на свободном порту на время замера, с amf `iperf3 -u -b 10M -t 120` и TCP `-t 120` в обе стороны). Если поток «замерзает» — апстрим через туннель (вариант В брифа), это другой `PLUMA_RU_SFU_ADDR`.
2. **Узел.** В `/etc/pluma-ru/env` — `PLUMA_RU_SFU_ADDR=195.201.252.126`, затем выкладка узла (`docs/ops/ru-node.md`, «Выкладка»). Экран Timeweb — пропустить 20600/udp и 20601/tcp. Проверка — `docs/ops/ru-node.md`, «Труба групповых звонков».
3. **Край.** В `/opt/pluma-edge/.env` края — `SFU_RELAYS=ru=194.87.226.185:20600/20601`, выкладка края (пересоздаётся `sfu`: идущие групповые звонки входят заново сами). В журнале SFU — `relays [ru]`.
4. **Дом.** В `.env` — `GROUPCALLS_ROUTES=RU,BY:ru;*:direct`, перезапуск `bff`.
5. **Проверка:** клиент из России без VPN входит в звонок группы и слышит участника из Германии; в метриках SFU `sfu_ice_pairs_total{route="ru"}` растёт, `sfu_connections{route="ru",state="connected"}` — по числу соединений россиян.

**Откат** — в обратном порядке: дома убрать запись `RU,BY` из `GROUPCALLS_ROUTES` (или всю переменную) и перезапустить `bff`; затем, при нужде, `SFU_RELAYS` на краю и `PLUMA_RU_SFU_ADDR` на узле.

## Конференции (задача 117, ADR 0075)

Конференция — групповой звонок без чата: те же таблицы, вход, цепочка, SFU и маршруты по стране (`GROUPCALLS_ROUTES`), своя политика доступа. Новых переменных и настроек нет; миграция `migrate-20261126-conference-calls.sql` (повторяемая) применяется службой migrate.

- **Хранение.** Строка `group_calls` с `conference = 1`, `peer_type = 0`, `peer_id` = id звонка; `group_call_conferences` — создатель, `random_id` запроса, slug ссылки, `empty_since`; `group_call_invites` — приглашения и их состояние (`state` 0 звонит, 1 вошёл, 2 пропущено, 3 завершено; `shown` — что показывает сообщение); `group_call_participants.kicked` — исключённые создателем; `phone_calls.discard_slug` — slug при переводе звонка один на один (`discard_reason = 5`).
- **Ссылка** — `https://pluma.chat/call/<slug>` (22 знака base64url), одна на конференцию. Внутри приложений открывается без сети на всех четырёх клиентах; в браузере — страница службы `links` с кнопкой «Присоединиться к звонку» (`plm://call?slug=`), на `pluma.chat` и на зеркале `pluma.sckra.dev`. Создатель сбрасывает ссылку — старый slug сразу `GROUPCALL_INVALID`. Slug завершённой конференции 7 дней отвечает «звонок завершён».
- **Кто что может.** Видеть и входить: участники (бывшие тоже), создатель, пришедший по действующей ссылке, приглашённый. Приглашать — любой, кто в звонке. Завершить для всех, исключить, сбросить ссылку — только создатель. Исключённый не возвращается ни по ссылке, ни по приглашению участника, пока его не пригласит сам создатель.
- **Приглашение** — служебное сообщение `messageActionConferenceCall` в личном чате; клиенты звонят на него сами. Сервер правит то же сообщение у обоих: вошёл — «идёт», отказ, отмена или 90 с без ответа — «пропущен», конец конференции — длительность. Пуши: Android `CONF_CALL_REQUEST` (и `CONF_CALL_MISSED`), iPhone с токеном VoIP — PushKit, без него — пуш расширения.
- **Конец.** Создатель завершает сам; пустая конференция кончается через 5 минут после выхода последнего, а если в неё так никто и не вошёл — через 24 часа после создания (сборщик, раз в 5 с).
- **Перевод звонка один на один.** У каждого `phoneCall` стоит `conference_supported`; `phone.discardCall` с причиной перевода принимается, если slug — живая конференция, где сбросивший создатель или участник, и уходит собеседнику как есть.

| Предел | Где | Сейчас |
|---|---|---|
| Участников в конференции | appConfig `conference_call_size_limit`, `groupcalls.MaxParticipants` | 100 |
| Живых конференций у создателя | `groupcalls.ConferencesPerCreator`, сверх — `CONFERENCE_LIMIT_EXCEEDED` | 20 |
| Приглашений в минуту от пользователя | `groupcalls.InvitesPerMinute`, сверх — `FLOOD_WAIT_60` | 30 |
| Звонит приглашение | `groupcalls.InviteRingTimeout` = `call_ring_timeout_ms` | 90 с |

Метрики: `groupcalls_conferences_total{event}` (created: `link`, `joined`; ended: `discard`, `empty`, `refused`), `groupcalls_conferences_live`, `groupcalls_conference_invites_total{result}` (`ringing`, `privacy`, `kicked`, `already`, `flood`, `active`, `missed`, `ended`, `edit_failed`).

| Признак | Что смотреть |
|---|---|
| У приглашённого звонит и не перестаёт | `groupcalls_conference_invites_total{result="edit_failed"}` растёт — правки сообщений не проходят: лог bff `the message of invitation`, служба msg. Сборщик повторяет правку каждые 5 с |
| Приглашение не звонит на закрытом приложении | лог push, `push:`; у iPhone — есть ли токен VoIP (`pushdevices`), PushKit идёт только на него |
| `CONFERENCE_LIMIT_EXCEEDED` | у пользователя 20 незавершённых конференций; пустые кончатся сами (5 мин / 24 ч) |
| Ссылка «неактивна» | ссылку сбросили или конференция завершена больше 7 дней назад |

В журналы не пишутся slug ссылок (это пропуск в звонок), ключи и блоки; пишутся id звонков, пользователей и состояния.

## Перенос SFU на другую машину

1. На новой машине — образ SFU и `teamgramd/deploy/sfu/sfu.yaml` с её публичным адресом. `Control.ListenOn` — адрес, который видит bff, лучше внутренний или VPN.
2. Сертификаты выпустить заново с именем или адресом новой машины: `control-certs.sh SFU_DIR BFF_DIR <имя или IP>`. Каталог SFU — на новую машину, каталог bff — на сервер ядра.
3. На сервере ядра: `GROUPCALLS_SFU_ENDPOINT=<адрес>:20500` в `.env`, наложение `docker-compose.sfu.yaml` не нужно. Сертификат bff смонтировать в `/run/secrets/groupcalls` (как в наложении) и перезапустить bff.
4. В Prometheus добавить цель `<адрес>:20501`.
5. Трубы: на узле amf — новый `PLUMA_RU_SFU_ADDR` и выкладка узла, на новой машине — тот же `SFU_RELAYS`.
6. Идущие звонки переедут сами: их комнаты на старом узле, и при первом же повторном входе клиента bff открывает комнату заново (условное обновление `sfu_node`). Имя узла (`Name: main`) менять нельзя, пока идут звонки. Несколько узлов перечисляются в `GroupCalls.Nodes` в порядке предпочтения: новая комната — на первом отвечающем.

Порты и роль ICE узла — в `teamgramd/deploy/sfu/sfu.yaml` (Docker) или `app/service/sfu/etc/sfu.yaml` (без Docker). Флага `Plaintext` больше нет: все комнаты сквозные, любой узел берёт любой звонок. Старый ключ `Plaintext`/`E2E` в конфигурации узла можно удалить; он ни на что не влияет.

## Лимиты

| Что | Где | Сейчас |
|---|---|---|
| Участников в звонке | `Limits.MaxParticipants` SFU; `groupcalls.MaxParticipants` | 100 |
| Камер одновременно | `Limits.MaxVideos` SFU, `GroupCalls.VideoLimit` bff, appConfig `groupcall_video_participants_max` — одно и то же число в трёх местах | 30 |
| Говорящих одновременно | `Limits.LastN` | 5 |
| Отдача узла | `Limits.UplinkMbps` (0 — без лимита); при нехватке SFU понижает слои видео, а не отказывает во входе | 0 |
| Память и CPU контейнера | `SFU_MEMORY`, `SFU_CPUS` | 512m, 2 |

Сколько выдерживает узел под нагрузкой, не замерялось.

## Неполадки

| Признак | Что смотреть |
|---|---|
| Звонок создаётся, но клиент «соединяется» и не входит | `sfu_connect_failures_total` по `reason`. `no_check` — до SFU ничего не дошло: `SFU_PUBLIC_IPV4`, опубликованные порты, экран хостера |
| `GroupCallsSFUDown` | `docker compose ps sfu`, `docker compose logs --tail 100 sfu`: контейнер не запущен или перезапускается по кругу |
| `GroupCallsSFUUnreachable`, в логе bff `groupcalls: ... SFU node` | `docker compose ps sfu`; сертификаты (истёк срок, не тот центр); `GROUPCALLS_SFU_ENDPOINT` |
| Участник «висит» в списке после ухода | через 30 с его выведет сборщик; если нет — лог bff, строки `groupcalls:` |
| Исключённый из группы или канала остаётся в звонке | сборщик выводит его за один проход (5 с), `groupcalls_leaves_total{reason="access"}` |
| Выключенного администратором слышно | сборщик сверяет выключение на SFU со словом участника и повторяет `SetMuted`: `groupcalls_mute_repairs_total`; если растёт — лог bff, `mute of` |
| Видео мутное у всех | `sfu_uplink_bps` против `sfu_uplink_limit_bps`, `sfu_receiver_loss_ratio` |
| Только через TCP | `sfu_ice_pairs_total{network="tcp4"}`; у клиента закрыт UDP |
| Из России не входят, `GroupCallsRelayNoCheck{route="ru"}` | До SFU через трубу ничего не доходит. Алерт `RuSfuRelayDown`; на amf `systemctl status pluma-ru-nginx`, `ss -lunp 'sport = :20600'`; экран Timeweb для 20600/udp и 20601/tcp; с amf `timeout 5 bash -c '</dev/tcp/195.201.252.126/20601'`. Пока чинится — дома убрать `RU,BY` из `GROUPCALLS_ROUTES`: россияне с VPN войдут напрямую |
| `GroupCallsRouteUnknown` | `GROUPCALLS_ROUTES` дома называет набор, которого нет в `SFU_RELAYS` края; `docker compose logs sfu | grep route` |
| Россиянин в звонке через `direct` | Страна его адреса не `RU` (VPN, ошибка GeoIP) — так и задумано, узел для него не нужен; `pluma_ipcountry_errors_total` — bff не получил страну |

В журналы не пишутся ни учётные данные ICE, ни отпечатки DTLS, ни JSON входа, ни блоки цепочки, ни ключи участников, ни отчёты `PlumaE2EStatus` (`tools/logaudit`).

## Шифрование звонка: что смотреть

`pluma-admin -f /app/etc2/bff.yaml calls show <id звонка>` (в контейнере bff) печатает высоту цепочки, ход сверки эмодзи и по каждому участнику: в составе цепочки ли он, в звонке ли, с какой высоты опрашивает подцепочки, какими эпохами шифрует звук (высота, если сервер её знает), последний отчёт клиента (высота, блок, код ошибки tde2e, кадры, расшифровано и отвергнуто по отправителям), потерянные отчёты, повторные входы за 5 минут (входы того, кто уже был в составе цепочки: новое соединение или новый ключ после сбоя; первый вход не считается) и тревоги. Телефонов и ключей там нет. Идентификатор звонка — метка `call` у тревоги.

| Тревога | Что значит | Что делать |
|---|---|---|
| `GroupCallsE2EPollBehind` | клиент 15 с опрашивает цепочку ниже её высоты или не опрашивает | клиент завис; по правилу самовосстановления он входит заново через 12 с отставания. Если тревога держится — у пользователя старая сборка или клиент упал |
| `GroupCallsE2EStaleEpoch` | звук шифруется без эпохи текущей высоты 12 с после блока | отправитель отстал, его не слышно; ждать его повторного входа |
| `GroupCallsE2EVerificationStuck` | на высоте нет чьего-то commit или reveal 15 с | эмодзи у участников не совпадут, пока он не войдёт заново; чаще всего это участник «в составе, но не в звонке» |
| `GroupCallsE2EUnknownEpoch` | получатель не знает эпоху отправителя | эпоха отправителя — текущая высота: отстал получатель; старая — отправитель |
| `GroupCallsE2EKeyFailed` | клиент сообщил ошибку tde2e и не вошёл заново за 10 с | код в `calls show`; 300 — участника удалили из цепочки |
| `GroupCallsE2EStaleMember` | в составе цепочки, но не в звонке 30 с, хотя в звонке есть другой участник цепочки | его должны были удалить оставшиеся клиенты (`only_left`); если нет — у них старые сборки. Когда из звонка ушли все, удалить ушедших некому, и тревоги нет: следующий вошедший удалит их сам |
| `GroupCallsE2ERejoinLoop` | больше 3 повторных входов за 5 минут | см. ниже |
| `GroupCallsE2EUndecryptedSender` | отправителя не расшифровывает никто 10 с | неисправен отправитель |
| `GroupCallsE2EUnencryptedAudio` | в SFU идёт звук, который не кадр tde2e | клиент без шифрования или испорченные пакеты; SFU их отбрасывает, этого отправителя не слышно (задача 096) |
| `GroupCallsE2EReportsDropped` | SFU отбрасывает отчёты | причина в `sfu_e2e_reports_total{result}`; `version`/`schema` — клиент другой версии отчёта |

**Петля повторных входов.** Клиенты входят заново с новым ключом не больше 3 раз за 5 минут (ADR 0060 §5), потом выходят с сообщением. Тревога значит, что сбой повторяется: в `calls show` смотреть код ошибки и у кого тревоги отставания или неизвестной эпохи. Если ошибка у всех, кто вошёл после определённой высоты, — испорченный блок или несовместимый клиент: завершить звонок (`phone.discardGroupCall` администратором) и начать новый. Сервер сам цепочку не чинит: блок с новым ключом может написать только клиент.
