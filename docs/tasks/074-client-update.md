# 074. Обновление версий клиентов до слоя 233

- Статус: in progress (шаг 1, сервер на слое 233, готов и ждёт полного прогона; клиенты — отдельные шаги)
- Зависит от: партий 2026-11-09
- ADR: 0008 заменяется новым (сервер обслуживает несколько слоёв сразу), 0009 (порядок обновления кодека).

## Цель
Android, iOS, Desktop и Web на свежих версиях. Для Android это важно пользователям: новый интерфейс и новая запись кружков (`InstantCameraView2`, пауза, предпросмотр, обрезка).

## Что известно (подробности и источники в `074-research/`)
| Клиент | Сейчас | Цель | Слой | Сломанных якорей патча |
|---|---|---|---|---|
| Android | 12.9.1 | 13.2.1 (`7be672ea`) | 233 | 28 из 828 |
| iOS | 12.9.2 | 13.2 (`24638bc6`) | 233 | 31 из 415 |
| Desktop | 7.0.9 | 7.4.1 (`157f5cfc`) | 233 | 20 из 191 |
| Web K | 2.2 (676) | 2.3 (686, `aa74832e`) | 233 | 35 из 238 |

- **Клиент отдельно от сервера обновить нельзя:** из 210 новых конструкторов сервер знает 5, например `inputReplyToMessage` сменился, и ответы перестанут декодироваться.
- **`teamgram/proto` есть только до слоя 231,** генератора `mtprotoc` нет: 232 и 233 нужны своим способом.
- Кодек умеет несколько слоёв, но ошибки Encode проглатываются, а пуши строятся один раз на всех: это чинить до смешанного режима.
- Сборка: Android — 19 субмодулей, SDK 36, CMake 3.22; iOS — Xcode 27.1 (на GitHub пока preview), Bazel 9.2; Desktop — обновления v2, Rust; Web — tiptap.

## План
1. Сервер: слой 233 при сохранении клиентов 228 (выкатывается первым, текущие клиенты продолжают работать).
2. Клиенты по одному: Android первым, затем Desktop, Web, iOS (когда доступен Xcode 27.1).
3. Новые функции слоёв 229–233 — отдельные задачи.

## Результат
Шаг 1 (сервер): слои 228 и 233 одновременно, полный прогон зелёный (146 e2e). Шаг 2 (клиенты): ветки `task/074-upstream` всех четырёх форков. Android 13.2.1, Desktop 7.4.1 (Linux), Web 2.3 собраны на CachyOS; iOS 13.2 проверен наложением патча и разбором Swift, сборка невозможна без macOS 27 и Xcode 27.1. На устройствах и с сервером 233 клиенты не запускались.

Ссылка `getpremium` в Android закрыта (решение владельца 2026-11-09). Открыто на решение владельца: строки с telegram.org в Android (`PrivacyPolicyUrl`, FAQ) остались с прежних версий.

### Шаг 1 (сервер на слое 233, клиенты 228 продолжают работать)

Сервер обслуживает слои 228 и 233 одновременно: кодек переведён на upstream v0.231.0 (ADR 0009, наши патчи перенесены отдельными коммитами), 232–233 добавлены своим генератором `tools/tllayergen` из tdesktop api.tl, ответ и пуш кодируются для слоя конкретной сессии, старые клавиатуры и JSON-строки читаются, новые формы методов обслуживаются. Полный прогон (e2e, `-race`, `make lint`) и проверка клиентами ждут объединённой партии.

- **Кодек:** `third_party/teamgram-proto` v0.231.0; 16 наших патчей перенесены, `Encode` теперь возвращает ошибки вложенных объектов. Генератор (51 новый конструктор и метод 232–233, 8 новых id, 9 `flags.N?true`) идемпотентен, повторный запуск ничего не меняет.
- **Хранимое:** из 7 переименованных полей хранимое одно — `ReplyMarkup.rows`, имя возвращено; номера protobuf-полей 11 сообщений, что сдвинулись между 228 и 231, возвращены к прежним (очередь и бинарный каталог читаемы).
- **`pkg/layercompat`:** приведение объекта к слою сессии на копии (пуши общие): конструктор вне слоя заменяется unsupported-формой или выпадает, `quote_rich` для слоёв <232 получает плоский текст, клавиатуры 229+ собираются из формы хранения 228. Подключён во всех точках кодирования `session`; непредставимое — ошибка запроса или пропуск пуша, не усечённое тело.
- **Методы:** `channels.toggleForum` с `sidebar` (колонка `channels.forum_sidebar`, `migrate-20261109-forum-sidebar.sql`), прежняя форма работает и `sidebar` не трогает; `quote_rich` принимается и хранится в заголовке ответа (для слоёв до 232 — плоский текст так, как его собирает Android: `RichQuote.appendFlat`; цитата из другого чата проверяется по тексту сообщения, как обычная); `channel`, `channelFull`, `userFull`, `messageReplyHeader` идут новыми конструкторами для 232+.
- **Новые методы слоёв 229–233 (61):** где нет обслуживающего сервиса (`RPCNotServed` и заглушки), отвечают 400 `ERR_ENTERPRISE_IS_BLOCKED`. Прочитаны вызовы тех, что могут сработать без действий пользователя:
  - `ephemeral.getWelcomeMessages` — tdesktop `welcome_messages.cpp:589`, при открытии чата; ошибка 400 только прекращает загрузку приветствий.
  - `messages.getShareThemeBackdrops` — по действию пользователя в экране темы/QR (`api_share_themes.cpp`, Android `QrBackdrops.java`).
  - `payments.getCurrencyRates`, `wallet.getState`, onramp — экраны кошелька (`wallet_rates.cpp`, `wallet_session.cpp`, tweb `appWalletManager.ts`).
  - `messages.getWidgetPublicData`, `getBotWidgetQueryAnswer` — только при наличии виджета, сервер виджеты не создаёт.
  - Запуск клиентов 233 на сервере не выполнялся, поэтому полная последовательность вызовов при старте и открытии чата проверена только чтением кода перечисленных мест (не проверено).
- **Проверка на ветке:** `go build ./...`, `go vet -tags integration,e2e -unreachable=false` и `go test` затронутых пакетов (включая `pkg/layercompat`, `tools/tllayergen`, `third_party/teamgram-proto/mtproto`); e2e `test/e2e/mixed_layers_test.go` (пользователи 228 и 233 в одном чате, ответ, инлайн-клавиатура от ботов обоих слоёв, канал, тема форума) собран vet'ом, но не запускался: это прогон партии.

Решения для подтверждения:
- При `update` с новым `pts`, которого нет в старом слое, старый клиент его не получит (сейчас таких не создаётся).
- Диапазон поддерживаемых слоёв фактически ограничен тем, что `GetClazzID` знает: 233 и ниже; слой выше 233 не обслуживается.
- Пропущенные обновления для клиентов старых слоёв (дропнутые пуши) логируются и не компенсируются.

Открытые вопросы и известное: e2e и `-race` ещё не запускались на этой ветке; реальные клиенты 233 не подключались; подключение реальных клиентов — шаги 2–3 этой задачи.
