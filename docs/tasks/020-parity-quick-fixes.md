# 020. Быстрые правки по сверке с Telegram

- Статус: todo
- Зависит от: —
- ADR: 0017 (push; пункт про тип 7 заменить новым ADR), 0022

## Цель
Убрать дешёвые расхождения с Telegram, которые пользователь видит каждый день. Источник каждого пункта — `docs/audit/07-telegram-parity.md`: в скобках номер раздела. Эталон — Telegram на запасном аккаунте владельца; сравнение методов — по способу из приложения отчёта.

## Область
1. **Пуш-сессия Android, тип токена 7** (1.10).
   - Android в tgnet регистрирует отдельную MTProto-сессию для пушей: `account.registerDevice(token_type = 7, token = pushSessionId)`, `TMessagesProj/jni/tgnet/ConnectionsManager.cpp:2398-2419` (aac1efcb).
   - Сервер отвечает `TOKEN_TYPE_INVALID`: за 72 ч было 13 таких ответов.
   - Нужно принять регистрацию и будить клиент записью в эту сессию, когда основной сессии нет. Android по любому пакету в пуш-соединении зовёт `onInternalPushReceived`.
   - Что именно шлёт Telegram в эту сессию, не проверено; выяснить по коду tgnet и записать в новом ADR, который заменит пункт ADR 0017 «Android тип 7 сам не регистрирует».
   - Размер может оказаться средним: это слой session.
2. **Правка сообщения без потери форматирования** (1.3). Сейчас правка стирает жирный, курсив, спойлер и ссылки-текст у всех.
3. **`messages.readMentions`** (1.9): «Прочитать все упоминания» должно доходить до сервера.
4. **Вкладка «Медиа»** (1.4): ошибка SQL в `SelectByMediaType`, счётчики `messages.getSearchCounters`, листание в просмотрщике.
5. **Сохранённые GIF** (2.2): `messages.saveGif` и `getSavedGifs` с синхронизацией между устройствами.
6. **Дни рождения** (2.8).
   - `contacts.getBirthdays` сейчас заглушка внутри biz; должна стать настоящей.
   - Баннер «Добавьте день рождения» должен показываться. Android и Web K прячут его при `premium_purchase_blocked`; решение владельца — показывать, значит, нужны патчи клиентов. Место условия найти в коде клиентов и сослаться на него.
7. **`help.getSupport`** (1.11): «Задать вопрос».
8. **Удаление** (2.4): под-чата «Избранного» и истории за выбранные дни.
9. **Пересылка** (2.3): «Скрыть имя отправителя» и «Ответить в другом чате».
10. **`messages.getMessages(inputMessageReplyTo)`**: сервер понимает его как id самого сообщения, а по core.telegram.org это «сообщение, на которое отвечает указанное».
11. **«О себе» — 70 символов**, а не 128 байт (STATUS); кириллица длиннее 64 символов сейчас не сохраняется.
12. **Время в «Кто прочитал»**; **iOS: `account.getReactionsNotifySettings`**.
13. **Строка устройства Android — как у Telegram:** «Android, 15 (35)» вместо «SDK 35». Два наблюдения: 15 (35) и 16 (36), см. приложение отчёта.
14. **Мёртвые заглушки** (раздел «Как читать» отчёта).
    - Подмены `fake` для `messages.getWebPage`, `getWebPageView`, `report` указывают на несуществующие в layer 228 имена типов.
    - `tools/apicoverage` должен показывать статус `fake` и ловить такие имена.

Не трогаем: превью ссылок (023), реакции и стикеры (024), архив, отложенные и опросы (этап 2).

## Критерии приёмки
- Каждый пункт проверен против эталона Telegram (вызов метода или экран) и покрыт тестом. Видимое клиенту — e2e через `pkg/mtclient`.
- Android-телефон без Firebase получает уведомления в фоне.
- `go run ./tools/apicoverage` показывает fake-методы отдельно.
- STATUS и бриф обновлены.
