# 079. ИИ-редактор убрать из клиентов

- Статус: done (патчи четырёх клиентов; сборки клиентов — CI после пуша, проверка в клиентах — позже)
- Решение владельца 2026-11-11: ИИ-редактор сообщений убрать из всех четырёх клиентов (модели у Pluma нет).

## Что сделать
Патчами клиентов убрать вход в редактор и его экраны: Android `AIEditorAlert`, iOS вызовы `Translate.swift` для `composeMessageWithAI`, Desktop `create_ai_box` и `api_compose_with_ai`, Web соответствующие кнопки. Точные места — `docs/project/feature-registry.md`, пространство `aicompose` и `messages.compose*WithAI`.

## Результат
ИИ-редактор сообщений не предлагается ни в одном из четырёх клиентов. Правка в каждом клиенте — патч в его `ci/patch.py` из точных якорей, с проверкой `verify_no_ai_editor` и тестами `NoAiEditorTest`; экраны редактора остаются в исходниках недостижимыми. Каждая правка записана в реестр `clients/patches` (A-113, I-117, D-091, W-073). Пины взяты из `upstream.env` веток `main` клиентов: Android 13.2.1 (`7be672ea`), iOS 12.9.2 (`6ad963e5`), Desktop v7.4.1 (`157f5cfc`), Web `aa74832e`. Во всех четырёх пинах редактор есть. Ничего не закоммичено, ветки `task/079-remove-ai-editor` в worktree `~/pluma-work/wt-079-ai-{android,ios,desktop,web}`.

- **Android** (A-113). `showAiButton` в `ChatActivityEnterView`, `ChatAttachAlert` и `CaptionPhotoViewer` больше никогда не показывает кнопку. В редакторе rich (`RichEditor`, `RichEditorToolbar`) скрыты нижняя кнопка ИИ и группа кнопки стиля ИИ, панель форматирования не держит под неё место.
- **iOS** (I-117). Кнопка ИИ поля чата никогда не видна (`if false && self.isAIEnabled, …`). `isAIEnabled` у поля чата не трогается, потому что от него же зависит кнопка «развернуть». Подписи вложения и медиа не включают ИИ: убраны блоки, которые апстрим и сам пропускает при `ios_disable_ai_chat`/`ios_disable_ai_attach`. Кнопка ИИ редактора rich не добавляется на экран.
- **Desktop** (D-091). `Ui::HasEnoughLinesForAi` всегда false: это закрывает все кнопки полей ввода. Таблетка ИИ редактора rich не создаётся. Строка сочетания клавиш «Apply AI style to text» убрана.
- **Web** (W-073). Поле сообщения и подпись окна медиа не получают контекст редактора и не создают кнопку. Кнопка ИИ всплывающей панели форматирования скрыта.

Проверка. `python3 ci/patch_test.py` во всех четырёх репозиториях — OK (Android 77 тестов; iOS 77; Desktop все `*_test.py`; Web 48). Тесты на настоящем апстриме (`UpstreamTest`, с полным прогоном патча и порчей каждого нового якоря в `DAMAGE`) прогнаны локально через `./upstream`, взятый из соседних checkout на тех же коммитах: Desktop 28 OK, iOS 9 OK, Web 14 OK. В Android такого класса нет: правки наложены с `verify_no_ai_editor` на копию файлов `7be672ea`, обратная проверка падает на неправленом апстриме. Сборки клиентов (Gradle, Bazel, CMake, `pnpm run typecheck` и vite) не запускались, по правилу задачи их делает CI после пуша.

Решения, требующие подтверждения:
- iOS: кнопка «развернуть» поле чата сохранена. Официальный переключатель апстрима `ios_disable_ai_chat` убрал бы и её.
- Desktop: строка сочетания клавиш ИИ убрана из настроек, хотя команда в коде осталась (без стиля из редактора она только показывает подсказку).
- Не правились: ссылки на чужой стиль (`aicompose.getTone`; стилей в Pluma не создать, сервер отвечает ошибкой) и пункт ИИ на экране Premium (сервер не включает `ai_compose` в `premium_promo_order`).

Для задачи 027 (перевод). В iOS 12.9.2 экран перевода — тот же `TextProcessingScreen`, и он переводит через `messages.composeMessageWithAI` с `translate_to_lang` (`TextProcessingTranslateContentComponent.swift:240`, `Translate.swift:918`). На этом же экране вкладки стилей и «эмодзи», а это те же ИИ-инструменты. Сейчас перевод выключен в конфиге сервера, и задача 079 его не трогала.
