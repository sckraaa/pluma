# 015. Конфиг приложения: help.getAppConfig

- Статус: done
- Зависит от: 014
- ADR: 0001, 0016

## Цель
- Сервер отдаёт официальным клиентам конфиг приложения (`help.getAppConfig`).
- По его ключам клиенты включают функции и выставляют лимиты. Значения совпадают с тем, что сервер реализует и проверяет.
- Экраны покупки Premium скрыты штатным ключом, без патчей клиентов (ADR 0016).

## Контекст
- **Сейчас.** `help.getAppConfig` в обоих конструкторах (`app/bff/configuration/internal/core/help.getAppConfig*_handler.go`) — заглушка апстрима: пишет в лог «License key» и отдаёт пустой JSON.
- **Как ведёт себя Android без ключей.** Он берёт значения по умолчанию из своего кода (`MessagesController`, разбор `help.appConfig`, около 200 ключей). Это расходится с сервером:
  - `dialog_filters_limit_premium` по умолчанию 20, а сервер (как Telegram) разрешает 30 (задача 014);
  - `premium_purchase_blocked` не задан, поэтому экраны покупки Premium ведут в никуда;
  - лимиты закреплённых чатов, длины подписи и «о себе», загрузок и т. д. — значения клиента, их никто не сверял с сервером.
- **Схема ответа.** `help.appConfig hash:int config:JSONValue` и `help.appConfigNotModified` при совпадении `hash`.
- Web K и tdesktop читают свой набор ключей, выяснить по их коду.

## Область
1. **Конфиг** хранится на сервере как данные (файл рядом с `config.json` или секция в конфиге bff), а не в коде.
   - `hash` считается от содержимого.
   - Ответ `notModified`, если `hash` клиента совпал.
   - Оба конструктора метода отвечают одинаково.
2. **Ключи.**
   - Перечень — по коду клиентов: DrKLO/Telegram `MessagesController`, tdesktop, Web K.
   - Значения — как у Telegram для того, что сервер реализует: лимиты папок 10/30 и 100/200, закреплённые чаты, длины текстов.
   - Для нереализованного — значения, которые не включают функцию в клиенте.
   - `premium_purchase_blocked: true`.
   - `new_noncontact_peers_require_premium_without_ownpremium: false` (так считает сервер, задача 014).
3. **Лимиты, которые клиент берёт из конфига, а сервер не проверяет** (закреплённые чаты и т. п.), — список в брифе. Проверка каждого — своей задачей, если она нужна против неофициальных клиентов.

Не в этой задаче: `help.getConfig` (уже отдаётся из `config.json`), реализация новых функций.

## Критерии приёмки
- e2e: `help.getAppConfig` отдаёт ключи; с тем же `hash` — `help.appConfigNotModified`.
- Пользователь Android с Premium создаёт 30 папок. Экраны покупки Premium в официальном клиенте не открываются.
- Ключи и их источник (какой клиент читает) задокументированы.

## Результат
Сделано в ветке `task/015-app-config`. Ключи, значения и причины — `docs/ops/app-config.md`.

**Конфиг как данные.**
- Файл `teamgramd/bin/app_config.json` (71 ключ) лежит рядом с `config.json`. bff читает его при старте (`app/bff/configuration/internal/appconfig`).
- Порядок ключей в ответе — как в файле. Если файл не JSON-объект или ключ повторяется, bff не запускается.
- `hash` — FNV-1a от содержимого без пробелов. Если он совпал с `hash` клиента, сервер отвечает `help.appConfigNotModified`. Старый конструктор `help.getAppConfig#98914110` отдаёт тот же JSON.

**Ключи.**
- Ключи взяты из кода клиентов: Android 12.9.1 (`MessagesController`, `AppGlobalConfig`), tdesktop v7.0.9 (`appConfig().get`, `Data::PremiumLimits`), Web K `346844bf` (`MTAppConfig`, `getLimit`). Значения Telegram — из примера на core.telegram.org/api/config.
- В файле:
  - лимиты;
  - явные выключатели того, чего на сервере нет;
  - ключи, которые читает Web K: у него нет значений по умолчанию.
- Премиальные значения как у Telegram — только для папок и закреплённых чатов. Для остального они равны бесплатным (ADR 0016).
- Значения:
  - Premium: `premium_purchase_blocked: true`. Покупка звёзд, подарки, платные сообщения, розыгрыши и партнёрские программы выключены. `premium_promo_order` перечисляет только реализованное: лимиты папок, теги, «только контакты и Premium», значок.
  - Папки: 10/30 и 100/200. `new_noncontact_peers_require_premium_without_ownpremium: false`.
  - Выключены: истории, перевод, расширенное форматирование, пробная расшифровка голосовых, passkey, автоархив, кубики.
  - Фоновое соединение Android включено, как у Telegram: пушей пока нет.
  - Домены Telegram (`url_auth_domains`, `autologin_domains`, `whitelisted_domains`, `fragment_prefixes`) пустые.

**Проверки.**
- Unit-тесты:
  - разбор: типы, порядок, ошибки;
  - `hash` не зависит от форматирования и меняется от любого значения;
  - ответ и `notModified`;
  - файл из репозитория: обязательные значения, каждый ключ есть в `docs/ops/app-config.md`;
  - лимиты папок совпадают с константами сервиса диалогов.
- e2e `TestAppConfig`:
  - ответ равен всему `app_config.json`;
  - с тем же `hash` приходит `help.appConfigNotModified`;
  - старый конструктор отвечает тем же.
- Web K: сценарий `e2e/run.sh` репозитория `pluma-web` (ветка `task/015-folder-check`). Пользователь создаёт папку в настройках, второй браузер находит её. Без конфига Web K папок не создавал: «limit of undefined folders».
- На Android не проверено: 30 папок у Premium и закрытые экраны покупки. Значения сверены с кодом клиента. Проверка — за ревьюером (критерий приёмки).

**Лимиты из конфига, которые сервер не проверяет или проверяет иначе.** Проверка каждого — своей задачей, если она нужна против неофициальных клиентов.

| Лимит (ключ) | В конфиге | Сервер |
|---|---|---|
| Закреплённые чаты (`dialogs_pinned_limit_*`, `pinned_dialogs_count_max_*`) | 5 / 10 | не проверяет |
| Закреплённые в архиве (`dialogs_folder_pinned_limit_*`) | 100 / 200 | не проверяет |
| Закреплённые в «Избранном» (`saved_dialogs_pinned_limit_*`) | 5 / 100 | не проверяет |
| Длина сообщения (`message_length_limit_*`) | 4096 | не проверяет (проверка в `messages.sendMessage` закомментирована) |
| Подпись (`caption_length_limit_*`) | 1024 | до 4000 байт, только в `sendMedia` и `sendMultiMedia`: 1024 символа всегда помещаются |
| «О себе» (`about_length_limit_*`) | 70 | **не больше 128 байт**: кириллица длиннее 64 символов получает `ABOUT_TOO_LONG`, хотя клиент разрешает 70. Нужна проверка в символах UTF-16 с лимитом по Premium (70/140), как у Telegram |
| Цитата в ответе (`quote_length_max`) | 1024 | не проверяет |
| Части файла (`upload_max_fileparts_*`) | 4000 | у документов не проверяет (фото, GIF, обои, темы — до 3000). dfs собирает файл целиком в памяти, так что 2 ГБ на деле не выдержать |

Лимиты того, чего на сервере нет (каналы, общие папки, сохранённые GIF, избранные стикеры, реакции), ни на что не влияют, пока этих функций нет.

**Найдено попутно, не исправлено.**
- Кубики: ⚽ (у Telegram 1–5) и 🎰 (1–64) сервер разыгрывает как 1–6. Наборов стикеров (`messages.getStickerSet`) нет, поэтому кубики выключены в конфиге.
- `help.getPremiumPromo` — заглушка апстрима, отвечает ошибкой.
- У пользователя с Premium клиенты показывают кнопки Premium-функций, которых на сервере нет (расшифровка, чек-листы): ключа, который их выключает, нет.
