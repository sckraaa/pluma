# 072. Панель управления Pluma

- Статус: in progress (сервер и интерфейс готовы; ждёт общего прогона партии и проверки в браузере на сервере)
- Зависит от: 025 (панель модерации), 071 (Premium для всех: раздел Premium убирается), 073 (коды входа: настройка регистрации)
- ADR: 0040 (сеть и вход не меняются); новый, если меняется модель данных панели.

## Цель
Панель — пульт управления всем Pluma; SSH нужен только в аварии. Сейчас в ней только модерация (279 строк интерфейса).

## Решения владельца (2026-11-09)
- Объём: все разделы ниже, двумя шагами.
- В панели работает только владелец: **ролей нет** (`admin_users` остаётся как список входа, разделение прав убрать).
- Удаление аккаунта и канала — не сразу: сначала блокировка, удаление отдельным подтверждением ключом доступа.
- Панель удобна и на телефоне.

## Область
**Шаг 1**
- **Обзор:** пользователи, в сети, сообщения за сутки, регистрации, диск, проблемы сервисов, новые жалобы.
- **Пользователи:** поиск по номеру, имени, `@username`, id. Карточка: профиль, устройства, ограничения, жалобы. Действия: завершить сессии, ограничить, заблокировать, снять, показать код входа, написать от Pluma, удалить аккаунт.
- **Каналы и группы:** поиск, карточка (владелец, участники, жалобы), заблокировать, удалить.
- **Жалобы:** переделать удобнее: очередь, снимок, решение в один клик.
- **Регистрация:** переключатель «открыта / по списку», управление списком номеров (073).

**Шаг 2**
- **Рассылка** от служебного аккаунта всем или группе пользователей.
- **Выпуски:** версии клиентов на сайте, выпустить, откатить.
- **Система:** состояние сервисов, зависшие события с «повторить» и «отбросить», ссылки на Grafana.
- **Журнал и доступ.**

## Правила
- Панель никогда не показывает переписку: только снимки того, на что пожаловались.
- Действия — через RPC сервисов, как в 025; каждое опасное действие требует ключ доступа и пишется в журнал.
- Интерфейс без внешних зависимостей (CSP), вёрстка в стиле сайта, тексты на русском.
- Раздел Premium убрать (ADR 0041).

## Решения по ходу (подтвердить)
- Блокировка канала и группы — новые RPC `channel.setBlocked`, `chat.setBlocked` (ADR 0042). Канал виден `restricted`, текст в `restriction_reason` — один на двух языках сервера, поле не знает язык читателя (Android, tdesktop, iOS и Web показывают текст и не открывают канал).
- Обычная группа блокируется как `deactivated` со столбцом `blocked`: у `chat#` нет полей ограничения.
- `phone_allowlist`, `user_passwords` при удалении, коды в Redis, `mq_outbox` — через пакеты (`pkg/phoneallowlist`, `pkg/twofa`, `pkg/logincode`, `pkg/outbox`), как у `pluma-admin`: отдельных RPC для них нет.
- «Выпустить» в разделе «Выпуски» — вернуть отозванную сборку; новую сборку загружает только CI. Откат — через сервис `releases`, новые маршруты `/internal/releases` за токеном `RELEASES_ADMIN_TOKEN`, не под `/dl/`.
- При открытой регистрации, пока нет доставки (073), код видит только владелец: на карточке или в разделе «Регистрация».
- В заблокированном канале никто, включая создателя, не вступает, не удаляет сообщения, не меняет адрес и не удаляет канал; в заблокированной группе создатель не удаляет группу. Исключения только у сервера: решение по жалобе удаляет сообщение, панель удаляет канал или группу.
- Удаление аккаунта: сеансы, 2FA, имя пользователя, затем сама запись. Шаг не выполнился — ошибка, аккаунт остаётся, удаление можно повторить.
- Рассылка не сдвигает курсор, если сервис сообщений не ответил (перезапуск, размыкатель): продолжит с того же получателя, когда кончится аренда. Отказ сервиса по конкретному получателю считается ошибкой этого получателя.

## Результат
Панель стала пультом владельца. Роли убраны, `admin_users` — список входа. Разделы: Обзор, Пользователи, Каналы и группы, Жалобы (очередь, снимок, решение в один клик), Регистрация (переключатель «открыта / по списку» действует на `auth.sendCode` и `auth.signUp`, список номеров), Рассылка от 777000 (всем, по id, участникам канала; задача с курсором переживает перезапуск), Выпуски (откат и возврат через сервис `releases`), Система (сервисы и алерты из Prometheus, зависшие события: «повторить» и «отбросить» через `pkg/outbox`, ссылка на Grafana), Журнал (фильтры), Доступ (логины, ключи). Каналы и группы теперь можно блокировать (обратимо) и удалять; удаление возможно только после блокировки и подтверждается вводом id и ключом доступа. Интерфейс без внешних зависимостей, русский, с токенами сайта (графит и шалфей), состояния загрузки, пусто и ошибка, проверен макетом на 375 px (нет горизонтальной прокрутки).

Конкретика:
- Миграции: `migrate-20261109-panel-console.sql` (`registration_settings`, `channels.blocked`, `chats.blocked`, `admin_broadcasts`, индексы), `migrate-20261109-panel-roles.sql` (убирает `role`). Гранты — в `docs/ops/admin-panel.md`.
- Новые RPC: `channel.setBlocked`, `chat.setBlocked`. CLI для e2e и запасного доступа: `pluma-admin registration open|list`, `moderation block-channel|unblock-channel|block-chat|unblock-chat`.
- Новые переменные: `RELEASES_ADMIN_TOKEN`, `PANEL_GRAFANA_URL`; панели нужны `REDIS_PASSWORD`, `LOGIN_CODE_HMAC_KEY`.
- Тесты: unit; интеграционные на MySQL (панель, правила ключа и удаления, журнал без кода и телефона, рассылка, `pkg/phoneallowlist`, `channel`, `chat`, `releases`), e2e `TestRegistrationSwitch`, `TestChannelBlockedByOwner`.

Не сделано или не проверено: интеграционные тесты панели, блокировки каналов и групп, регистрации и выпусков прогнаны на CachyOS; e2e-тесты собраны, но запустятся впервые в общем прогоне партии; проверка на настоящем сервере и в браузере с настоящими данными не проводилась, показ вёрстки выполнен на макете с поддельным API; доставка кодов при открытой регистрации — задача 073.
