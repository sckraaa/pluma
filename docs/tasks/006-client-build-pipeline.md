# 006. Конвейер сборки клиентов

- Статус: in progress (Android готов; Web, iOS, Desktop — дальше)
- Зависит от: 001 (новый RSA-ключ — до этого собирать на временном тестовом ключе)
- ADR: 0001, 0006, 0008

## Цель
Каждый клиент собирается одной командой/кнопкой, с кэшем, с проверками в начале; повтор после ошибки — минуты, а не час.

## Область
По `docs/audit/04-clients-and-builds.md`:
- Отдельный репозиторий (или каталог `clients/`) с патчами поверх тегов upstream: iOS `release-12.9.2`, Android 12.9.1 (`aac1efcb83`), tdesktop v7.0.x, Web K/A — найти коммиты на layer 228.
- Патч: адреса серверов (`pluma.chat`), публичный RSA-ключ, api_id/api_hash, ID приложений `chat.pluma.*`, push-ключи.
- Preflight за секунды: версии Xcode/NDK, патчи применились, layer = 228, отпечаток RSA-ключа, профили для всех iOS-целей и App Group, keystore.
- Сборка в облаке по ADR 0010 (`docs/audit/05-cloud-builds.md`): публичные репозитории клиентов, стандартные GitHub-hosted раннеры, кэш в `actions/cache` с сохранением даже при падении, preflight → build → sign → publish на VPS, еженедельная «канарейка». Своё железо не используется.
- Подпись отдельным шагом после компиляции.
- Порядок: Android → Web → iOS → Desktop.

## Критерии приёмки
- Каждый клиент подключается к локальному стенду и проходит вход.
- Повторная сборка без изменений с тёплым кэшем: iOS ≤10 мин, Android ≤10 мин.
- Намеренно сломанный профиль подписи → падение на preflight за минуту, а не в конце.

## Результат

### Android (2026-10-23)

Репозиторий `sckraaa/pluma-android`, порядок работы — в его README; на стороне сервера — `docs/ops/clients.md`.

**Патч.** Копии кода клиента в репозитории нет. CI скачивает DrKLO/Telegram 12.9.1 (`aac1efcb83`, layer 228) по `upstream.env` и правит его скриптом `ci/patch.py`.
- Каждая замена обязана совпасть с апстримом точно. После замен скрипт отдельно проверяет, что в tgnet не осталось адресов и ключей Telegram.
- tgnet: один DC с адресом сервера для прод- и тест-бэкенда; свежая установка стартует на нём.
- Ключ: RSA-ключ сервера и его отпечаток вместо ключей Telegram. Отпечаток проверен тестом на известных ключах Telegram.
- Отключён поиск запасных адресов Telegram через DNS и Firebase.
- Идентичность: `chat.pluma.app`, «Pluma», `api_id` 10001. Свой тип аккаунта контактов и свои MIME-типы, чтобы жить рядом с Telegram на одном телефоне.
- Сборка только нужных модулей, без репозитория Huawei.
- Firebase: заглушка, пока нет настоящей конфигурации (009).

**CI.**
- Цепочка: `check` (тесты патча, shellcheck) → `build` → `sign`.
- `build`: ccache для нативного кода, Gradle build cache, оба в `actions/cache`.
- `sign`: только для сборок под настоящий сервер, в environment `release`.
- APK под настоящий сервер выходит из job только зашифрованным age-ключом владельца.
- Сборка без переменных сервера — dev-сборка (`10.0.2.2:10443`, dev-ключ): её не подписывают и не шифруют.
- Раз в неделю — «канарейка».
- Actions закреплены по SHA, Dependabot.

**Замеры.** Холодная сборка — 48 мин (Gradle 46 мин). Тёплая без изменений — 4 мин 45 с на весь job (Gradle 2 мин 57 с, ccache 8060 из 8060).

**Проверка.** Dev-APK на эмуляторе с локальным стендом (`E2E_SERVER_KEY` с dev-ключом, `E2E_GATEWAY_PORT=10443`):
- handshake на ключе Pluma, `invokeWithLayer` 228;
- выбор страны, `auth.sendCode`, код из `pluma-admin`, регистрация;
- отправка сообщения в «Избранное» (запись в MySQL);
- аккаунт контактов типа `chat.pluma.app`.

**Сервер (найдено клиентом).** `help.getCountriesList` апстрима отвечал пустым списком, и официальный клиент не мог выбрать страну и войти. Теперь список строится из libphonenumber: коды, шаблоны номеров, названия на языке клиента, основная страна общего кода — последней, hash и `countriesListNotModified`. `help.getNearestDc` отвечает «страна неизвестна» вместо выдуманной «CN».

**Не сделано / дальше.**
- Проверка на телефоне владельца (Android): dev-сборка с LAN-адресом и стенд, слушающий LAN.
- Настройка выпуска владельцем: ключ подписи, age-ключ, environment `release` с ревьюером, переменные сервера — когда будет VPS.
- Ребрендинг: иконка, строки «Telegram», пункты Premium и Business.
- Preflight подписи для Android не отделён: плохой секрет ловится в `sign` через минуты после сборки и чинится «Re-run failed jobs» без пересборки. Критерий «падение на preflight за минуту» остаётся для iOS-профилей.
