# 007. Каркас сравнительных тестов

- Статус: in-progress
- Зависит от: 005
- ADR: 0002, 0018

## Цель
Можно записать сценарий против настоящего Telegram и автоматически сравнить поведение нашего сервера.

## Область
- Выбор клиентской библиотеки (TDLib или Go MTProto-клиент) — обосновать в ADR.
- Сценарий = последовательность вызовов + ожидаемые ответы и апдейты; нормализация изменчивых полей (id, даты, хэши, access_hash).
- Запись эталонов с тестовых аккаунтов Telegram в фикстуры репозитория; прогон против нашего сервера без доступа к Telegram.
- Первые сценарии: вход, отправка/редактирование/удаление сообщения в ЛС, getDifference после пропуска апдейтов.
- `tools/apicoverage` дополняется колонкой «есть сценарий».

## Данные владельца
- Приложение на my.telegram.org (платформа Other) зарегистрировано владельцем 2026-10-25.
- `api_id` и `api_hash` лежат на Mac владельца в `~/pluma-secrets/telegram-api.env` (переменные `TELEGRAM_API_ID`, `TELEGRAM_API_HASH`, файл 600), в git и в чат не попадают. Запись эталонов нужна только при их обновлении. Прогон против нашего сервера и CI их не требуют.
- Эталоны пишутся в тестовой среде Telegram (номера `99966XYYYY`), без настоящих аккаунтов.

## Решения (план реализации)
Решения — ADR 0018.

**Шаги.**
1. **Каркас** `test/conformance`:
   - записывающая обёртка над `mtclient`;
   - нормализация TL в дерево с метками;
   - эталоны JSON в `testdata`;
   - сравнение с понятным diff;
   - исключения для сознательных отличий.
2. **Цели.**
   - Наш стенд (`PLUMA_E2E_*`, как e2e).
   - Тестовая среда Telegram: `TELEGRAM_API_ID`/`TELEGRAM_API_HASH`, DC1–3 по адресам и ключу из `mtproto_dc_options.cpp` Telegram Desktop, номер DC в рукопожатии + 10000.
3. **Сценарии до входа:**
   - `initConnection` + `help.getConfig`;
   - `help.getNearestDc`;
   - `auth.sendCode` (ответ, неверный номер);
   - `auth.signIn` (неверный и пустой код).
4. **Прогон** против стенда — в `test/e2e/run.sh test`, то есть и в CI.
5. **`tools/apicoverage`** — колонка «есть сценарий».
6. **Сценарии после входа** (личные сообщения, правка, удаление, `getDifference`) — когда появится способ войти.

**Тестовая среда Telegram на 2026-10-25.**
- Рукопожатие, `initConnection`, `help.getConfig`, `auth.sendCode` работают.
- Вход номерами `99966XYYYY` с документированным кодом (номер DC пять или шесть раз) даёт `PHONE_CODE_INVALID` на DC1 и DC2. Байты запроса проверены.
- Нужно решение владельца, откуда брать эталоны после входа.

## Критерии приёмки
- 5 сценариев записаны и прогоняются в CI против нашего сервера.
