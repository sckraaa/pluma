# 004. Развёртывание, наблюдаемость, бэкапы

- Статус: todo
- Зависит от: 001 (сетевые настройки compose)
- ADR: 0005

## Цель
Каждый процесс под супервизией, упавший сервис перезапускается сам, есть алерты и проверенные бэкапы.

## Область
По `docs/audit/03-architecture-and-ops.md`:
- docker-compose: один процесс — один сервис; `restart: unless-stopped`; healthcheck; exec-form entrypoint (SIGTERM доходит до процесса, graceful shutdown).
- Образы с закреплёнными версиями (никаких `:latest`).
- Redis: AOF, `maxmemory`; MySQL: `max_connections` согласован с пулами (сейчас пулы ≈400 при лимите 151).
- Версионируемые миграции схемы (golang-migrate или аналог) вместо ручного SQL.
- Логи: убрать Elasticsearch/Kibana/Filebeat/go-stash и log-топик Kafka, поставить Loki + Grafana.
- Метрики и алерты: доставка (лаг консьюмеров, DLQ), ошибки RPC, задержки, место на диске.
- Бэкапы MySQL и MinIO по расписанию + автоматическая проверка восстановления.

## Критерии приёмки
- `docker kill` любого сервиса → он поднимается сам, клиент переподключается.
- Восстановление из бэкапа на чистой машине по runbook проходит и проверено.
- Дашборд Grafana и хотя бы алерты: сервис недоступен, лаг доставки, DLQ не пуст, диск.
