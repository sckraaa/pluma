- Статус: done (код), ждёт выкладки.
- Поставлена владельцем 2026-11-19: «все приложения тоже отдавались по CDN, в том числе для пользователей РФ — по РФ серверу, хочу чтобы всё летало». Уточнение владельца: Android в России нет, только iOS.
- Зависит от: 054 (сервис `releases`, `/dl/`), 085 (обновление iPhone из приложения), 107 (источник CDN `cdn-origin.caddy`), 109 (ресурс Gcore края, узел amf, выдача 202), 113 (зеркала сайта, `PLUMA_RELEASES_ROUTES`).
- ADR: 0035 (выпуски на своём сайте), 0072 (края и узел). Новых архитектурных решений нет: кэши — уже существующие ресурс Gcore края и nginx узла.
- Ветка: `task/115-cdn-downloads`.

## Цель
Установщики и обновления приложений скачиваются из кэша рядом с пользователем, а не с домашнего сервера: весь мир — через ресурс Gcore края (`gk8qyyfx.gcorecdn.com`), Россия — через узел amf (`r1.sckra.dev`). Один файл выпуска поднимается из дома один раз на кэш. Всё включается и выключается переменными, без пересборки.

## Что было
- `/dl/` отдаёт только сервис `releases` за Caddy дома, на именах сайта и зеркала `pluma.sckra.dev` (зеркало — TCP-труба через amf, без кэша). Файл версии сервис уже отдаёт с `Cache-Control: public, max-age=31536000, immutable`, списки — `no-cache`, переходы `latest` — `no-store` (`app/service/releases/internal/server/handler.go`).
- Префикс обновлений Desktop (`help.getConfig`, `autoupdate_url_prefix`) — `<сайт>/dl/desktop`, по стране — зеркало (`PLUMA_RELEASES_ROUTES`, задача 113).
- iPhone (Ad Hoc): страница `/iphone/install`, манифест и IPA — у `iosinstall`, IPA только по токену устройства или билету обновления (`docs/ops/ios-install.md`); ссылка обновления — на сайте или зеркале.
- Кнопки сайта (`pluma-site`, `src/install/releases.ts:55-58`, `:151`) ведут на `https://pluma.chat/dl/<платформа>/latest`; сборка сайта принимает только адреса `https://pluma.chat/dl/…` (`:61`).
- Источник края Gcore (`edge-origin.caddy`) раздавал только `/apiws` и Web K; ответ без `Cache-Control` (например, 308 файлового сервера на каталог) Gcore мог закэшировать.

## Дизайн
1. **Сайт и файлы — разные базы.** Префикс Desktop и кнопки сайта — на кэш файлов, а страница установки, манифест и IPA iPhone — по-прежнему на сайте и его зеркале: кэши файлов не раздают `/iphone/install` и `/ios/adhoc/` (их нельзя кэшировать — токены, переподпись). Поэтому не новая запись в `PLUMA_RELEASES_ROUTES`, а две новые переменные:
   - `PLUMA_RELEASES_FILES_URL` — CDN для любой страны: `https://gk8qyyfx.gcorecdn.com`;
   - `PLUMA_RELEASES_FILES_ROUTES` — кэши по стране, формат `PLUMA_RELEASES_ROUTES`: `RU,BY=https://r1.sckra.dev`.

   Порядок выбора для клиента (`releasesite.ParseFiles`): запись страны в `FILES_ROUTES` → зеркало сайта, если страна есть только в `PLUMA_RELEASES_ROUTES` (CDN там может быть так же недоступен, как сайт) → `FILES_URL` → сайт. Без новых переменных поведение прежнее.
2. **Desktop принимает любой хост префикса.** tdesktop сохраняет префикс из конфига как есть (`Local::writeAutoupdatePrefix`, `mtproto/mtp_instance.cpp:945-947`, `storage/localstorage.cpp:561-579`) и ставит пакет только после проверки подписи встроенным ключом (`Updates::VerifyUpdate`, `core/update_checker.cpp:475-488`); tdesktop v7.4.1 `157f5cfc` (`upstream.env` Desktop), прочитано 2026-11-19. Подмена в кэше не даёт поставить чужой пакет.
3. **Мир — Gcore (ресурс 2).** `edge-origin.caddy`: `/dl/*` → `releases:9097` для GET и HEAD (иначе 405), без секрета ресурса. Кэшем управляет `Cache-Control` сервиса (ресурс — «Origin controlled», `docs/ops/edge.md`). Всё, что хранить нельзя, источник помечает `no-store`: `/apiws`, 403 без секрета, переходы 301/302/303/307/308, ошибки 4xx/5xx и ошибки самого Caddy (`handle_errors`); 304 не трогается — он обновляет то, что у Gcore уже лежит.
4. **Россия — узел amf.** `files.conf.tmpl`: на имени выдачи 202 (`r1.sckra.dev`) файл версии — из своего кэша `pluma_releases` (куски 8 МиБ, 6 ГБ, 30 дней), остальное `/dl/` — насквозь; только GET/HEAD. Домой — тем же туннелем и upstream, что шифр, на имя источника CDN (`cdn-origin.caddy`, туда добавлен `/dl/*` → `releases` для GET/HEAD), без `X-Pluma-Origin-Auth` и без заголовков клиента, кроме диапазона. Отступление от первоначального плана («Host сайта»): у Caddy дома на :443 имя сайта и так есть, но запрос с `Host: pluma.chat` сервис принял бы за запрос сайта и отправил бы `latest` на Gcore; имя источника этого не делает и переиспользует проверенный upstream с TLS-проверкой. Новых переменных узла нет.
5. **Кнопки сайта.** Переход `latest`, запрошенный на имени самого сайта (`PLUMA_RELEASES_URL`), при заданном `FILES_URL` ведёт на файл на CDN; на любом другом имени — путь на том же имени (зеркало, CDN, узел). Кнопки `pluma.chat/dl/<платформа>/latest` качают с Gcore без правки сайта.
6. **iPhone без изменений.** Страница, манифест и IPA остаются у `iosinstall`. Из России они уже идут через узел (зеркало `pluma.sckra.dev`, TLS-труба), то есть «по РФ серверу», но без кэша (решение 3).

1. Desktop из России (через узел) и из Германии: в журнале апдейтера префикс `r1.sckra.dev` / `gk8qyyfx.gcorecdn.com`, обновление ставится.
2. Ресурс Gcore 2: есть ли опция больших файлов (кусками) и включать ли её; второй запрос файла — из кэша Gcore (заголовок ответа).
3. Кнопка установщика на `pluma.chat` скачивает с `gk8qyyfx.gcorecdn.com`.

## Решения к подтверждению
1. Отдельные переменные кэшей файлов, сайт и iPhone не переезжают (дизайн, п. 1).
2. Страна, которой нет в `FILES_ROUTES`, но есть в `PLUMA_RELEASES_ROUTES`, остаётся на зеркале (дизайн, п. 1).
3. IPA не кэшируется: выдаётся по токену устройства или билету и переподписывается при каждом новом айфоне; общий кэш потребовал бы проверки токена на краю. Из России IPA идёт через узел без кэша.
4. `/dl/` на источнике CDN (`origin.pluma.chat`) открыт без значения доступа: файлы публичные, только GET/HEAD.

## Открытые вопросы
- **Кнопки сайта в России.** Сборка `pluma-site` принимает только `https://pluma.chat/dl/…` (`src/install/releases.ts:61`), и `releases.json` даёт такие же адреса — на зеркале кнопки ведут на заблокированное имя (известно с задачи 113). Нужна правка сайта (относительные `/dl/<платформа>/latest`); после неё переход на зеркале останется на зеркале (труба через узел без кэша). Направлять зеркало на кэш узла — отдельное решение (сервису пришлось бы знать пары «имя зеркала → кэш»).
- Android в России не раздаётся (уточнение владельца); с сайта во всём мире Android идёт через Gcore, в приложении — документом через MTProto, как раньше.

## Результат
Сделано. bff даёт Desktop префикс обновлений на кэше файлов по стране клиента: `PLUMA_RELEASES_FILES_ROUTES` (узел amf для России), иначе зеркало сайта (`PLUMA_RELEASES_ROUTES`), иначе `PLUMA_RELEASES_FILES_URL` (Gcore), иначе сайт; iPhone остаётся на сайте и зеркале. Сервис `releases` отправляет кнопки сайта на CDN (`latest` на имени сайта), на остальных именах оставляет путь. Источник края Gcore раздаёт `/dl/` для чтения и помечает `no-store` всё, что Gcore хранить нельзя (`/apiws`, 403, переходы, ошибки); источник CDN дома раздаёт `/dl/` для кэша узла; nginx узла кэширует файлы версий (куски 8 МиБ, 6 ГБ) и пропускает списки и переходы. Документация: `releases.md` («Раздача через CDN»), `ru-node.md` («Выпуски»), `edge.md`, `deployment.md` (порядок выпуска сертификатов имён через узел), `.env.example`.
