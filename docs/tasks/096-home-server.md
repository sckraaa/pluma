# 096. Переезд на домашний сервер

- Статус: переключено (2026-11-14, 01:14 UTC); остаются хвосты из «Дальше».
- ADR: 0057 (направление), 0061 (как переезжаем).
- Ветка: `task/096-home-server`. Инструкция оператора: `docs/ops/home-server.md`.

## Цель
Всё Pluma — база, файлы, сервисы, ключи, сайт, раздача сборок, веб-клиент — работает на домашнем сервере владельца. На VPS остаётся только то, что дома невозможно и видит один шифр:
- публичный адрес 195.201.252.126, пересылаемый домой;
- SFU групповых звонков;
- TURN звонков один на один.

Клиенты не пересобираются, пользователи ничего не замечают, кроме короткого окна переключения.

## Ограничения
- Роутер дома арендный и закрытый: пробросов и белого адреса нет. Туннель открывает дом.
- 159.69.215.232 и всё на нём не трогать ни в каком виде. 195.201.252.126 — можно всё. `sckra.dev` должен работать (владелец, 2026-11-14).
- Секреты переходят с сервера на сервер и не печатаются (разрешение владельца). Ключ чтения для дома на VPS — с разрешения владельца, удаляется после переезда.

## Сделано
- **Домашний сервер:**
  - Ubuntu 26.04.1, LVM на весь диск (466 ГБ);
  - автообновления, ufw (только 22), SSH только по ключу;
  - Docker 29.9 + Compose 5.7, логи `local`, DNS контейнеров через туннель;
  - `pluma.slice` 28 ГБ.
- **Туннель WireGuard:** `tunnel.sh`. Рукопожатие есть, задержка 11–18 мс. Выход контейнеров с 195.201.252.126 и DNS через туннель проверены.
- **Файлы края:**
  - `docker-compose.edge.yaml`: SFU, TURN, node-exporter, site-relay;
  - `docker-compose.groupcalls.yaml`: bff дома;
  - `forward.sh`: переключатель DNAT;
  - цели Prometheus из файлов хоста.
- **Перенесено домой:** секреты и файлы сайта; черновая копия данных идёт.

## Репетиция (2026-11-14, прошла)
- **Черновая копия данных VPS → дом:** около 30 ГБ за 7,5 минуты по туннелю (`pluma-seed`).
- **Данные дома:**
  - MySQL — согласованный дамп с прода, 40 секунд; 11 пользователей и 1652 сообщения, как на проде;
  - Garage — метаданные из часового снимка;
  - `state-raise` и миграции прошли.
- **Запущено ядро без `push`, `codes`, `backup`, `alertpush`, `alertmanager`.** Все сервисы `healthy`, порты только на `10.77.0.2`.
- **Проверки с VPS через туннель:**
  - сайт, веб-клиент и `www` — 200 с действующим сертификатом;
  - `/progress.json` — 200;
  - `/apiws` — 101;
  - `http` → `https` — 308;
  - рукопожатие MTProto (obfuscated abridged, `req_pq_multi` → `resPQ`) на 10443 и 5222 — как у прода;
  - `/dl/health`, `/dl/releases.json`, `/dl/desktop/current4` и `/ios/adhoc/` побайтно совпадают с продом;
  - APK на 41 МБ отдан из дома на 6,8 МБ/с (потолок отдачи);
  - `sckra.dev`: домашний Caddy отвечает с действующим сертификатом, путь до `lawyer-app` через пересылку отдаёт 200.
- **Не проверено до переключения:** вход и работа настоящих клиентов, адреса клиентов в сессиях, звонки через край, Prometheus с целями края.
- **Бэкап из R2 в репетиции не восстанавливался:** данные пришли напрямую с прода. Еженедельная проверка восстановления бэкапа работает отдельно (`docs/ops/backup.md`).

## Конфиденциальность (2026-11-14, после переключения)
Проверка: пять агентов, отдельный проверяющий перепроверил их выводы по коду. Итог и что осталось принятым — ADR 0061, дополнение. Сделано:
- **Старое ядро на VPS стёрто:**
  - контейнеры, тома `pluma_*`, `/opt/pluma` (с `.env`, `.env.bak-*`, ключами, данными), `/srv/pluma-*`, служебные файлы в `/root`, образы;
  - ключ `pluma-home-pull` и таймер языковых пакетов;
  - строки тома в `/etc/fstab` (копия в `/root/fstab.before-096`); том отмонтирован и очищен `blkdiscard`;
  - `fstrim /`.
- **Сертификаты:**
  - `acme_ca` Let's Encrypt в `Caddyfile`;
  - новый ACME-аккаунт `acct/3996877102`, все четыре имени перевыпущены;
  - старые сертификаты отозваны certbot с причиной keyCompromise, их ключи стёрты.
- **SFU:** `audioFrame` отбрасывает звук, который не кадр tde2e; пакеты без полезной нагрузки проходят. Тест `TestUnencryptedAudioDropped`; тесты SFU шлют кадры формата tde2e (`groupcallpeer.SendAudioPayload`).
- **DNS:** systemd-resolved с DNS over TLS, дополнительный адрес `172.20.0.1`, `daemon.json` `dns` и `live-restore`; сервисы, ходящие наружу, пересозданы. Проверено tcpdump: запросы идут на `172.20.0.1`, а не на 1.1.1.1 через туннель.
- **Простой 01:44–01:45:42 UTC:**
  - `networkctl reload` (резолверы eno1) удалил правила `pref 100/110` туннеля;
  - восстановлены перезапуском `pluma-tunnel-rules`;
  - причина закрыта: `networkd.conf.d/10-pluma-tunnel.conf`, проверено повторным `networkctl reload`.

## Решения, требующие подтверждения
- `sckra.dev`: TLS заканчивается дома, запрос возвращается на VPS к `lawyer-app` через `site-relay`. Сайт работает, пока работает дом. Альтернатива с разбором по SNI на VPS описана и отклонена в ADR 0061, п. 4.
- Исходящий трафик сервера идёт через VPS, чтобы не раскрывать домашний адрес. VPS видит только шифр и метаданные.

## Найдено попутно (не в этой задаче)
- `pluma-deploy.sh` после каждого деплоя публикует порт шлюза 11443 на адресе Pluma: команда C2 запускается без `docker-compose.web.yaml`, а `!override` портов есть только там. Документ `docs/ops/deployment.md` говорит, что порт закрыт. Пересылка на дом 11443 не включает.
- На VPS в `/opt/pluma` лежат 60+ копий `.env.bak-*`: каждый деплой делает новую. Это копии всех секретов. Их стоит ограничить последними несколькими.
