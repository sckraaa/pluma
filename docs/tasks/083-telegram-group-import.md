# 083. Перенос группы из Telegram в Pluma

- Статус: done (2026-11-12, ветка `task/083-telegram-group-import`, не закоммичено); решения из раздела «Решения, требующие подтверждения» ждут владельца.
- Инструкция оператору: [docs/ops/import-chat.md](../ops/import-chat.md).
- ADR: [0051](../adr/0051-telegram-group-import.md).

## Что нужно
Владелец переносит настоящую группу из Telegram в Pluma: все сообщения, фото, видео, файлы, кружки, голосовые, стикеры, ответы, пересылки, правки, реакции. Автор каждого сообщения — уже существующий аккаунт Pluma того же человека. После переноса у всех участников история прочитана, голосовые и кружки прослушаны.

Решения владельца (2026-11-11):
- у каждого автора группы есть аккаунт Pluma; несопоставленный автор — ошибка, а не «сообщение от имени группы»;
- реакции переносятся;
- прочитанность переносится.

## Что делает владелец

### 1. Выгрузить группу из Telegram Desktop
1. Официальный Telegram Desktop → группа → меню «⋮» → **Export chat history**.
2. Отметить все виды: **Photos, Videos, Voice messages, Video messages, Stickers, GIFs, Files**.
3. **Size limit** — ползунок до конца вправо (4000 МБ). По умолчанию там 8 МБ и только фото: с такими настройками видео и файлы в выгрузку не попадут.
4. **Location and format** → формат **Machine-readable JSON** (не HTML). Путь — диск, где хватит места.
5. Даты не ограничивать. Нажать **Export** и дождаться конца; Telegram может попросить подтвердить выгрузку с другого устройства и подождать сутки.
6. Выгружать должен участник, который видит всю историю. Получится папка `ChatExport_<дата>` с `result.json` и подпапками `photos`, `video_files`, `voice_messages`, `round_video_messages`, `stickers`, `files`.

### 2. Положить папку на сервер
`rsync -a --partial ChatExport_<дата>/ <сервер>:/srv/pluma-import/<имя>/` — папку целиком, не меняя имён. `--partial` позволяет докачать после обрыва.

### 3. Составить соответствие авторов
Все команды — разовым контейнером сервиса `bff` с папкой выгрузки внутри (`DC` — `docker compose` с файлами стенда):
```
DC run --rm --no-deps -v /srv/pluma-import/<имя>:/import bff ./pluma-admin -f=../etc2/bff.yaml import-chat map -dir /import
```
Команда читает выгрузку и пишет `/import/mapping.json`: все, кто встречается в группе, с именами и числом сообщений, и кандидата из Pluma, если имя и фамилия совпали ровно с одним аккаунтом. Повторный запуск сохраняет уже заполненное. Id аккаунтов показывает `import-chat accounts`.
```json
{
  "export_chat_id": 1234567890,
  "creator": 1000001,
  "exporter": 1000001,
  "authors": {
    "user111222333": {"names": ["Иван Петров"], "messages": 15234, "pluma": 1000001, "pluma_name": "Иван Петров", "suggested": true, "confirmed": false},
    "user444555666": {"names": ["Маша"], "messages": 8120, "pluma": null, "confirmed": false}
  },
  "service_names": {"Олег Сидоров": null},
  "extra_members": []
}
```
- `creator` — аккаунт Pluma, который станет создателем группы (владелец).
- `exporter` — аккаунт Pluma того, кто делал выгрузку: его голос в опросах переносится. `0` — опросы без голосов.
- `authors` — каждой строке поставить `pluma` (id аккаунта) и `"confirmed": true`. Автор сообщений без подтверждения — ошибка. Строки с `"messages": 0` (только реакции или служебные) заполнять не обязательно.
- `"skip": true` вместо `pluma` — явно не переносить сообщения этого автора (бот).
- `service_names` — имена из служебных сообщений («добавил(а) Олега»), которые нельзя свести к участнику: в выгрузке там только имя. Можно вписать id аккаунта Pluma; `null` — такое служебное сообщение не переносится.
- `extra_members` — аккаунты, которых надо добавить в группу, хотя они в ней ничего не писали.
- Участниками станут создатель, все `pluma` из `authors`, аккаунты из `service_names` и `extra_members`.

### 4. Проверить план (ничего не пишет)
```
DC run --rm --no-deps -v /srv/pluma-import/<имя>:/import:ro bff ./pluma-admin -f=../etc2/bff.yaml import-chat plan -dir /import
```
Печатает: число сообщений по видам; авторов без соответствия или подтверждения; сообщения с отсутствующими файлами (с причиной из выгрузки); общий размер файлов; что будет пропущено и почему (служебные без пользователя, неподдерживаемые виды); ответы без цели; реакции — сколько по счётчикам, сколько с именами и сколько будет перенесено; число участников; число сообщений с датой правки; таблицу авторов «кто из выгрузки → какой аккаунт Pluma» с именем аккаунта из базы (её нужно прочитать перед переносом). Код выхода не 0, пока есть ошибки. Текст сообщений не печатается.

### 5. Перенести
```
DC run --rm --no-deps -v /srv/pluma-import/<имя>:/import:ro bff ./pluma-admin -f=../etc2/bff.yaml import-chat run -dir /import -storage-dir /import
```
- `-storage-dir` — каталог на диске хранилища (сама папка выгрузки, если она на том же диске), либо `-free-bytes <байт>`: команда проверяет, что места хватит на файлы (размер × 2,2 плюс 5 ГиБ).
- Пока идёт перенос, группы ни у кого нет: уведомлений и событий клиентам нет.
- **Оборвалось** (сеть, перезапуск, выключение) — запустить ту же команду ещё раз: продолжит с места остановки, без дублей и повторной загрузки файлов.
- `import-chat status -dir /import` — состояние и счётчики; `import-chat abort <id>` — отменить незавершённый перенос и удалить недоделанную группу.
- В конце команда делает создателя участником, добавляет остальных и печатает итог. Каждый участник получает группу в списке чатов с одним уведомлением «добавил(а) вас»; непрочитанного нет.
- Папку выгрузки после проверки можно удалить.

### 6. После переноса руками
Назначить админов, поставить фото группы, закрепить нужные сообщения — этого в выгрузке нет.

## Что переносится
- Сообщения с исходными датами, порядком и авторами; правки (отметка «изменено» с датой).
- Текст и разметка: жирный, курсив, подчёркнутый, зачёркнутый, код, блок кода с языком, цитата, спойлер, ссылки, упоминания, хэштеги.
- Фото, видео, GIF, файлы, музыка (исполнитель, название), голосовые (с волной, она считается заново), кружки, стикеры, спойлер на медиа.
- Ответы; пересылки (от кого).
- Опросы (с голосом выгружавшего, если указан `exporter`) и списки дел (без отметок), контакты, геоточки, места.
- Служебные: создание, смена названия и фото, добавление, выход и удаление участников, вступление по ссылке и по заявке, закрепление.
- Реакции, у которых выгрузка называет поставившего, — от его аккаунта Pluma, с исходной датой.
- Прочитанность: у всех всё прочитано; свои старые сообщения авторы видят прочитанными; упоминаний и реакций «непрочитано» нет; голосовые и кружки прослушаны.
- Поиск, календарь, переход к дате, вкладки медиа работают по перенесённой истории сразу.

## Что не переносится и почему
| Что | Почему |
|---|---|
| Кто что прочитал и прослушал | В выгрузке этого нет вовсе (`Data::Message`, `export_data_types.h:1286-1315`). Поэтому результат — «прочитано у всех». |
| Реакции сверх названных поимённо | Выгрузка пишет счётчик `count` и только тех, кого Telegram сам вернул в `recent_reactions`; полного списка она не запрашивает (`export_data_types.cpp:1259-1296`). Реакция без автора в Pluma невозможна, чужим именем её подписывать нельзя. `plan` покажет оба числа до переноса. |
| Реакции своими эмодзи, свои эмодзи в тексте | Вместо id эмодзи в выгрузке путь к файлу (`export_api_wrap.cpp:2614-2681`). В тексте остаётся обычный эмодзи-замена; реакция не переносится. |
| Альбомы | Признака альбома в выгрузке нет: фото идут отдельными сообщениями подряд. |
| Что закреплено сейчас | Есть только служебные «закрепил(а)». |
| Дата оригинала у пересланного, цитата в ответе | Не записаны в JSON. |
| Голоса опросов по людям, вид опроса (викторина) | В выгрузке только числа и голос самого выгружавшего. |
| Админы и права | Списка участников в выгрузке нет. |
| Набор у стикера | Стикер переносится как картинка-стикер без набора. |
| Сообщения ботов с кнопками, игры, счета, розыгрыши, звонки, подарки | Нет соответствия в перенесённой группе; текст сохраняется, кнопки нет; остальное пропускается и перечисляется в `plan`. |
| Темы форума | У сообщений в выгрузке нет темы: форум переносится обычной группой. |
| Превью ссылок | В выгрузке их нет; заново при переносе не строятся. |
| Служебные «группа стала супергруппой» | Переход внутри одной перенесённой группы; `messageActionChannelMigrateFrom` называет id обычной группы, которой в Pluma нет. |
| Признак «правка скрыта» | Выгрузка пишет `edited` из `edit_date`, не глядя на `edit_hide` (`export_data_types.cpp:2910-2912`): отметка «изменено» появится у всех сообщений с датой правки, включая те, где клиенты Telegram её не показывали. `plan` печатает их число. |
| Вложенная разметка (жирная ссылка) | Выгрузка пишет каждому куску текста один вид. |
| Файлы больше предела выгрузки, исчезающие медиа | Их нет в папке. `plan` перечисляет; `run` без `-missing-media=skip` не начнётся. |

## Решения, требующие подтверждения
1. Реакции только с именами; число без имён не переносится (сколько это — покажет `plan`).
2. Закреп не восстанавливается, альбомы — отдельными сообщениями.
3. Опросы без чужих голосов; открытые остаются открытыми.
4. В конце истории — служебное «владелец добавил …» с сегодняшней датой и одно уведомление каждому.
5. `"skip": true` для автора — допустимое явное решение в файле соответствий.
6. Если потеря реакций по `plan` существенна — отдельная задача на дополнение через TDLib.
7. Отметка «изменено» ставится всем сообщениям, у которых в выгрузке есть дата правки: скрытые правки Telegram (`edit_hide`) выгрузка не отличает от настоящих (ADR 0051, решение 11).

## Открытые вопросы исполнителю — ответы
- **Сколько записей Telegram кладёт в `recent_reactions`** — не проверено и на код не влияет; `plan` показывает на настоящей выгрузке оба числа.
- **Свободное место Garage.** Admin API не используется (поле не проверено, токена в контейнере `bff` нет). Оператор даёт `-storage-dir` или `-free-bytes`; без них перенос с файлами не начинается.
- **Отмена и загруженные файлы.** Канал помечается удалённым, файлы остаются в хранилище и в `channel_import_media`; повторный перенос того же чата их использует. Очистки нет.
- **Канал без участников.** Запросы идут от строк участников и диалогов, которых нет; подробности — ADR 0051, «Последствия».
- **Каталог свежих эмодзи для реакций** — сверка невозможна: id документа в выгрузке нет.

## Результат
Сделано целиком (2026-11-12): `pluma-admin import-chat` переносит выгрузку группы из Telegram Desktop в новую закрытую супергруппу Pluma. Сообщения стоят от сопоставленных аккаунтов с исходными датами; файлы загружены обычным путём `dfs`/`media`; ответы, пересылки, правки, опросы, списки дел, служебные сообщения и поимённые реакции перенесены; у всех участников история прочитана, голосовые и кружки прослушаны. Несопоставленный автор останавливает перенос до первой записи. Перенос продолжается той же командой после сбоя на любом шаге. Пока он идёт, у группы нет участников и клиенты не получают ни одного события.

Отклонения от проекта (все — в ADR 0051):
- миграция называется `migrate-20261114-channel-imports.sql`, чтобы идти после уже применённых;
- RPC пять, а не три: добавлены `channel.importGetState` и `channel.importAbort`; сообщение 1 приходит в `importCreate`;
- миниатюры из выгрузки не загружаются: `dfs` делает свои;
- загруженные файлы запоминаются по исходному чату, а не по переносу: после отмены повторный перенос их не грузит;
- соответствия авторов хранятся в переносе и сверяются при продолжении (`IMPORT_MAPPING_CHANGED`);
- место в хранилище даёт оператор (`-storage-dir` или `-free-bytes`), запроса к Garage нет; множитель 2,2, потому что `dfs` держит части загрузки около трёх часов;
- `migrate_from_group` не переносится (как и `migrate_to_supergroup`);
- в файле соответствий появилось поле `exporter` (чей голос в опросах) и подкоманда `import-chat accounts`.

Проверка (CachyOS, 2026-11-12, всё зелёное):
- `go build ./...`; `go vet -tags integration,e2e -unreachable=false ./...`; `make lint` — 0 замечаний;
- `go test` и `go test -race`: `pkg/tgexport`, `pkg/channelcontents`, `app/service/biz/channel/...`, `tools/pluma-admin`; `go test ./tools/...` (включая `logaudit` и `boxaudit`); `go test` для `app/messenger/sync`, `app/messenger/msg`, `app/bff` (те, кто импортирует затронутое);
- интеграционные на MySQL: `TestImportHistory`, `TestImportAgain`, `TestImportAbort`, `TestContents*`, `TestInvite*` в `app/service/biz/channel/internal/core`;
- e2e на стенде: `TestImportChat` (отказ при неполном соответствии, убитый после первой транзакции перенос и продолжение, чтение тремя участниками, сообщение после переноса);
