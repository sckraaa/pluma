# 109. Доступ к Pluma отовсюду без VPN: весь трафик клиентов через CDN

- Статус: todo (большая задача; сначала исследование и ADR)
- Решение: будет ADR.
- Зависит от: 092 (замеры доступности из России), 107 (HTTPS-CDN на Gcore — аккаунт, ресурс, опыт подписи и источника), ADR 0057 и 0061 (дом — ядро, VPS — труба для шифра).
- Поставлена владельцем 2026-11-16: «важно, чтобы клиенты могли заходить откуда угодно, даже там, где блокировки, без VPN».

## Цель
Клиенты Pluma подключаются к серверу не к адресу VPS, а к большому CDN, как к обычному HTTPS-сайту. CDN — только труба: внутри TLS идёт трафик MTProto, который и так зашифрован ключом авторизации между клиентом и домом. Содержимое CDN не видит, как сейчас не видит VPS.

## Что это решает и что нет (оценка 2026-11-16, проверить исследованием)
- **Решает:**
  - блокировку и замедление по IP адресу VPS. Задача 092: подсети Hetzner из России «замораживаются» после ~16 КБ, HTTPS pluma.chat прошёл с 3 из 30 точек. Адреса CDN общие с огромным числом сайтов, блокировать их дорого;
  - блокировку по сигнатуре протокола (MTProto, VPN-протоколы): снаружи это обычный TLS к CDN.
- **Не решает или решает частично:**
  - мобильные «белые списки» в России — проходят только адреса из списка. Нужен российский CDN с адресами из списка, а это пока не проверено;
  - целевую блокировку нашего имени по SNI — для закрытого сервиса на 100 человек маловероятна, но возможна;
  - звонки — им нужен UDP, CDN его не проксирует; звонки остаются на VPS, сюда смежный вопрос TURN по TLS.
- Скорость отдачи по-прежнему ограничена домашним каналом; быстрее станет подключение, и пропадёт замедление Hetzner.

## Что исследовать
1. **Транспорт клиентов, который CDN умеет проксировать:**
   - Web K уже ходит по WebSocket;
   - нативные клиенты (Android, iOS, Desktop) ходят по TCP; есть ли у них HTTP- или WebSocket-транспорт; «WEB-прокси» из Telegram 13.2 (tdesktop 7.1+, Android `WebProxyTransport.java`, iOS `.web` в `ProxySettings.swift`) — что это на проводе и можно ли направить его на наш CDN;
   - какой патч клиентов нужен и сколько он стоит.
2. **Провайдеры:** WebSocket и долгие соединения на бесплатных и дешёвых тарифах (Gcore, Cloudflare и другие), таймауты простоя, лимиты, условия использования.
3. **Россия:**
   - замеры из российских сетей до кандидатов, мобильные сети отдельно;
   - российский CDN с адресами из «белых списков» для режима белых списков.
4. **Конфиденциальность:** что видит CDN-провайдер — адреса, время, объёмы, содержимого нет; влияние на ADR 0057.
5. **Устойчивость:** запасные пути, если CDN недоступен (прямой адрес VPS как сейчас, второй провайдер), и как клиент между ними выбирает.

## Не в задаче
- Звонки (UDP) — отдельно.
