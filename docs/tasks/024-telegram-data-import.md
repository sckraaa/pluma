# 024. Импорт данных Telegram

- Статус: in-progress (2026-11-02)
- Зависит от: —
- ADR: [0028](../adr/0028-telegram-catalog-import.md); исследование — [024-research/](024-research/README.md)

## Цель
Данные, которые у Telegram есть, а у Pluma нет, в Pluma: реакции, стикеры, анимированные эмодзи, подсказки эмодзи, цвета, темы, обои, эффекты, эмодзи-статусы и списки эмодзи по умолчанию. Сервер отдаёт их теми же методами, что Telegram.

## Решения владельца
- Стикеры, подарки и прочее — выкачать с серверов Telegram, в идеале всю базу (2026-10-30).
- id документов и наборов **перенумеровать**: id выдаёт Pluma, ссылки на id Telegram не хранятся (2026-10-30).

## Область
- **Сборщик.** Скачивает из Telegram ответы методов и все документы (`upload.getFile`), перекладывает файлы в dfs, выдаёт новые id и переписывает все ссылки на документы и наборы внутри данных.
- **Аккаунт для выгрузки.** Каким аккаунтом и каким клиентом выгружать, решить в ADR. Сторонний вход с запасного аккаунта Telegram однажды привёл к сбросу ключа (задача 019); не повторять без владельца и не чаще раза в сутки.
- **Обработчики** этих методов, с `hash` и `NotModified`, как у Telegram.
- **Обновление** данных по команде или по расписанию.
- **Реакции.** Импорт даёт список; хранение реакций на сообщениях и обновления — этап 2.

## Критерии приёмки
- Ответы перечисленных методов по форме и количеству совпадают с эталоном: сравнение методов.
- В Android, iOS и Web K видны анимированные эмодзи, панель стикеров с популярными наборами, подсказки эмодзи, цвета имени и профиля, темы и обои.

## Результат

## Ход работы
- 2026-11-02: исследование (сервер, семантика методов и клиенты, выгрузка через Web K) и ADR 0028. Проверено: встроенный браузер не пускает web.telegram.org на `127.0.0.1`, поэтому приёмник выгрузки — временный, на сервере по HTTPS.
- **Решения на подтверждение владельцем:**
  1. Канал выгрузки: временный приёмник `pluma.chat/collect` на сервере (предложено) или Chrome владельца с приёмником на Mac.
  2. id Telegram, прописанные в клиентах: оставить их у этих документов, поправить клиентов или принять потерю.
- 2026-11-02: путь импорта документов (`e729dfa3`). `dfs.importDocument` сохраняет файл и данные миниатюры как есть: `i`/`j` встроенные, остальные — из своих загруженных частей, каждая со своим файлом. Всё лежит в хранилище до ответа, `access_hash` несёт тип хранения. `media.importDocument` пишет строки: миниатюры раньше документа, ошибки возвращаются. Попутно исправлено чтение в media (`a2aa9b5c`): размеры progressive-фото терялись, отсутствующий документ ронял сервис.
- 2026-11-02: `pkg/catalog/tl` (`d0736e18`, `c75904ae`). Объекты tweb сериализуются обратно в байты TL по схеме слоя 228 (`api.tl` tdesktop v7.0.9) и декодируются кодеком сервера, без угадывания полей по именам. Проверено на настоящем ответе `messages.getAvailableReactions` (74 реакции, `hash` 1046478762): `file_reference` и байты миниатюр tweb отдаёт массивами чисел, `long` — числом или строкой. Каждый из семи документов реакции ссылается на свой отдельный набор (`inputStickerSetID`), поэтому выгрузка забирает и все наборы, на которые ссылаются данные. Миграция каталога (`catalog_answers`, `catalog_sticker_sets`, `catalog_documents`) написана, не закоммичена.
- 2026-11-02: хранилище каталога (`20877242`, `4a2f5bbb`) и модуль `app/bff/catalog` (`719bb797`). 12 служб маршрутизированы в bff, 39 методов отвечают из каталога с `hash` и `NotModified`. Пока каталог пуст, они дают пустые списки с `hash = 0`, без ошибок. Личные списки аккаунта пусты до этапа 2. Остальные методы этих служб — `ErrEnterpriseIsBlocked`, подмены прокси для них удалены. `getCustomEmojiDocuments` отдаёт только документы каталога. Покрытие API: 211 ok (24,3%). Ветка в CI.
- 2026-11-02: импорт готов (`ef70106f`, `4f4adf33`, `68f49441`): `pkg/catalog/importer` и `pluma-admin catalog import <каталог>`.
  - **Формат выгрузки** — `importer.Manifest`: ответы методов, наборы с видом, документы только по id, обои по слагу, файлы документов и миниатюр.
  - **Перенумерация.** Обход protobuf. Ссылка на то, чего нет в выгрузке, — ошибка.
  - **Документы.** Повторный импорт не загружает файл заново: документ узнаётся по `catalog_documents`.
  - **Хэши.** Реакции — по формуле core.telegram.org/api/reactions; на ответах Telegram от 2026-11-02 формула дала ровно его хэши (−5948247740602425726 и −2068317817079727459). Популярные наборы — по алгоритму клиентов, обои — по id, остальное — по содержимому.
  - **Проверка.** Тест импорта проверяет, что в сохранённом не осталось ни одного id Telegram; без поля `EmojiList` в списке он падает. e2e импортирует набор, реакцию и список эмодзи и скачивает стикер и миниатюру по новым id.
  - **Осталось:** приёмник выгрузки и скрипт выгрузки (ждут решения о канале), выгрузка, импорт, проверка в клиентах, `docs/ops/catalog.md`.
- **Импорт (спроектирован, см. выше; `pkg/catalog/importer` + `pluma-admin catalog import`):**
  1. Прочитать выгрузку и декодировать каждый объект через `pkg/catalog/tl`.
  2. Собрать все документы и наборы. Набору — id Pluma: прежний по `short_name` или новый, плюс новый `access_hash`.
  3. Каждый документ: ключ — sha256(файл) и `short_name` его набора. Есть в `catalog_documents` — взять id. Нет — части файла и миниатюр в `dfs.writeFilePartData`, затем `dfs.importDocument`, `media.importDocument`, `PutDocument`.
  4. Переписать ссылки обходом protobuf-объектов. Документы заменяются целиком. Переписываются `inputStickerSetID`, `stickerSet` (id, `access_hash`, `thumb_document_id`) и числовые поля id: `StickerPack.documents`, `EmojiList.document_id`, `EmojiStatus.document_id`/`pattern_document_id`, `AvailableEffect.static_icon_id`/`effect_sticker_id`/`effect_animation_id`, `Reaction.document_id`, `EmojiGroup.icon_emoji_id`/`document_id`, `StickerKeyword.document_id`, `Messages_FeaturedStickers.unread`. Обои и темы получают id и `access_hash` Pluma, устойчиво по `slug`. Ссылка на то, чего нет в выгрузке, — ошибка.
  5. Хэши. Где клиент считает хэш сам (`getFeatured*`, tdesktop `CountFeaturedHash`), — по его алгоритму на наших id. Где клиент возвращает хэш сервера, — по содержимому ответа.
  6. `Store.Replace` одной транзакцией.
- **План:** хранилище каталога и импорт документов в dfs/media → приёмник и скрипт выгрузки → импорт с перенумерацией → обработчики методов → выгрузка, импорт на стенде, проверка в клиентах → прод.
