# 055. Каналы после проверки владельцем: возврат, удаление, вступление, пуши, поиск, превью

- Статус: done (сервер; проверка в клиентах — владельцем после выкатки)
- Зависит от: 035–044 (каналы, ADR 0034), 027 (карточки ссылок, ADR 0027), 009 (пуши)
- Ссылки pluma.chat вместо t.me (QR приглашения ведёт в Telegram, страница `/+hash` в браузере) — задача 026, следующая после этой.

## Отчёт владельца (2026-11-04, Android)
1. После выхода из приватного канала нельзя вернуться по той же ссылке.
2. Удаление приватного канала: канал пропадает только у удалившего; у второго участника остаются канал, посты и первый аккаунт в подписчиках.
3. После вступления по ссылке из диалога канал не открывается сразу (нужно выйти в чаты или нажать ссылку ещё раз).
4. Уведомления о постах приватного канала не приходят, когда приложение смахнуто (проверить код, не телефон).
5. Превью ссылок с картинками не работают (YouTube: «- YouTube», общий текст, без картинки).
6. Глобальный поиск не находит публичный канал.

## Причины (разбор 2026-11-04: исследователь на каждую проблему и скептик на каждый вывод; клиенты на `aac1efcb`, `6ad963e5`, `a1e89e1f`)
1. **Возврат.** Вступление по ссылке пишет в `chat_invite_participants` простым `INSERT` (`biz/channel/internal/dao/membership.go:209`), а у таблицы `UNIQUE (link, user_id)` (`1_teamgram.sql:866`); выход строку не убирает. Повтор той же ссылки — ошибка MySQL 1062, вся транзакция откатывается, клиент получает 500 и показывает «группа не существует» (`AlertsCreator.java:521-539`). У базовых групп та же запись уже сделана upsert'ом (`biz/chat/internal/dao/chat_box.go:46-47`). Telegram такой ошибки не знает (core.telegram.org/method/messages.importChatInvite).
2. **Удаление.** `channels.deleteChannel` не обслуживается: `bff/channels/internal/core/not_served.go:43-46` → `ERR_ENTERPRISE_IS_BLOCKED`. Android удаляет диалог у себя до запроса и молча глотает ошибку (`MessagesController.java:15865-15869`, `:15917-15922`); iOS при ошибке пробует `leaveChannel`, а создателю это `USER_CREATOR`. Telegram удаляет канал у всех (core.telegram.org/method/channels.deleteChannel; ошибки `CHANNEL_INVALID`, `CHANNEL_PRIVATE`, `CHAT_ADMIN_REQUIRED`, `CHANNEL_TOO_LARGE`).
3. **Вступление не открывает канал.** Android шлёт старые конструкторы `messages.importChatInvite#6c50051c` и `channels.joinChannel#24b524c5`, но разбирает ответ как `messages.ChatInviteJoinResult` (`TLRPC.java:53439-53452`, `:56623-56630`, слой 228). Наш сервер отвечает на них голым `Updates`; Android не разбирает ответ, пишет `FileLog.fatal` и не вызывает колбэк (`ConnectionsManager.java:416-423`), поэтому `JoinGroupAlert` не открывает чат (`JoinGroupAlert.java:338-376`). Вступление на сервере при этом проходит. Тот же сбой — у `joinChannel` из профиля и у ссылок базовых групп.
4. **Пуши каналов.** Посты каналов до сервиса пушей не доходят вовсе: пуш-потребитель Sync-T понимает только `pushUpdates`/`updatesNotMe`/`updatesMe` и отбрасывает `sync.pushChannelUpdates` (`messenger/push/internal/server/mq/mq.go:48-64`, `:79-82`); раздача по участникам идёт в процессе sync только живым сессиям; сборщик уведомлений не знает `updateNewChannelMessage` и `peerChannel` (`push/internal/notify/notification.go:135-163`, `:231-238`). Это пробел сервера, не телефона.
5. **Превью YouTube.** С адреса сервера (Hetzner) YouTube отдаёт пустую страницу: `<title> - YouTube</title>`, без og-тегов (проверено с сервера 2026-11-04). Наш разборщик честно строит из неё карточку «- YouTube» без картинки и кэширует на сутки (`pkg/webpage/parse.go:161-176`, `build.go:90-92`, `service.go:41,157`). oEmbed YouTube с того же адреса отвечает нормально.
6. **Поиск.** `contacts.search` находит канал по username, но оставляет только пользователей (`bff/contacts/internal/core/contacts.search_handler.go:101-105`), `Chats` в ответе всегда пуст, у bff контактов нет клиента каналов; флаги `broadcasts`/`bots` не читаются.

## Область
1. Возврат: upsert строки приглашения; интеграционный тест «вступил по ссылке → вышел → снова по той же ссылке», и «исключён → разбанен → снова».
2. Удаление: `channels.deleteChannel` целиком — проверки (создатель, размер, удалён ли), в одной транзакции канал `deleted`, участники выходят, диалоги удаляются, имя освобождается, приглашения отзываются; всем участникам — обновление канала (канал недоступен), клиенты убирают его. Ответы после удаления: `CHANNEL_PRIVATE`/`CHANNEL_INVALID`.
3. Вступление: в bff-прокси переписать старые конструкторы Android на новые (`importChatInvite#de91436e`, `joinChannel#7f6a1e22`), как уже делается для других старых конструкторов Android; ответ `messages.chatInviteJoinResultOk`.
4. Пуши: сервис пушей принимает событие канала, раздаёт уведомления участникам, кто видит пост, с учётом их настроек; формат Android `CHANNEL_MESSAGE_*`/`custom.channel_id`, iOS — как для групп.
5. Превью: распознавание выдачи без og-тегов у YouTube и запасной путь через oEmbed (название, автор, картинка, `embed_url`, тип video); выродившаяся карточка любого сайта кэшируется коротко.
6. Поиск: публичные каналы в `contacts.search` (`results`/`my_results`, `chats`), флаги `broadcasts` и `bots`.

## Решения на подтверждение
- Повторное вступление по ссылке считается ещё одним использованием (`usage_limit`) — так уже у базовых групп. Как считает Telegram — не проверено.
- Имя удалённого публичного канала освобождается сразу. Как у Telegram — не проверено.

## Результат
Все шесть проблем из отчёта владельца исправлены на сервере; клиенты не менялись. Ссылки `pluma.chat/+…` (QR приглашения, страница в браузере) — задача 026, следующая.

- **Возврат по ссылке** — строка приглашения пишется upsert'ом; интеграционный тест «вступил по ссылке → вышел → снова по ней» и «исключён → разбанен → снова» (`TestRejoinByLink`), e2e (`TestChannelRejoinAndDelete`).
- **Вступление открывает канал** — bff-прокси переписывает старые конструкторы Android (`importChatInvite#6c50051c`, `joinChannel#24b524c5`) на новые, ответ которых Android читает (`messages.chatInviteJoinResultOk`); юнит-тест подмены и маршрутов. Касается и ссылок базовых групп, и вступления в публичный канал из профиля.
- **Удаление канала** — `channels.deleteChannel` целиком (ADR 0034, дополнение): канал помечается удалённым, все выходят, имя и ссылки освобождаются, каждый участник через своё событие ящика получает `updateChannel` с `channelForbidden` и теряет диалог; чтение удалённого — `CHANNEL_PRIVATE`. Интеграционный тест (`TestDeleteChannel`) и e2e.
- **Пуши каналов** — сервис пушей раздаёт событие канала участникам (кроме автора): посты `CHANNEL_MESSAGE_*` с одним `channel_id`, супергруппы `CHAT_*` с `channel_id` и `chat_from_id`, `READ_HISTORY` для прочитанного; без звука — по настройке канала или классу (`docs/ops/push.md`). Юнит-тесты полезной нагрузки Android/iOS, раздачи и отключения звука.
- **Превью YouTube** — карточка из oEmbed, когда YouTube отдаёт серверу пустую страницу (ADR 0027, дополнение); карточки «голой» страницы живут 6 часов. Тесты на подставном сервере.
- **Поиск** — `contacts.search` находит публичные каналы по username (`results`/`my_results`, `chats`), флаги `broadcasts` и `bots`; исключение контактов в SQL — только для пользователей, `LIKE` буквальный. Юнит- и интеграционный тест.
- **Попутно** — гонка за имя канала (выкачено ранее): исправлено в задаче 054.
- **Проверка:** `go build`, `go vet`, `go test` затронутых пакетов, `make lint` — зелёные; интеграционные и e2e — в CI ветки `task/055-channel-fixes`.
- **Не проверено:** коды ошибок Telegram после удаления канала и освобождение имени; поведение в клиентах — после выкатки, владельцем.
