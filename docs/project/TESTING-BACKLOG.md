# Что ещё не проверено в клиентах

Всё из этого списка реализовано на сервере и прошло автоматические проверки (сборка, vet, `-race`, модульные, интеграционные и сквозные тесты), но **ни разу не проверено в живых клиентах**. Владелец проверит всё вместе, одним проходом (решение 2026-11-09). До этого статус каждой строки — «не протестировано».

Проверять удобнее на Android и iOS, для шагов со вторым участником нужен второй аккаунт. Результат записывать рядом с пунктом: дата, клиент, что не так.

## Призрак @support (задача 080, ADR 0048)
Перед проверкой: `pluma-admin ghost set @support on`.
- [ ] Обычный участник частной супергруппы пишет `@support помогите`: на телефоне поддержки (Android, iOS) приходит уведомление; чат появляется в списке, упоминание непрочитанное, видна вся история до упоминания; чат «без звука», а следующие упоминания и ответы поддержке уведомляют.
- [ ] У остальных участников той же группы (Android, iOS, Desktop, Web): число участников в шапке и в профиле не изменилось, в списке участников и в подсказке «@» поддержки нет, служебного «присоединился» нет, «в сети» не изменилось, в «Недавних действиях» входа нет.
- [ ] Поддержка отвечает в этой группе: у участников ответ с галочкой; нажатие на имя открывает профиль; удаление её сообщения админом и бан из меню сообщения работают (Android, Desktop).
- [ ] Поддержка ставит реакцию на сообщение в группе: реакция видна всем.
- [ ] Публичный канал с обсуждением: поддержка, не подписанная на канал, открывает комментарии к посту и пишет комментарий; в списке подписчиков канала и участников обсуждения её нет, счётчики прежние; ответ на её комментарий приходит ей уведомлением.
- [ ] «Прочитали» у своего сообщения в супергруппе: поддержка, прочитавшая его, в списке не появляется; у автора нет второй галочки от её прочтения.
- [ ] Просмотры поста канала: открытие поста поддержкой не увеличивает счётчик.
- [ ] Пригласить поддержку в супергруппу или канал и в обычную группу, назначить её админом — «нельзя добавить из-за настроек приватности» (Android, iOS, Desktop).
- [ ] `pluma-admin ghost join @support t.me/+…` в частный чат: чат появляется у поддержки (все клиенты), у участников ничего не меняется; `ghost leave` убирает его у поддержки.
- [ ] `pluma-admin ghost set @support on` для аккаунта, уже состоявшего в чатах: в них счётчики уменьшились на 1, поддержки нет в списках; `off` возвращает.
- [ ] Обычная (не супер-) группа: участник пишет `@support помогите` — у поддержки уведомление, чат в списке «без звука», видна вся история группы до упоминания, упоминание непрочитанное (Android, iOS, Desktop, Web).
- [ ] Обычная группа: два участника почти одновременно пишут `@support`, затем сразу третье сообщение с упоминанием — у поддержки уведомление о каждом упоминании, все три сообщения непрочитанные после истории, ни одно не пропало и не задвоилось.

- [ ] Создать обычную группу, выбрав поддержку среди участников: группа создаётся без неё, клиент показывает «нельзя добавить из-за настроек приватности» (Android, iOS, Desktop, Web); добавить поддержку в существующую обычную группу — то же.

- [ ] Номер поддержки (+77777777777): в профиле поддержки номер не показан никому, в том числе тому, у кого номер записан в контактах телефона (Android, iOS, Desktop, Web); поиск по номеру и импорт контакта с этим номером поддержку не находят (клиент предлагает пригласить).
- [ ] Отправить в чат карточку контакта с номером поддержки (вложение «Контакт», ввести номер вручную): у отправителя и получателя карточка без кнопки «Написать»/«Открыть профиль», как у номера без аккаунта (Android, iOS, Desktop, Web).
- [ ] Админ обычной группы, где поддержки нет, удаляет её (через API или из профиля, открытого по `@support`): ответ без ошибки «не участник», у участников ничего не меняется; затем `@support` в этой группе не вводит поддержку.
- [ ] Поиск `@support` в глобальном поиске находит поддержку с галочкой; любой пользователь, не контакт, пишет ей в личку, даже если у поддержки в «Конфиденциальность → Сообщения» включено «только контакты»; голосовое сообщение ей тоже отправляется.

## Перенос группы из Telegram (задача 083, ADR 0051)
Перед проверкой: выгрузка группы из Telegram Desktop (JSON, все виды файлов, предел 4000 МБ), `import-chat map`, заполненный `mapping.json`, `import-chat plan`, `import-chat run` (`docs/ops/import-chat.md`). Проверять на всех четырёх клиентах, двумя участниками.
- [ ] (083) После `run` группа появилась в списке чатов у каждого участника с одним уведомлением «добавил(а) вас», без счётчика непрочитанного, без значков «@» и реакции.
- [ ] (083) Сообщения стоят от своих авторов (аватар, имя, свои — справа), с исходными датами; переход к дате и календарь показывают старые даты.
- [ ] (083) Свои старые сообщения видны прочитанными (две галочки).
- [ ] (083) Фото, видео, GIF, файлы, музыка открываются и скачиваются; стикеры показываются.
- [ ] (083) Голосовые играют, волна нарисована, синей точки «не прослушано» нет; кружки играют круглыми, точки нет. У участника, добавленного в группу позже, старые голосовые тоже без точки.
- [ ] (083) Ответы ведут к исходному сообщению; пересланные подписаны источником; у правленых стоит «изменено».
- [ ] (083) Реакции стоят от тех, кого назвала выгрузка; в списке «кто поставил» — они же.
- [ ] (083) Опрос показывается, голос выгружавшего на месте, проголосовать можно; список дел показывается.
- [ ] (083) Служебные из выгрузки («создал(а) группу», «изменил(а) название», «добавил(а)…», «закрепил(а)…») читаются нормально; нажатие на «закрепил(а)» ведёт к сообщению.
- [ ] (083) Поиск по группе находит старые сообщения; вкладки «Медиа», «Файлы», «Голосовые», «Ссылки» в профиле группы заполнены.
- [ ] (083) Новое сообщение после переноса приходит с уведомлением и счётчиком, как в любой группе.
- [ ] (083) Во время переноса большой выгрузки остальные чаты работают без задержек; после обрыва (`docker kill` контейнера команды) та же команда продолжает, дублей в группе нет.

## Известные баги клиентов Telegram (не наши, 2026-11-11)
- Android: в канале два кружка подряд; смотреть первый, открыть комментарии — включается второй; после выхода из комментариев видео кружка не идёт, играет только звук. Повторяется в официальном Telegram (проверено владельцем 2026-11-11). Патч клиента — только по решению владельца.
- iOS 12.9.2: запись кружка стартует через ~4 с и пишет ~3 с после «отправить». Причина в записи кружков Telegram-iOS 12.9.2; в 13.2 запись переписана — проверить после выпуска 13.2.

## @support: статус (2026-11-11, ADR 0048)
- [ ] У `@support` в шапке чата, профиле и списке чатов вместо «был(а) в сети» написано «служба поддержки» (Android, iOS, Desktop, Web); «в сети» не появляется, когда поддержка онлайн. Сам аккаунт поддержки свой статус видит как обычно.

## Антиспам групп, автоперевод каналов, геогруппы (задача 082, ADR 0050)
Перед проверкой: супергруппа с 10+ участниками (или счётчик участников поднят в базе), два аккаунта — админ и только что вступивший участник.
- [ ] Список администраторов группы: переключатель «Агрессивный антиспам» виден админу с правом удалять сообщения (Android, iOS, Desktop, Web); в группе меньше 10 участников он заблокирован с подсказкой; включение и выключение сохраняются, после перезапуска клиента состояние то же.
- [ ] Новый участник отправляет ссылку: у него и у всех сообщение исчезает через секунду-две (Android, iOS, Desktop, Web); обычный текст нового участника и ссылка админа остаются.
- [ ] «Недавние действия» группы: удаление показано как удаление антиспамом («Pluma Anti-Spam»), в фильтре админов есть антиспам (Android, iOS, Desktop); Web показывает событие удаления.
- [ ] Из меню этого события админ отмечает ложное срабатывание: Android показывает «модераторы рассмотрят жалобу», Desktop — тост, iOS — без ошибки; следующая ссылка того же участника остаётся; в панели модерации появилась жалоба «Ложное срабатывание антиспама» с текстом сообщения.
- [ ] Один и тот же длинный текст от старого участника в три группы за 10 минут: в группе с антиспамом, куда он пришёл третьим, сообщение удалено; в первых двух осталось.
- [ ] Профиль служебного аккаунта «Pluma Anti-Spam» открывается из «Недавних действий» без ошибки (Android, iOS, Desktop).
- [ ] Настройки вещательного канала: переключатель «Автоперевод» сохраняется вместе с остальной карточкой; в Desktop сохранение карточки больше не обрывается ошибкой; повторное сохранение без изменений не ругается (Android, iOS, Desktop, Web).
- [ ] Android: в настройках супергруппы нет пункта «Адрес» (геогруппа).

## Обновление iPhone из приложения (2026-11-11, задача 085)
Нужны две ad hoc-сборки подряд, `PLUMA_IOS_UPDATE_SECRET` на сервере и айфон со старой сборкой, поставленной с сайта.
- [ ] iOS 26: на экране обновления нажать «Обновить» — появляется системный вопрос об установке, новая сборка ставится поверх, сайт не открывается. Если установка висит на «Ожидание…», пока приложение открыто, — записать; тогда секрет очищается и основным способом остаётся сайт.
- [ ] iOS 18: то же.
- [ ] «Пропустить» на экране обновления: в течение суток (до 03:00 по Москве) экран не появляется снова — ни после перезапуска приложения, ни после возврата из фона.
- [ ] Новая сборка загружена, но ещё не переподписана (первая минута после CI): «Обновить» открывает страницу сайта `/iphone/install`, а не системную ошибку; после переподписи — установка из приложения.
- [ ] Сборка из TestFlight экран обновления не показывает.
- [ ] Отозвать выпуск в панели: экран обновления больше не появляется; с уже открытого экрана «Обновить» отозванную сборку не ставит (системная ошибка загрузки вместо установки).

## Внешний вид аккаунта, мелодии, заметки, ссылки на профиль (задача 084, ADR 0052)
Перед проверкой: два аккаунта (А и Б), Б добавил А в контакты; у А два устройства; каталог импортирован (цвета профиля, custom emoji).
- [ ] Цвет имени: А выбирает цвет в «Настройки → Оформление → цвет имени» (Android, iOS, Desktop). На втором устройстве А и у Б имя, ответы и превью ссылок А меняют цвет без перезапуска. Отдельно проверить первый цвет палитры (красный): после перезахода он остаётся красным, а не «цветом по умолчанию».
- [ ] Узор цвета имени (эмодзи в фоне ответа) и цвет профиля с узором: видны у Б в профиле А (Android, iOS, Desktop, Web). «Сбросить цвет профиля» возвращает обычную шапку на всех устройствах.
- [ ] Эмодзи-статус: А ставит статус навсегда и на час (Android, iOS, Desktop, Web). У Б значок рядом с именем А появляется сразу — в списке чатов, в чате, в профиле. Через час статус пропадает у обоих (в том числе после перезапуска клиента Б).
- [ ] Снять статус: значок пропадает у Б сразу.
- [ ] Недавние статусы: в окне выбора статуса сверху показаны последние поставленные, новые первыми; на втором устройстве А список тот же. Android: долгое нажатие → «Очистить недавние» очищает список на обоих устройствах.
- [ ] Окно выбора статуса на iOS и Desktop открывается без ошибок и без раздела коллекционных статусов.
- [ ] Своя мелодия: «Настройки → Уведомления → звук → Загрузить звук» (Android, iOS, Desktop), файл MP3 до 5 секунд — появляется в списке и проигрывается; на втором устройстве появляется без перезапуска.
- [ ] Мелодия из Ogg-файла (Desktop, Android): загружается, проигрывается на iOS.
- [ ] Мелодия длиннее 5 секунд и файл больше 100 КБ: клиент показывает понятное сообщение об ограничении, в списке ничего не появляется (Desktop, Android, iOS).
- [ ] Удаление мелодии из списка: пропадает на обоих устройствах.
- [ ] Android: «Сохранить для уведомлений» в меню короткого MP3-файла в чате — мелодия появляется в списке. Для голосового сообщения пункт ничего не добавляет (известное ограничение).
- [ ] Выбранная для чата мелодия играет на устройстве, где выбрана (Android, Desktop). Известное ограничение: на другом устройстве и в push на iOS звук стандартный.
- [ ] Заметка о контакте: Б пишет заметку в карточке контакта А (Android, iOS, Desktop, Web), с жирным текстом и эмодзи. Заметка видна в профиле А под «О себе» на всех устройствах Б и не видна А.
- [ ] Заметка длиннее 128 символов: клиент не даёт сохранить. Пустая заметка удаляет её. После удаления контакта и повторного добавления заметки нет.
- [ ] QR-код профиля: «Настройки → QR-код» (iOS), профиль → QR (Android, Desktop). Показан обратный отсчёт от 5:00, по истечении код меняется сам.
- [ ] Б сканирует QR-код А (или открывает ссылку `pluma.chat/contact/…`): открывается профиль А с кнопкой добавить в контакты (Android, iOS, Desktop, Web). Та же ссылка через 6 минут — «ссылка недействительна или устарела».
- [ ] Предложить день рождения: Б в карточке контакта А выбирает «Предложить день рождения» (Android, iOS, Desktop, Web). У А в чате карточка с датой и кнопкой; нажатие ставит день рождения в профиль А. Повторное предложение у Б — без карточки (у А уже есть дата).
- [ ] Автозагрузка: Android «Данные и память → Через мобильную сеть» выключить и включить, сменить ползунок; iOS — изменить лимит видео для сотовой сети. Ошибок нет, после перезапуска клиента настройки те же. Ползунки «Низкий/Средний/Высокий» на обоих клиентах не поменяли своих значений через сутки (проверить на следующий день).
- [ ] iOS: видео, отправленное по сотовой сети после изменения настроек автозагрузки, уходит в прежнем качестве (720p).
- [ ] Android: «Пригласить друзей» — в тексте приглашения ссылка `https://pluma.chat`, фраза на языке интерфейса и одна (без повтора).
- [ ] Исключения уведомлений: А выключает звук у Б, у группы и у канала. «Настройки → Уведомления → Личные чаты / Группы / Каналы → Исключения» (Android, iOS, Desktop): в каждом разделе только свои чаты, супергруппа — в группах.

## Свои наборы стикеров и эмодзи, поиск стикеров (задача 084, ADR 0053)
Перед проверкой: два аккаунта (автор и второй), у автора два устройства.
- [ ] Android: фото → «Создать стикер» → «Новый набор» с названием на русском: набор создан, открылся, стикер в нём; набор сразу виден в панели стикеров на обоих устройствах автора и на iOS/Desktop/Web без перезапуска.
- [ ] iOS: редактор стикера → «Создать набор»: набор создан и открылся; он есть в панели стикеров (сервер ставит его сам) и на втором устройстве.
- [ ] Android и iOS: «Добавить в набор» показывает список своих наборов (`getMyStickers`); полный набор (120) в списке Android не предлагается.
- [ ] Desktop: правый клик по чужому стикеру → «Добавить в свой набор»: стикер появился в конце набора; повторное добавление того же стикера — «уже в наборе», число стикеров не растёт.
- [ ] Видеостикер (Android, из видео) и анимированный `.tgs` (импорт на iOS): добавляются и проигрываются на всех четырёх клиентах; файл больше 256 КБ / длиннее 3 секунд отклоняется с понятной ошибкой, а не зависшей загрузкой.
- [ ] Ссылка `pluma.chat/addstickers/<имя>` у второго аккаунта открывает набор; кнопка «Добавить»; у второго аккаунта нет пунктов редактирования, у автора есть (Android, iOS, Desktop).
- [ ] Автор добавляет, удаляет, переставляет стикер, переименовывает набор: у второго аккаунта (набор установлен) изменения видны в панели без перезапуска на Android, iOS, Desktop, Web.
- [ ] «Заменить стикер» (Android, iOS): новый стикер стоит на месте старого; старый стикер в уже отправленных сообщениях по-прежнему показывается.
- [ ] Удаление последнего стикера (Android): набор исчезает из панели автора без ошибки; через «Добавить в набор» в него снова можно добавить стикер.
- [ ] «Удалить набор для всех»: набор исчезает из панели у автора и у второго аккаунта; ссылка на набор говорит, что набора нет; стикеры в старых сообщениях остались видны.
- [ ] Создание набора на iOS через импорт (приложение со стикерами): поле ссылки заполняется подсказкой, занятое имя помечено «занято», неверное — «неверно»; на Android в диалоге ссылки то же.
- [ ] Набор кастомных эмодзи (Desktop: добавить существующий эмодзи в свой набор; импорт 100x100): эмодзи вставляются в текст и видны у получателя на всех клиентах.
- [ ] Обложка набора из импорта iOS (у набора своя иконка): иконка видна в панели стикеров на Android, iOS, Desktop, Web, а не первый стикер.
- [ ] Поиск в панели стикеров по слову из названия своего набора и набора каталога: наборы находятся на Android, iOS, Desktop, Web; свои установленные идут первыми.
- [ ] Поиск стикеров по слову («кот», «cat») и по эмодзи: Desktop и Web показывают стикеры (сервер сам переводит слово в эмодзи), Android и iOS тоже; прокрутка подгружает следующую страницу.
- [ ] Панель эмодзи: категории кастомных эмодзи (Android, iOS, Web) показывают эмодзи из наборов, включая свои.
- [ ] Вкладка «Популярные»: после обновления есть значок непрочитанных; после просмотра он пропадает на этом устройстве и на втором устройстве того же аккаунта, после перезапуска не возвращается.
- [ ] Фото со стикером (редактор фото на Android/iOS, наложить стикер и отправить): у получателя в просмотре фото есть «Стикеры на этом фото», открывается набор (Android, iOS, Desktop, Web); фото из альбома — так же; пересланное фото — так же.

## Личные сообщения каналу (задача 084, ADR 0055)
Перед проверкой: вещательный канал, три аккаунта — владелец, админ с правом «Управлять личными сообщениями» и подписчик (лучше два подписчика). Сквозной тест `TestMonoforum` проходит на стенде (2026-11-12).
- [ ] Настройки канала → «Личные сообщения» (Android: «Предложения постов»): включить бесплатно — у канала появляется кнопка сообщения каналу; ползунка цены в звёздах нет или он на нуле (Android, iOS, Desktop, Web). Если цену удалось выставить больше нуля — должна прийти ошибка, а не тихое сохранение.
- [ ] В канале появилось служебное сообщение о включении личных сообщений; у подписчиков канал не «прыгает» и не теряет историю.
- [ ] Подписчик открывает чат с каналом (кнопка в канале) и пишет текст, фото, голосовое: сообщения видны ему как в обычном личном чате, имя и аватар — канала (все четыре клиента).
- [ ] У владельца и у админа с правом в списке чатов появляется чат личных сообщений канала со счётчиком непрочитанного; внутри — вкладки/список подписчиков, у каждого своя переписка (Android, iOS, Desktop, Web).
- [ ] Админ отвечает подписчику: у подписчика ответ приходит от имени канала (без имени админа), с уведомлением на телефон; у второго админа ответ виден в том же чате подписчика.
- [ ] Второй подписчик пишет каналу: первый подписчик не видит ни его сообщений, ни счётчиков, ни уведомлений; при активной переписке нескольких подписчиков сообщения у каждого приходят без пропусков и дублей (возможна задержка около секунды — отметить, если заметна).
- [ ] Отметки прочтения: админ открыл чат подписчика — у подписчика две галочки, у второго админа пропал счётчик; подписчик прочитал ответ — у админов две галочки на ответе.
- [ ] «Кто написал»: у админа в меню сообщения канала в личных сообщениях показан админ-автор (Android, Desktop, Web; iOS — если есть).
- [ ] Админ без права «Управлять личными сообщениями» видит чат с каналом как обычный подписчик (только свою переписку). Снять право у админа — чужие переписки пропадают у него сразу (после перезапуска клиента — точно).
- [ ] Ответ с цитатой на сообщение подписчика; правка и удаление своего сообщения с обеих сторон; админ удаляет сообщение подписчика; подписчик не может удалить ответ канала у всех.
- [ ] Админ удаляет всю переписку с подписчиком («удалить чат» в списке подписчиков): чат пропадает из списка у всех админов, у подписчика история очищается.
- [ ] Отметить переписку с подписчиком непрочитанной и снять отметку (Desktop, Android): видно у второго админа.
- [ ] Черновик админа в переписке с подписчиком появляется на втором устройстве админа и пропадает после отправки.
- [ ] Реакции в личных сообщениях ставятся с обеих сторон и показываются счётчиком; список «кто поставил» не открывается.
- [ ] Закрепить сообщение в переписке (админ): закреп виден только в этой переписке и у этого подписчика.
- [ ] Выключить личные сообщения: у подписчика поле ввода закрыто или отправка даёт ошибку, история остаётся; включить снова — те же переписки на месте.
- [ ] Закрытый канал: посторонний (не участник) не может открыть личные сообщения; публичный канал: может написать, не вступая.
- [ ] Удалить канал: чат личных сообщений пропадает из списка у владельца, админов и подписчиков сразу, без перезапуска клиента (все четыре клиента).
- [ ] Кнопка «Предложить пост» у подписчика: сейчас отправка даёт ошибку (не сделано) — проверить, что клиент не зависает и обычные сообщения рядом работают.
- [ ] Убрать чат с каналом из списка у подписчика и у админа (Desktop: «Покинуть группу» в меню чата): чат пропадает и не возвращается после перезапуска клиента; следующий ответ канала (или своё новое сообщение каналу) возвращает его. На Android, iOS, Web записать, какой пункт меню есть и срабатывает ли он.
- [ ] Поиск, вкладка «Медиа» и календарь внутри переписки с одним подписчиком у админа: находятся сообщения и медиа только этой переписки (Desktop, Android, iOS, Web).
- [ ] Подписчик набирает текст: у админов в чате личных сообщений видно «печатает», у другого подписчика — нет; админ набирает ответ — у подписчика «печатает» не появляется (имя админа не раскрывается).
- [ ] У подписчика в меню сообщения нет «Закрепить», в профиле чата с каналом нет «Изменить» и «Добавить участников»; у владельца «Закрепить» есть и работает.
- [ ] Android: у админа счётчик непрочитанных реакций у переписки подписчика обновляется сразу, без перезахода.

## Истории (задача 084, ADR 0054)

Нужны два аккаунта, добавленные друг другу в контакты, и третий — не контакт. Проверять на Android и iOS; Desktop и Web — просмотр.

**Публикация и лента**
- [ ] Опубликовать фото-историю «для контактов»: у контакта над списком чатов появляется кружок, у автора — «Моя история»; у не-контакта ничего нет, и в профиле автора кольца нет.
- [ ] Опубликовать видео-историю (со звуком и без): воспроизводится у зрителя, перемотка и предзагрузка работают.
- [ ] История с подписью, ссылкой и форматированием в подписи, с областью-реакцией, геометкой, ссылкой, погодой: всё нажимается у зрителя.
- [ ] Срок 6, 12, 48 часов в редакторе: история исчезает из ленты в срок (проверить хотя бы 6 часов), но остаётся в архиве автора.
- [ ] «Запретить пересылку и скриншоты»: у зрителя нет «Поделиться», пересылка в чат отказывает.
- [ ] Приватность «Близкие друзья» (зелёное кольцо), «Выбранные», «Все, кроме…»: исключённый не видит ни кружка, ни истории в профиле.
- [ ] iOS: «Все, кроме…» с исключённой супергруппой (группой, где больше 200 участников или с публичной ссылкой): её участники не видят ни кружка, ни истории; «Выбранные» с супергруппой — видят.
- [ ] Вторая история подряд: у зрителя кружок снова непрочитанный, счётчик сегментов верный.
- [ ] Потянуть список чатов вниз и вернуться: лента не мигает и не дублирует людей (ответ «не изменилось»).
- [ ] Лимит: после 100 активных историй клиент показывает экран лимита (можно не проверять вручную).

**Просмотр**
- [ ] Посмотреть историю контакта: кольцо гаснет на всех устройствах зрителя (второе устройство — без перезапуска).
- [ ] У автора: счётчик просмотров, список зрителей с временем, реакция зрителя в списке; поиск по имени и «Только контакты», сортировка «Сначала реакции».
- [ ] Реакция на историю (сердце и другая), снятие реакции; автор получает уведомление о реакции в приложении.
- [ ] Ответ на историю текстом и медиа: в чате сообщение с миниатюрой истории у обоих.
- [ ] Скрытый режим (Stealth): включить, посмотреть историю — автор зрителя не видит; посмотренное за последние 5 минут пропадает из списка зрителей; повторное включение недоступно час.
- [ ] Перенести истории контакта в архив (долгое нажатие на кружок → «Скрыть»): кружок уходит в архивный ряд, вернуть обратно.

**Скрыть мои истории от…**
- [ ] В списке зрителей своей истории (Android, iOS) «Скрыть мои истории от X»: X больше не видит ни кружка, ни историй (после обновления профиля или ленты), но пишет и звонит автору, а в «Заблокированных» его нет. «Показать мои истории» — всё возвращается.
- [ ] В настройке приватности новой истории (Android: «Скрыть мои истории от…», iOS — то же в выборе аудитории) отметить людей и сохранить: после перезапуска приложения список тот же; эти люди историю не видят.
- [ ] Заблокировать X, которому истории уже скрыты, и разблокировать: в списке зрителей и в профиле X у автора отметка «истории скрыты» не пропадает; на втором устройстве автора то же без перезапуска.
- [ ] Заблокированный пользователь не видит кольца на аватаре автора (в списке чатов, в профиле), хотя история «для всех».

**Профиль и управление**
- [ ] «Сохранить в профиль»: история видна в профиле после истечения; «Закрепить» до трёх историй вверху профиля, порядок сохраняется.
- [ ] Архив историй автора: видны все, включая истёкшие; открываются.
- [ ] Изменить подпись, медиа и приватность истории: у зрителя история обновляется; у того, кого исключили правкой, пропадает.
- [ ] Удалить историю: пропадает у зрителей и на втором устройстве автора.
- [ ] После удаления или истечения истории кольцо на аватаре автора гаснет без перезапуска: в списке чатов, в профиле, в чате (iOS и Desktop — отдельно, у них это держится на `stories_unavailable`).
- [ ] «Скопировать ссылку» у аккаунта с публичным именем: ссылка `pluma.chat/<имя>/s/<номер>` открывает историю в приложении; без имени клиент не предлагает ссылку или показывает ошибку.
- [ ] Репост чужой публичной истории в свою: у зрителя виден автор оригинала.

**Каналы**
- [ ] Создатель канала публикует историю от имени канала (выбор автора в редакторе); подписчик видит кружок канала в ленте и кольцо на аватаре канала в списке чатов.
- [ ] Админ с правом «Публиковать истории» публикует; админ без этого права и подписчик — нет (канала нет в списке авторов).
- [ ] У истории канала у всех виден счётчик просмотров и реакций; у админа — список реакций.
- [ ] Скрыть истории канала в архивный ряд и вернуть.
- [ ] Супергруппа: история от имени группы публикуется админом.

**Истории в чатах**
- [ ] «Поделиться» историей в личный чат и в группу: сообщение с историей открывается у получателя, которому она разрешена; у того, кому не разрешена, — «история недоступна». У автора счётчик пересылок растёт на одно сообщение, а пересылка, которую сервер отклонил, его не меняет.
- [ ] Упомянуть человека в подписи истории (@имя и через выбор из списка): ему приходит сообщение «упомянул вас в истории», история открывается.
- [ ] После удаления истории сообщения с ней показывают «история больше недоступна».

**Модерация**
- [ ] Пожаловаться на историю (меню истории): выбор причины, комментарий; в панели жалоба вида «История» со снимком, «Удалить» убирает историю.

**Старые клиенты**
- [ ] Клиент слоя 228 (старая сборка) видит истории, опубликованные клиентом слоя 233, и наоборот.

## Расшифровка голосовых (задача 090, ADR 0056)
Проверять после выкладки сервера с сервисом `stt` (`docs/ops/transcription.md`) и сборки клиентов, в которой кнопка снова показана (снятие патчей A-109, I-109, D-084, W-068) и есть метка «служебный аккаунт» — обе в одной сборке (решение владельца 2026-11-12). Сначала сервер и `stt`, потом клиенты: без движка Android запоминает у сообщения пустой текст навсегда. Пределов нет: ни длины записи, ни числа расшифровок.

**Android**
- [ ] Короткое голосовое на русском: «→A» — текст с пунктуацией за пару секунд.
- [ ] Кружок: «→A» — текст.
- [ ] Голосовое на 30 минут (записать или переслать): кнопка крутится, текст приходит сам, без перезахода в чат, целиком — конец записи в тексте есть.
- [ ] Одноразовое голосовое и одноразовый кружок (отправить со второго аккаунта): кнопки «→A» нет.
- [ ] Остановить `stt` (`docker compose … stop stt`), нажать «→A» на новом голосовом, подождать 5 минут, запустить `stt`: кнопка всё это время крутится, «слова не распознаны» не появляется, текст приходит сам.
- [ ] Переслать расшифрованное голосовое в другой чат и нажать «→A» там: текст сразу.
- [ ] Тишина или шум без слов: «слова не распознаны».
- [ ] Перезапустить приложение: текст показан без нового ожидания.
- [ ] Оценить расшифровку (палец вверх и вниз): вопрос исчезает, ошибки нет.
- [ ] Отложенное голосовое (здесь кнопка не скрыта): запрос завершается без зависания и без чужого текста.

**iOS**
- [ ] Короткое голосовое и кружок: «→A» — текст.
- [ ] Голосовое на 30 минут: текст приходит сам, целиком; надписи «слишком длинная запись» нет.
- [ ] Одноразовое голосовое и одноразовый кружок: кнопки нет.
- [ ] Остановить `stt`, нажать «→A», подождать 5 минут, запустить: текст приходит; кнопка не блокируется и не просит Premium.
- [ ] Пересланное расшифрованное голосовое в другом чате: текст сразу.
- [ ] 40 расшифровок новых записей подряд: ни одна не отклонена, замка на кнопке нет.
- [ ] Оценка: вопрос исчезает, ошибки нет.

**Desktop**
- [ ] Короткое голосовое и кружок: «→A» — текст.
- [ ] Голосовое на 30 минут: текст приходит сам, целиком; надписи «слишком длинная запись» нет.
- [ ] Одноразовое голосовое и одноразовый кружок: кнопки нет.
- [ ] Остановить `stt`, нажать «→A», подождать 5 минут, запустить: текст приходит без повторного нажатия.
- [ ] Пересланное расшифрованное голосовое в другом чате: текст сразу; у оригинала текст остаётся свой (у копий разные `transcription_id`).
- [ ] Оценка: вопрос исчезает, ошибки нет.

**Web**
- [ ] Короткое голосовое и кружок: «→A» — текст.
- [ ] Голосовое на 30 минут: текст приходит сам, целиком.
- [ ] Одноразовое голосовое и одноразовый кружок: кнопки нет.
- [ ] Остановить `stt`, нажать «→A» у кружка, подождать 5 минут, запустить: текст приходит (кружок ждёт без тайм-аута).
- [ ] Пересланное расшифрованное голосовое в другом чате: текст сразу.
- [ ] Оценка: вопрос исчезает, ошибки нет.

**Все клиенты и сервер**
- [ ] То же голосовое со второго аккаунта: текст сразу.
- [ ] Личный чат, «Избранное», группа, супергруппа, канал (автором и подписчиком).
- [ ] Два устройства одного аккаунта: длинное голосовое расшифровать на одном — на втором текст появляется сам или сразу по нажатию.

- [ ] Секретный чат: кнопки нет или запрос завершается без зависания.
- [ ] Во время 30-минутного голосового: `docker stats` — `stt` держится около 0,35–0,45 ГБ, bff не перезапускался (`docker compose … ps bff`).

## Почта восстановления облачного пароля (задача 091, ADR 0058)
Проверять после выкладки с `MAIL_API_KEY` и `MAIL_FROM` в `.env` (`docs/ops/email.md`). Адрес — свой ящик, который можно открыть.

**Все клиенты (Android, iOS, Desktop, Web)**
- [ ] Задать облачный пароль с почтой: письмо пришло на языке приложения, код из него подтверждает почту; в настройках пароля видна почта восстановления.
- [ ] «Отправить код снова» до минуты — «подождите», после минуты — новое письмо, старый код не подходит; отмена ожидающей почты убирает экран кода.
- [ ] Сменить почту на другую: новое письмо на новый адрес, после подтверждения в настройках новый адрес.
- [ ] Первый пароль с почтой, на экране кода ничего не вводить: в настройках «пароль не задан, ждёт подтверждения почты», вход на другом устройстве пароль не спрашивает; после ввода кода пароль включён и одно сообщение 777000 о смене.
- [ ] Первый пароль с почтой, на экране кода прервать установку (Android «Прервать», Desktop «Прервать», iOS «Сбросить»): ошибки нет, пароль не задан, код из письма больше не подходит.
- [ ] iOS и Web: первый пароль с почтой, на экране кода «Сменить почту», ввести другой адрес (через минуту после первого письма): ошибки нет, письмо на новый адрес, его код включает пароль.
- [ ] Выйти, войти по коду телефона, «Забыли пароль?» → письмо → код → новый пароль: вход прошёл, другие устройства остались и получили сообщение от 777000 «Облачный пароль сброшен» с устройством и местом.
- [ ] Неверный код пять раз — код сгорает, клиент предлагает отправить снова.
- [ ] Шаблон адреса при входе (`ab***@gmail.com`; на Android звёздочки под спойлером) и у аккаунта без почты — переход к сбросу.

**Android и Web**
- [ ] Восстановление с «пропустить» на экране нового пароля: пароль снят, вход прошёл.

**Почта**
- [ ] Письмо не в спаме у Gmail и Яндекса; в заголовках `dkim=pass`, `spf=pass`, `dmarc=pass`.
- [ ] Письмо на русском, английском и арабском (справа налево) выглядит ровно на телефоне и на компьютере.

## Групповые звонки (задача 093, ADR 0059)
Проверять после выкладки с SFU (`docker-compose.sfu.yaml`, сертификаты управления, открытые UDP и TCP порты SFU — `docs/ops/group-calls.md`). Нужны три-четыре аккаунта: создатель чата, участник, подписчик канала, кто-то вне чата. «Войти от имени канала» нет (решение владельца 2026-11-12), запись и трансляции не обслуживаются.

**Android**
- [ ] Начать звонок в супергруппе: экран звонка открылся, в чате строка «идёт звонок» с числом участников и аватарами, в истории «начат звонок».
- [ ] Войти со второго аккаунта из строки звонка: слышно в обе стороны в первые секунды, у говорящего подсвечивается аватар, список упорядочен по активности.
- [ ] Микрофон: выключить и включить себе; у других значок меняется сразу.
- [ ] Администратор выключает микрофон участнику: у того «выключен администратором», включить нельзя; «поднять руку» — администратор видит руку, даёт слово — участник включает микрофон и слышен.
- [ ] Администратор меняет громкость участнику — у всех; обычный участник меняет громкость и выключает звук другого — только у себя.
- [ ] Камера: включить — видно у остальных, переключить на заднюю камеру; плитка у других не замирает.
- [ ] Показ экрана: видно у остальных отдельной плиткой, остановка убирает её.
- [ ] Настройки звонка (администратор): «новые участники без микрофона», сменить название, ссылки для слушателя и для выступающего в публичной группе, сброс ссылки, пригласить участника чата.
- [ ] Выбор «войти от имени»: не предлагается, вход сразу от себя.
- [ ] Обрыв сети: включить авиарежим на 5–10 секунд — клиент сам возвращается в звонок, звук идёт; переход Wi-Fi → LTE без выхода из звонка.
- [ ] Выйти и войти снова; завершить звонок для всех — в истории «звонок завершён» с длительностью, строка в чате пропала.
- [ ] Качество: звук без провалов и эха за 5 минут разговора троих, видео с камеры у трёх участников; записать впечатление и сравнение с Telegram.

**iOS**
- [ ] Начать звонок в супергруппе и в базовой группе; строка звонка и служебные сообщения о начале и конце с длительностью.
- [ ] Войти со второго аккаунта: слышно в обе стороны, говорящий подсвечен, порядок списка по активности.
- [ ] Микрофон, «поднять руку», выключение администратором и слово от него — как на Android.
- [ ] Громкость участника от администратора и личная; личное выключение звука другого только у себя.
- [ ] Камера (передняя и задняя) и показ экрана (трансляция экрана iOS): видно у остальных, остановка убирает плитку.
- [ ] Действия администратора: название, «новые без микрофона», ссылки слушателя и выступающего, сброс, приглашение, завершение.
- [ ] «Войти от имени» не предлагается.
- [ ] Обрыв сети и переход Wi-Fi → LTE: возвращается сам; свернуть приложение на минуту — звонок продолжается.
- [ ] Запланированный звонок в канале: подписаться на начало, уведомление при старте, войти.
- [ ] Качество: звук и видео за 5 минут разговора троих; записать впечатление.

**Desktop**
- [ ] Начать звонок в супергруппе, войти со второго аккаунта: слышно в обе стороны, панель звонка в чате.
- [ ] Микрофон и горячая клавиша «нажми и говори»; «поднять руку»; выключение администратором и слово от него.
- [ ] Громкость участника из меню: от администратора — у всех, от обычного участника — только у себя.
- [ ] Камера и показ экрана (окно и весь экран): видно у остальных; закреплённое видео в большом размере чёткое, миниатюры не замирают.
- [ ] Администратор: название, «новые без микрофона», ссылки, сброс, приглашение участника, завершение звонка.
- [ ] Окно «войти от имени» не появляется или показывает простое подтверждение со своим аккаунтом.
- [ ] Отключить сеть на 10 секунд: звонок восстанавливается сам; перезапуск `sfu` на сервере (`docker compose … restart sfu`) во время звонка — клиенты возвращаются сами за несколько секунд.
- [ ] Качество: звук и видео у троих участников за 5 минут; записать впечатление.

**Web**
- [ ] Войти в звонок, начатый с другого клиента: слышно в обе стороны (в браузере роль ICE другая — проверить, что соединяется).
- [ ] Начать звонок из Web в супергруппе и в канале.
- [ ] Микрофон, «поднять руку», выключение администратором и слово от него.
- [ ] Камера и показ экрана из браузера: видно у нативных клиентов; видео нативных клиентов видно в Web.
- [ ] Администратор: название, «новые без микрофона», ссылки, завершение.
- [ ] Обрыв сети (отключить Wi-Fi на 10 секунд): возвращается сам.
- [ ] Качество в Chrome и Safari; записать впечатление.

**Все клиенты и сервер**
- [ ] Звонок в канале: подписчик входит слушателем, поднимает руку, администратор даёт слово; вход по ссылке выступающего — сразу с правом говорить, по ссылке слушателя — без.
- [ ] Камеры у трёх участников и показ экрана одновременно; ограничить канал одного получателя (например, 1 Мбит/с) — картинка у него падает в качестве, а не замирает.
- [ ] Сеть без UDP (заблокировать UDP на роутере или в файрволе телефона): вход по ICE-TCP, звук идёт.
- [ ] Вход двух клиентов одновременно в разных сетях (дом и LTE).
- [ ] Звонок на 30 минут: `docker stats` — память `sfu` не растёт, bff и sfu не перезапускались.
- [ ] Как клиенты показывают «звонки не настроены» (`GROUPCALLS_NOT_CONFIGURED`, SFU не задан) и отказ на включение сообщений в звонке (`GROUPCALL_NOT_MODIFIED`).
- [ ] Канал с «новые без микрофона»: администратор дал слово подписчику, подписчик говорит; перезапустить `sfu` — клиент подписчика возвращается сам и по-прежнему может говорить (слово не пропадает).
- [ ] Администратор выключает микрофон тому, кто показывает экран и включил камеру: показ экрана и камера у всех пропадают, у выключенного — сообщение, что экран и камеру нельзя без слова (Desktop: «MutedNoScreen»/«MutedNoCamera»), попытка снова показать экран отклоняется.
- [ ] Исключить участника из группы (и забанить в супергруппе или канале) во время звонка: за несколько секунд он пропадает из списка, у него звонок закрывается («нет доступа»), он больше ничего не слышит.
- [ ] Базовая группа: начать звонок, войти, завершить — строка звонка в чате у второго аккаунта появляется при старте, показывает участников и пропадает при завершении (на Desktop особенно: раньше могла остаться «идёт звонок»).
- [ ] Desktop: пригласить в звонок сразу участника группы и контакт не из группы — участник получает приглашение, даже если добавить второго в группу не удалось.
- [ ] Видео при потерях у отправителя (ограничить исходящий канал отправителя с потерями 3–5%): у получателей картинка не замирает, `sfu_retransmissions_total{result="upstream"}` растёт.
- [ ] Звонок больше чем с тремя говорящими (больше `LastN`): видео у получателей не падает в качестве само по себе, когда говорящие сменяют друг друга.
- [ ] Остановить контейнер `sfu` (`docker compose stop sfu`): через 2 минуты приходит `GroupCallsSFUDown`.

## Сквозное шифрование групповых звонков (задача 094, ADR 0060)
Проверять вместе с групповыми звонками выше, на сборках с патчами задачи 094 во всех четырёх клиентах. Нужны четыре аккаунта в одной супергруппе и один подписчик канала. Оператору — доступ к `pluma-admin calls show <id звонка>` (`docs/ops/group-calls.md`, раздел «Шифрование звонка: что смотреть»).

**Android**
- [ ] Сквозной вход в звонок супергруппы и в звонок канала (подписчиком): слышно в обе стороны, в звонке нет пунктов «запись» и «трансляция», выбора «войти от имени» нет.
- [ ] Эмодзи проверки: у Android те же эмодзи, что у остальных клиентов в этом звонке; после входа нового участника эмодзи у всех меняются на одинаковые.
- [ ] Третий участник входит в звонок двоих: звук у первых двоих не пропадает дольше пары секунд, новичка слышно сразу.
- [ ] Участник выходит: остальные продолжают слышать друг друга, эмодзи у них обновляются; в `pluma-admin calls show` вышедший через несколько секунд пропадает из столбца `chain`.
- [ ] Обрыв сети на 10–30 секунд (авиарежим) и возврат: клиент сам возвращается в звонок, его снова слышно; в `pluma-admin calls show` у него не больше одного повторного входа.
- [ ] Сломанный ключ: пока у Android закрыт доступ к серверу API (не к SFU), в звонок входит ещё один участник; через 12–15 секунд после возврата доступа Android сам входит заново с новым ключом, его снова слышно; в `pluma-admin calls show` у него были тревоги `poll_behind`/`stale_send_epoch`, потом они пропали.

**iOS**
- [ ] Сквозной вход в звонок супергруппы и канала: слышно в обе стороны, пунктов записи и трансляции нет, «войти от имени» нет.
- [ ] Эмодзи проверки совпадают с остальными клиентами и обновляются у всех одинаково при входе и выходе участника.
- [ ] Третий участник: звук у двоих не прерывается, новичка слышно сразу.
- [ ] Выход участника: остальные слышат друг друга, вышедший пропадает из цепочки (`pluma-admin calls show`).
- [ ] Обрыв сети на 10–30 секунд и смена Wi-Fi на LTE: возвращается сам, тем же ключом при восстановлении соединения, звук идёт.
- [ ] Сломанный ключ (как у Android, закрыть доступ к серверу API на время входа другого участника): iOS сам входит заново с новым ключом, тревоги в `pluma-admin calls show` пропадают.

**Desktop**
- [ ] Сквозной вход в звонок супергруппы и канала: слышно в обе стороны, нет «Stream with…», записи и выбора «войти от имени».
- [ ] Эмодзи проверки в списке участников совпадают с остальными клиентами.
- [ ] Третий участник: звук не прерывается, новичка слышно.
- [ ] Выход участника: остальные продолжают разговор, эмодзи обновляются у всех одинаково.
- [ ] Отключить сеть на 10–30 секунд: возвращается сам, звук идёт; перезапуск `sfu` во время звонка — клиенты возвращаются без нового ключа (в `pluma-admin calls show` столбец `rejoins 5m` растёт не больше чем на один вход).
- [ ] Сломанный ключ (закрыть доступ к серверу API на время входа другого участника): Desktop сам входит заново с новым ключом, не больше трёх повторных входов за 5 минут, потом звонок закрывается с сообщением.

**Web**
- [ ] Сквозной вход в звонок супергруппы и канала в Chrome и Safari: слышно в обе стороны; в браузере без `RTCRtpScriptTransform` — понятное сообщение вместо входа.
- [ ] Эмодзи проверки совпадают с нативными клиентами.
- [ ] Третий участник: звук не прерывается, новичка слышно.
- [ ] Выход участника: остальные продолжают разговор.
- [ ] Отключить Wi-Fi на 10–30 секунд: возвращается сам, звук идёт.
- [ ] Сломанный ключ (закрыть доступ к серверу API на время входа другого участника): Web входит заново с новым ключом, а не выходит из звонка.

**Все клиенты и сервер**
- [ ] Android, iOS, Desktop и Web в одном звонке: слышно всех, у всех одинаковые эмодзи; в `pluma-admin calls show` у каждого столбец `sends with` называет текущую высоту, `report` обновляется раз в 5 секунд, тревог нет.
- [ ] Старая сборка клиента без патча 094 не входит в звонок и показывает понятную ошибку.
- [ ] Вход в звонок со второго устройства того же аккаунта (Desktop, потом Android, потом iOS при уже идущем звонке на другом устройстве): первое устройство само кладёт трубку, второе остаётся в звонке и его слышно; ни одно не входит заново по кругу, в `pluma-admin calls show` у пользователя не больше одного повторного входа. В журнале Desktop остальных участников нет ошибок `deleteConferenceCallParticipants` на этот вход.
- [ ] Вход нового участника при двух-трёх Desktop в звонке: в их журналах нет «Could not remove confcall participants» (сервер шлёт строку вошедшего раньше его блока).
- [ ] Перезапуск `sfu` в звонке не меньше чем на 12 участников (живых клиентов вместе с тестовыми `groupcallpeer`, если не хватает устройств): все возвращаются в звонок, никого не выбрасывает с ошибкой входа. Проверять после того, как ветки клиентов перейдут на правило «10 отказов подряд без движения цепочки» (ADR 0060 §5).
- [ ] Все вышли из звонка, звонок не завершён: тревога `GroupCallsE2EStaleMember` не приходит; кто-то входит снова — вышедшие удаляются из цепочки, тревоги нет.

## Обновления приложений (задача 095)
Проверять на сборках с сайта (Android — APK, iPhone — ad hoc со страницы установки, Desktop — установщик с сайта, Web — `web.pluma.chat`) после выката сервера и правок клиентов задачи 095. Оператору — `pluma-admin release list|mandatory|optional` (`docs/ops/releases.md`, «Обязательный выпуск»).

- [ ] Android: после выкладки новой сборки приложение, свёрнутое больше чем на час и открытое снова, показывает лист обновления; в течение часа после прошлой проверки — не показывает.
- [ ] Android: `release mandatory android <сборка>` сразу после выкладки (до первой проверки клиента) — при возврате в приложение полноэкранный экран обновления без «Пропустить», после сворачивания и возврата он снова на месте; «Обновить» качает и ставит APK.
- [ ] Android: `release optional` для того же выпуска — при следующем возврате в приложение экран исчезает сам.
- [ ] Android: клиент, уже получивший выпуск необязательным, после `release mandatory` экран не показывает (поведение клиента, `docs/ops/releases.md`); следующая обязательная сборка — показывает.
- [ ] iPhone: после выкладки новой сборки приложение, вернувшееся из фона через час и больше, показывает экран обновления (с правкой клиента задачи 095; без неё — только при запуске или через 12 часов).
- [ ] iPhone: `release mandatory ios <сборка>` — на экране обновления нет «Пропустить»; «Обновить» ставит сборку. `release optional` — при следующем опросе экран с «Пропустить»; что происходит с уже открытым экраном без «Пропустить», записать.
- [ ] Desktop: после выкладки новой сборки приложение в пределах 50–70 минут скачивает пакет и предлагает перезапуск.
- [ ] Desktop: `release mandatory macos <сборка>` отвечает ошибкой «no mandatory updates».
- [ ] Web: после выкладки новой сборки Web в течение 30 минут в меню появляется кнопка обновления; после нажатия страница загружается в новой версии, вход и чаты на месте.
- [ ] `release list`: колонка `MANDATORY` — `yes`/`no` у android и ios, `-` у desktop-платформ.
