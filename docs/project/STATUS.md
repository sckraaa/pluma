- **Безопасность P1** (задача 008, ветка `task/008-security-p1`).
  - **2FA по SRP**, как в Telegram: установка, вход (`SESSION_PASSWORD_NEEDED`, ключ не привязан до пароля), смена, снятие, лимит подбора. Почты нет: сброс из вошедшей сессии — через 7 дней, остальным — `pluma-admin password reset` (`docs/ops/security-setup.md`).
  - **Handshake.** Случайный `pq` (proof-of-work), проверки RSA_PAD, SHA1, `g_b`, коллизии и `retry_id`; старый `httpserver` удалён.
  - **Ключи.**
    - temp-ключ живёт не больше 7 дней, истёкшие удаляются;
    - `destroy_auth_key` и `auth.dropTempAuthKeys` удаляют ключи;
    - `auth.resetAuthorizations` работает, из сессии моложе суток — `FRESH_RESET_AUTHORISATION_FORBIDDEN`;
    - ключи в MySQL и Redis зашифрованы (`AUTH_KEY_ENCRYPTION_KEY`).
  - **Session и лимиты.**
    - окно `msg_id` −300/+30 с, повтор внутри окна распознаётся;
    - соли из `crypto/rand`;
    - на адрес: 512 соединений и 300 `req_DH_params` в минуту;
    - на ключ: 100 RPC в секунду, сверх — `FLOOD_WAIT_X`.
  - **Проверка.** e2e, Web K и Android (эмулятор) на стенде: пароль ставится, спрашивается при входе, меняется и снимается. В iOS 2FA ещё не проверена.
  - **При развёртывании.** Задать `AUTH_KEY_ENCRYPTION_KEY` в `.env`. Миграции `migrate-20261024-passwords.sql` и `migrate-20261025-auth-keys.sql` применит сервис `migrate`.

## Известные проблемы и риски
- **Журнал `seq` (задача 010).**
  - Поведение Telegram с `seq` (типы, эхо инициатору) — вывод из клиентов, эталона с двух авторизаций нет.
  - Изменения чатов вне этапа 3 (реакции, TTL, управление ссылками) — без `seq`; остальное — бриф 010.
- **iOS** повторяет около 15 неподдержанных методов (реакции, эмодзи-статусы, Stars, `messages.getStickerSet`) примерно раз в 15 с: они отвечают `ERR_ENTERPRISE_IS_BLOCKED`. На экране номера зовёт `auth.initPasskeyLogin` (заглушка, вход не мешает).
- **Push.**
  - iOS не проверен: на симуляторе push нет, нужна подписанная ad hoc-сборка (профили Apple, App Group, Notification Service Extension).
  - Web push (Web K) и VoIP push не отправляются: нет TLS-раздачи Web K и нет звонков.
  - Push нет на правки, реакции и удаления (`MESSAGE_DELETED`).
  - Связь оборвалась, а сессия ещё считается живой (до 60 с) — push в это время не уходит.
- **Остаточные риски безопасности.**
  - Кто знает номер из allowlist, может держать владельца в `FLOOD_WAIT` (снимается `pluma-admin login-unblock`).
  - etcd и Kafka без аутентификации, TLS между сервисами нет (порты закрыты снаружи).
  - Повтор перехваченного сообщения после рестарта session внутри его окна в 300 с не распознаётся: номера сообщений хранятся только в памяти.
  - `seqno` не проверяется (коды 32–35): Android сам шлёт `msg_resend_req`, `ping_delay_disconnect` и запросы прокси-соединений с чётным `seqno`.
  - Без почты 2FA восстанавливается только сбросом через 7 дней или администратором.
- Формат inbox-событий и число партиций изменились — при обновлении группы и топики пересоздаются (`docs/ops/user-state.md`).
- Свежие клиенты на layer 229–232; держим клиентов на 228 (ADR 0008). Обновление layer зависит от upstream `teamgram/proto` — генераторы TL не открыты.
- Каналы: 1 из 74 методов; звонки: 0 из 45; push: заглушка.
- GeoIP: атрибуция MaxMind — в `NOTICE` и runbook; в клиентах и на сайте её нет, так решил владелец (ADR 0023).
- `help.getNearestDc` не знает страну клиента (GeoIP-база есть только у authsession; клиент берёт страну SIM). `config.json` сервера отдаёт пустой `dc_options`, как в апстриме. Клиенты держат встроенный адрес, а Desktop пишет в лог «config with empty dc_options». `auth.sentCode` говорит «SMS», хотя код приходит из `pluma-admin` или в приложение.
- Web K: у собственного сообщения в «Избранном» отправивший браузер показывает бейдж непрочитанного «1», второй — нет. Похоже, отправителю приходит его же сообщение как входящее; Telegram своё в «Избранном» непрочитанным не считает.
- «О себе» сервер ограничивает 128 байтами, а не 70 символами: кириллица длиннее 64 символов не сохраняется. Закреплённые чаты, длину сообщения и число частей файла сервер не проверяет (список — бриф 015).
- Web K в настройках показывает у самого пользователя «last seen Jan 1, 1970».
- Интеграционный `TestConcurrentOperations` (`pkg/userbox`) один раз упал при полном прогоне с `-p 4` (тест шёл 111 с вместо 14); повторные прогоны зелёные. Причину не установили — при повторе сохранить вывод.
